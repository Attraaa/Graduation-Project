# 공통 카메라 설정

학습 화면 오른쪽 위의 **사용할 카메라** 선택 옆 **카메라 설정** 버튼으로 엽니다. 상체·키보드·안구 모드에 같은 위치로 제공하며 Electron에서는 이동·크기 조절이 가능한 별도 창입니다. 설정 창을 열거나 모드/장치를 선택하는 동작은 카메라를 켜지 않습니다. 학습 화면의 시작 버튼이 카메라를 소유합니다.

설정 창 왼쪽은 미리보기, 오른쪽은 설정입니다. 오른쪽만 스크롤합니다. 영상 둘레에 기본 24px(작은 창 16px) 여백과 둥근 테두리를 두며 실제 연결된 영상 비율을 유지합니다. CSS 컨테이너 크기로 영상의 가로·세로를 함께 맞춰 창을 줄여도 늘어나거나 찌그러지지 않습니다. 회전은 기존 cover 방식으로 가장자리를 잘라 검은 회전 모서리를 만들지 않습니다. 영상 연결 후 모델 준비를 기다리지 않고 미리보기를 시작합니다. 헤더의 연결 상태 배지, 별도의 저장 버튼이나 하단 저장 상태 영역은 없습니다.

Windows Electron의 메인 창과 설정 창은 앱 테마에 맞는 36px 제목 표시줄을 사용합니다. 드래그 영역과 Windows 기본 최소화·최대화·닫기 버튼을 유지하며 밝은/어두운 테마를 바꾸면 열린 창의 색도 함께 갱신합니다. 일반 브라우저에서는 자체 제목 표시줄을 추가하지 않습니다. `WindowTitleBar.tsx`는 화면을, `electron/windowAppearance.ts`는 네이티브 색/높이를 담당합니다. `window:set-theme` IPC는 주 창의 신뢰된 최상위 문서에서 `light`/`dark`만 받으며 설정 창에는 preload 권한을 추가하지 않습니다.

## 카메라 구도 확대와 이동

- 영상 위에서 휠을 돌리면 마우스가 가리킨 지점을 중심으로 100~500% 확대·축소합니다.
- 키보드 모드는 미리보기 도구의 **이동**을 선택해 왼쪽 버튼으로 드래그합니다. **영역 편집**은 기존 모서리/키보드 영역 조정을 유지합니다. 상체·안구는 왼쪽 드래그가 바로 화면 이동입니다.
- 모든 모드에서 휠 버튼을 누른 드래그로도 화면을 이동할 수 있습니다. 이동은 영상의 빈 가장자리가 드러나지 않는 범위로 제한합니다.
- **확대·이동 초기화** 버튼은 확대율과 이동을 초기화합니다. 키보드 격자는 영상과 함께 움직이고, 모서리의 클릭 영역은 화면상 40px을 유지합니다. 관측 오버레이는 바뀐 영상에서 다시 추론합니다.

휠 확대와 드래그는 실제 분석 영상의 구도를 바꾸며 모드·장치별로 자동 저장합니다. 설정 창, 학습 화면, Python/MediaPipe 입력은 동일한 변환 캔버스를 사용합니다. 창을 다시 열거나 측정을 재시작하면 저장한 구도를 복원합니다. 카메라를 자동 연결하지 않으며 시작 버튼 동작은 유지합니다. 휠은 영상 안에서만 처리하고 오른쪽 설정 목록의 스크롤은 유지합니다.

`zoom`(1~5), `panX`/`panY`(출력 가로·세로에 대한 정규화 이동)를 기존 회전·반전·크롭 뒤에 적용합니다. 프레임 크기와 비율은 유지하고 확대된 내용의 가장자리를 잘라 모델에 보냅니다. 디지털 확대는 모델에 들어가는 키보드의 비중을 키우지만 원본 카메라가 담지 못한 세부 정보를 만들지는 않습니다.

## 설정 범위와 생명주기

- 저장 키는 `moti.camera.v1:<modeId>:<actual deviceId>`입니다. 상체의 목·어깨는 단일 `upper_body` 모드를 공유하고, 키보드·안구는 독립 프로필을 사용합니다.
- 명시적으로 선택한 장치는 시작 전 편집도 그 장치에 저장합니다. 기본 카메라는 스트림의 `getSettings().deviceId`가 확인된 뒤 장치 프로필을 불러옵니다. 연결 전 편집은 실제 장치를 확인할 때 적용하며, 이전 기본 장치의 전체 프로필을 다른 장치로 복사하지 않습니다.
- 기존 `moti.keyboard.camera`는 처음 확인한 실제 키보드 카메라에만 한 번 이관합니다. 이미 장치별 프로필이 있으면 보존합니다. 다른 모드/카메라에 복제하지 않습니다.
- 설정 창은 부모의 변환 캔버스를 공유하는 React portal입니다. 두 번째 `getUserMedia`, Python 프로세스, MediaPipe 추론기를 만들지 않습니다. 창을 닫아도 측정은 계속됩니다.
- 측정 중지·페이지 이탈은 소유 모니터가 트랙/모델을 해제하고 공유 미리보기를 비웁니다. 카메라 트랙 종료도 공유 화면을 비웁니다. 모드/장치 변경 시 이전 설정 창을 정리합니다. 앱 종료·잠금·절전에서는 설정 창도 닫습니다.
- Electron은 동일 앱의 정확한 `camera-settings.html`과 지정한 창 이름만 허용합니다. 다른 창 열기와 외부 페이지 이동은 막으며 기존 기록/키보드 IPC의 주 창 검증은 유지합니다.

## 영상과 장치 조정

영상의 좌우/상하 반전, 90°/180° 회전, 자유 기울기, 밝기/대비는 미리보기와 분석 입력에 동일하게 적용합니다. 상체/안구의 기본 좌우 반전은 기존 셀프 미리보기 방향을 유지하되 이제 추론도 같은 변환 영상에서 수행합니다. 영상 크기는 실제 프레임 크기이며 좌표의 픽셀·정규화 단위와 점수 산식은 유지합니다. 구도가 바뀌면 상체 기준과 기록 구간을 새로 수집하고, 안구 v3는 개인 눈·거리 기준을 다시 수집하며 깜빡임/유효 시간/휴식 누적을 보존합니다. 안구 화면의 **거리 기준만 다시 잡기**는 학습한 개인 눈 기준을 유지합니다.

해상도는 활성 트랙에 `applyConstraints`로 요청하고 실제 `getSettings()` 크기를 표시합니다. 하드웨어 노출은 시작한 트랙의 `getCapabilities()`에 지원 방식/범위가 있는 경우만 제공합니다. 지원되는 노출 방식/시간을 적용한 뒤 현재 설정을 다시 읽고 오류를 표시합니다. 미지원 장치는 그 상태를 표시합니다. 소프트웨어 밝기/대비는 하드웨어 노출과 별개이며 포화된 영상을 복원하지 않습니다. 초점 조정은 이번 기능에 포함하지 않습니다.

## 키보드 영역

키보드 모드에서만 **자동 인식 / 직접 맞추기**와 **영역 방향**을 제공합니다. 영상이 연결되면 자동 인식 실패 여부와 관계없이 수동 설정을 사용할 수 있습니다.

1. 내부를 드래그하면 전체 영역이 이동합니다.
2. 네 모서리의 사각형/테두리를 드래그하면 사다리꼴과 원근을 조정합니다. 유한하고 볼록하며 현재 분석 영상 대비 최소 면적 1.5% 조건을 만족하는 조정만 받습니다. 기존 모서리가 확대 후 화면 밖으로 잘리더라도 격자는 영상에 붙어 유지됩니다.
3. 키 이름은 항상 표시합니다. 표는 Python과 동일한 `keyboard-detect/data/perfect_map.json`의 ANSI 61키입니다. 경계는 모서리 키 중심이 아니라 전체 키보드의 외곽입니다.
4. **영역 방향** 버튼이나 영역 우클릭 메뉴로 키 배치만 좌우/상하 반전하거나 90°/180° 회전합니다. 영상 방향은 별도입니다.
5. 드래그 중에는 현재 화면 및 승인 앱의 입력 판정을 보류합니다. 드래그를 끝내면 영역을 자동 저장하고 Python의 고정 키 맵에 적용합니다. 자동 재시도는 수동 영역을 덮어쓰지 않습니다. 학습 화면의 위치 재인식 버튼 또는 설정의 자동 인식 버튼은 명시적으로 자동 모드로 돌아갑니다.

수동 맵은 `source=manual`, `geometry_validated=true`로 전달합니다. 기하 검증은 실제 키 위치와의 일치나 AI 신뢰도를 뜻하지 않습니다. 자동 맵의 모델 신뢰도 0.18 조건 대신 기하 검증을 사용하며, 손 신뢰도·시간 차이·거리·모호성·지원 키 조건은 계속 적용합니다. 수동 맵에 AI 신뢰도 1을 만들지 않습니다. 영상의 반사 여부는 MediaPipe 손의 좌우 보정에 전달하고, 영역 반전은 손 이름을 바꾸지 않습니다. 손가락 정책은 `ansi-qwerty-touch:2.0.0`, 새 인식 메타데이터는 `hands-camera-manual-v3`입니다. 서버 계약/스키마 변경은 없습니다.

저장 프로필의 `grid.quad`는 영상 방향·기존 크롭을 적용한 뒤 확대·이동하기 전의 정규화 좌표입니다. 화면에서 편집하거나 자동 검출한 외곽은 역변환하여 저장합니다. UI는 표시 좌표로 투영하고, 로컬 `manual_keyboard`는 저장 외곽과 `framing: {zoom, panX, panY}`를 전달해 Python이 동일하게 투영합니다. 저장 외곽은 원본 범위 [0,1]과 최대 5배 확대를 고려한 최소 면적 0.06%를 검증하며, Python의 최종 분석 맵은 기존 1.5% 면적·볼록성 검사를 유지합니다. 축소 때문에 영역이 작아져도 저장 좌표는 보존합니다.

## 프레임 처리

미리보기는 RAF로 갱신하고 Python 프레임 ACK와 분리합니다. 분석은 최대 20Hz 전송 기회, 가로 최대 960픽셀의 비율 유지 영상, 비동기 JPEG Blob/Socket.IO 바이너리를 사용합니다. 직렬화·전송·추론을 포함해 한 프레임만 진행하며 완료 뒤 최신 프레임을 사용합니다. 비디오 시각이 달라진 프레임만 보내므로 멈춘 영상을 새 시각으로 반복 전송하지 않습니다. 5초 응답 지연 시 관찰을 종료하고, 설정 변경 전 결과는 폐기합니다. 손끝 표시가 500ms 이상 오래되면 지웁니다.

전송 영상은 새 카메라 프레임을 미리보기에 그린 브라우저 단조 시각을 보존하고 Python 수신 시각은 디코딩/추론 전에 잡습니다. 응답의 추론 시간과 인코딩/왕복/결과 나이는 `CameraRuntime.metrics`에 남깁니다. 기존 120ms 입력 대기, 80ms 외부 입력 카메라 지연 보정, 180ms 판정 시간 차이 기준은 유지합니다. 실제 추론 속도는 하드웨어·조명·입력에 따라 달라지므로 20Hz를 실측 성능으로 제시하지 않습니다.

- 자동 검사: `camera-settings.test.mjs`의 장치/모드 격리·이관·원근·방향·창 허용 목록·판정 게이트, `test_manual_mapping.py`의 실제 키 hit test·바이너리 전송·수신 시각·판정 중지·손 반사 보정.
- `camera-preview.test.mjs`는 마우스 중심 확대와 역변환, 범위/빈 가장자리 방지, 구도의 모드·장치별 저장과 이전 프로필 호환, 격자 투영과 작은 원본 외곽 보존을 확인합니다. 좌표 계산은 `framing.ts`에 두고 실제 캔버스·격자·분석 계약이 공유합니다. Python 검사는 실제 키 hit map의 확대·이동과 잘린 외곽, 확대 전 작은 영역, 잘못된 구도 거절도 확인합니다.
- 2026-10-09 가상 카메라로 브라우저와 빌드된 `file://` Electron 창에서 시작 전 비활성, 모델 준비 전 영상 표시, 단일 활성 스트림, 4:3 비율, 61개 이름표, 모서리 드래그, 독립 영역 반전/우클릭, 장치별 저장/기본 장치 교체, 노출 요청/읽기, 설정 스크롤, 닫기/중지를 확인했습니다. 상체는 합성 랜드마크로 설정 변경 시 기준 재수집을, 안구는 실제 Face Landmarker에 빈 합성 영상을 전달해 캔버스 입력/종료를 확인했습니다.
