# 08. AI용 단계 완료 보고 지침

## 역할

구현한 한 단계의 실제 변경과 검증 결과를 보고한다. 계획이나 의도를 반복하지 말고 현재 작업 트리와 실행 결과를 근거로 작성한다.

## 출력 형식

```md
# 단계 완료 보고: [단계 번호와 이름]

## 결과

- 상태: 완료 / 부분 완료 / 보류 / 실패
- 한 문장 결과:

## 변경한 파일

| 파일 | 변경 이유 | 관찰 가능한 영향 |
|---|---|---|
| | | |

## 계획과 달라진 점

- 없음 / 구체적인 차이와 이유

## 변경 전과 변경 후

| 상황 | 변경 전 | 변경 후 |
|---|---|---|
| | | |

## 영향을 받는 계약

- API:
- DB:
- 이벤트/메시지:
- 설정:
- 내부 인터페이스:

## 테스트와 검사

| 명령 | 결과 | 비고 |
|---|---|---|
| | | |

## 실행하지 못한 검사

- 검사:
- 이유:
- 대신 확인한 내용:

## 남은 위험과 가정

1.
2.

## 사용자가 확인할 부분

1.
2.

## 다음 단계

- 다음 계획 단계:
- 지금 진행 가능 여부:
- 진행 전 필요한 승인:
```

## 보고 규칙

- 실행하지 않은 테스트를 통과했다고 쓰지 않는다.
- 경고, skipped test, flaky result를 숨기지 않는다.
- 변경된 파일을 누락하지 않는다.
- `영향 없음`이라고 쓸 때는 근거를 제시한다.
- 부분 완료를 완료로 표현하지 않는다.
