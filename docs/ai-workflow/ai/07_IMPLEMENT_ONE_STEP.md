# 07. AI용 한 단계 구현 지침

## 역할

승인된 최종 계획에서 사용자가 지정한 한 단계만 구현한다.

## 구현 전 확인

다음을 먼저 확인하고 짧게 보고한다.

- 최종 계획서 경로
- 구현할 단계 번호와 이름
- 승인된 ADR이 필요한지와 상태
- 예상 변경 파일
- 실행할 검증
- 변경하지 않을 범위

ADR이 필요한데 Accepted가 아니거나, 구현 단계가 지정되지 않았으면 코드를 수정하지 않는다.

## 구현 규칙

- 지정된 한 단계만 구현한다.
- 계획에 없는 파일을 수정해야 하면 먼저 중단하고 이유를 보고한다.
- 관련 없는 리팩터링을 하지 않는다.
- 기능 변경, 포맷팅, 대규모 이름 변경을 섞지 않는다.
- 공개 계약은 계획 또는 ADR에 명시된 경우에만 변경한다.
- 새 production dependency는 명시적 승인이 있을 때만 추가한다.
- 기존 테스트를 삭제하거나 assertion을 약화하여 통과시키지 않는다.
- 사용자 또는 다른 작업자의 관련 없는 변경을 보존한다.
- 오류를 숨기거나 성공처럼 보고하지 않는다.
- 다음 계획 단계는 구현하지 않는다.

## 테스트 규칙

- 새 동작 또는 수정된 버그를 증명하는 테스트를 추가하거나 수정한다.
- 정상 경로만이 아니라 현재 단계와 관련된 주요 실패 경로를 포함한다.
- 구현 세부사항을 그대로 복제하는 테스트보다 관찰 가능한 동작과 계약을 검증한다.

## 범위 확대 중단 조건

다음 상황이면 구현을 멈추고 보고한다.

- 계획에 없는 공개 API 또는 스키마 변경이 필요함
- 예상보다 많은 모듈이 영향을 받음
- 기존 동작과 요구사항이 충돌함
- 데이터 손실 또는 보안 위험을 새로 발견함
- ADR이 필요한 새 설계 결정이 등장함
- 테스트 실패가 현재 변경과 무관해 보임
- 안전한 롤백 경로가 사라짐

## 완료 조건

1. 현재 단계의 코드와 테스트가 작성되었다.
2. 관련 검증을 실행했다.
3. 다음 단계는 수정하지 않았다.
4. `ai/08_STEP_COMPLETION_REPORT.md` 형식으로 결과를 보고한다.

단계 상태, 다음 행동, 관련 결과 파일은 `ai/00_UPDATE_WORK_ITEM_STATUS.md`에 따라 활성 작업의 `STATUS.md`에 반영한다.
