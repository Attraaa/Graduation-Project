# 05. AI용 계획 확정 지침

## 역할

사용자가 검토한 계획 초안을 수정하여 구현 기준이 되는 최종 계획서를 만든다. 아직 프로덕션 코드는 수정하지 않는다.

## 입력

1. 계획 초안
2. 활성 작업 폴더의 `04_PLAN_REVIEW.md`
3. 활성 작업 폴더의 `01_TASK_INPUT.md`
4. `templates/03_PLAN_TEMPLATE.md`와 활성 작업 폴더의 `03_PLAN.md`

## 수행 절차

1. 사용자 수정 요청을 항목별로 반영한다.
2. 초안과 달라진 내용을 `초안 대비 변경사항`에 기록한다.
3. 승인된 첫 구현 단계를 명확히 표시한다.
4. 각 단계의 변경 예상 파일과 검증 명령을 다시 확인한다.
5. 아직 해결되지 않은 질문을 숨기지 않는다.
6. ADR이 필요한 결정을 별도로 표시한다.
7. ADR 승인이 필요한 경우 구현 단계보다 앞에 배치한다.

## 최종 계획 조건

- 목표와 비목표가 분리되어 있다.
- 현재 동작과 변경 후 동작이 구분되어 있다.
- 유지해야 할 계약이 명시되어 있다.
- 단계별 결과, 파일, 검증 방법이 있다.
- 위험과 롤백 방법이 있다.
- 사용자 결정 사항이 해결되었거나 명시적으로 보류되어 있다.
- 처음 구현할 단계가 하나만 지정되어 있다.

## 출력 마지막 선언

구현 가능한 경우:

```text
계획 상태: 승인 조건 반영 완료
첫 구현 허용 단계: [번호와 이름]
구현 시작 전 ADR 필요 여부: [필요/불필요]
```

구현할 수 없는 경우:

```text
계획 상태: 구현 보류
보류 이유: ...
필요한 사용자 또는 담당자 결정: ...
```

최종 계획서 작성 후 구현을 시작하지 않는다.

계획 상태가 바뀌면 `ai/00_UPDATE_WORK_ITEM_STATUS.md`에 따라 활성 작업의 `STATUS.md`도 갱신한다.
