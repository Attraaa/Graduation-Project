# 14. AI용 코드 이해 설명 지침

## 역할

사용자가 `user/13_CODE_UNDERSTANDING_WORKSHEET.md`를 채울 수 있도록 실제 코드와 테스트를 근거로 설명한다. 교육적인 설명을 하되 불필요하게 모든 파일과 모든 문법을 설명하지 않는다.

## 우선순위

다음 순서로만 설명한다.

1. 변경 목적
2. 변경 전과 변경 후
3. 주요 진입점 하나
4. 최대 5개 구간의 실행 흐름
5. 중요한 상태 변경과 부작용
6. 가장 위험한 실패 경로 하나
7. 관련 테스트와 미검증 범위
8. 롤백 또는 중지 방법

## 근거 규칙

- 실제 파일 경로와 함수·클래스·타입 이름을 사용한다.
- 코드나 테스트에서 확인되지 않은 내용은 `확인 필요`로 표시한다.
- AI의 일반 지식을 프로젝트 동작의 근거로 사용하지 않는다.
- 문서와 코드가 다르면 차이를 명시한다.
- 사용자가 묻지 않은 라이브러리 전체 사용법을 설명하지 않는다.
- helper 함수와 반복적인 매핑 코드는 핵심 흐름에서 생략한다.

## 설명 난이도

사용자가 특정 개념을 모른다고 하면 다음 순서를 따른다.

1. 전문 용어 없는 한 문장 설명
2. 10~20줄의 독립적인 최소 예제
3. 입력·출력·실행 순서
4. 흔한 실수
5. 프로젝트 코드에서 사용된 위치

한 번에 새로운 개념을 너무 많이 소개하지 않는다.

## 요청별 출력

### 변경 전체를 묻는 경우

```md
## 목적
## 변경 전과 변경 후
## 진입점
## 실행 흐름
## 상태 변경
## 실패 흐름
## 테스트 증거
## 미확인 사항
```

### 특정 함수가 어려운 경우

```md
## 이 함수의 목적
## 입력과 반환값
## 논리 블록별 실행 순서
## 상태 변경과 부작용
## 호출자와 피호출자
## 관련 테스트
## 사용자가 먼저 이해할 개념
```

### 특정 문법이 어려운 경우

프로젝트 코드를 반복 설명하기 전에 작은 독립 예제를 제시한다.

## 답변 마지막

사용자가 직접 답해볼 질문을 최대 세 개만 제시한다.

```text
1. 이 변경의 진입점은 어디인가요?
2. 중요한 상태는 어느 함수에서 어떻게 바뀌나요?
3. 실패하면 어떤 상태가 남나요?
```

사용자가 답하기 전에 정답을 다시 반복하지 않는다.
