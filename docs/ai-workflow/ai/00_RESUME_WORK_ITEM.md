# 00-B. AI용 기존 작업 재개 지침

## 역할

다른 사람 또는 이전 AI가 진행한 작업을 안전하게 이어간다. `STATUS.md`만 신뢰하지 않고 실제 Git 상태, 작업 문서, 코드와 일치하는지 확인한다.

## 입력

- 작업 폴더 경로
- 해당 작업의 `STATUS.md`
- 현재 브랜치와 Git 상태
- 사용 가능한 계획·ADR·단계 보고·검증·리뷰 문서

## 재개 전 확인 순서

1. `STATUS.md`의 작업 이름, 상태, 현재 단계, 다음 행동을 읽는다.
2. 현재 Git 브랜치가 상태 파일의 브랜치와 일치하는지 확인한다.
3. 현재 HEAD와 상태 파일의 마지막 확인 커밋이 일치하거나 이후 변경이 있는지 확인한다.
4. staged, unstaged, untracked 파일을 확인한다.
5. 마지막 완료 단계의 결과 문서가 실제로 존재하는지 확인한다.
6. 계획의 체크 상태와 실제 코드 변경이 일치하는지 확인한다.
7. 테스트 결과의 실행 시점과 현재 코드가 같은지 확인한다.
8. 다른 작업자가 현재 같은 영역을 작업 중인지 상태 파일의 담당자·잠금 항목을 확인한다.

## 불일치 처리

다음 중 하나가 있으면 바로 구현하지 않는다.

- `STATUS.md`와 현재 브랜치가 다름
- 마지막 확인 커밋 이후 설명되지 않은 변경이 있음
- 완료로 표시된 단계의 결과 파일이 없음
- 테스트 결과가 현재 코드보다 오래됨
- 계획 밖의 파일이 수정되어 있음
- 담당자가 `작업 중`인데 인계 기록이 없음
- 해결되지 않은 P0/P1 리뷰 지적이 있음

불일치를 다음 형식으로 보고한다.

```md
## 재개 전 불일치

| 상태 파일의 기록 | 실제 저장소 상태 | 영향 | 필요한 확인 |
|---|---|---|---|
| | | | |
```

## 재개 요약 출력

```md
# 작업 재개 요약

## 작업

- 이름:
- 폴더:
- 브랜치:
- 현재 담당자:

## 확인된 현재 상태

- 마지막 완료 단계:
- 현재 단계:
- 마지막 확인 커밋:
- 작업 트리 상태:

## 완료된 결과

- 계획:
- ADR:
- 구현 단계:
- 검증:
- 리뷰:

## 미해결 사항

1.
2.

## 다음 행동

- 권장 다음 단계:
- 적용할 AI 지침 파일:
- 사용자 또는 담당자 승인 필요 여부:

## 재개 판단

- 바로 재개 가능 / 확인 후 재개 / 재개 보류
```

## 재개 규칙

- 사용자가 재개 요약을 확인하기 전에는 프로덕션 코드를 수정하지 않는다.
- 이전 계획을 무조건 따르지 않는다. 코드 또는 요구사항이 달라졌으면 계획 수정이 필요하다고 보고한다.
- 기존 작업자의 관련 없는 변경을 되돌리거나 덮어쓰지 않는다.
- 재개가 승인되면 `STATUS.md`의 담당자, 날짜, 현재 단계, 다음 행동을 갱신한다.
