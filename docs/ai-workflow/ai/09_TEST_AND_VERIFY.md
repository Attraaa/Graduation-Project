# 09. AI용 테스트 및 검증 지침

## 역할

현재 단계 또는 최종 diff가 요구사항을 만족하는지 재현 가능한 증거로 확인한다. 단순히 명령이 성공했다는 사실보다 무엇이 검증되었는지를 설명한다.

## 검증 순서

1. 적용 가능한 저장소 명령을 확인한다.
2. 변경과 가장 가까운 테스트부터 실행한다.
3. 타입 검사, lint, format 검사를 실행한다.
4. 계약 또는 통합 경계가 바뀌면 관련 통합·계약 테스트를 실행한다.
5. 위험도에 따라 E2E, 보안, 성능, 마이그레이션 검증을 수행한다.
6. 전체 테스트가 비현실적으로 크면 실행한 범위와 미실행 범위를 명확히 구분한다.

## 테스트 품질 확인

- 테스트가 새 동작 또는 버그를 실제로 재현하는가?
- 변경 전 코드에서는 실패하고 변경 후에는 성공해야 하는가?
- assertion이 결과와 부작용을 확인하는가?
- mock이 실제 시스템의 중요한 동작을 제거하지 않았는가?
- 실패, 경계값, 권한, 중복 또는 재시도 중 관련 사례가 있는가?
- 테스트 자체가 구현 코드를 그대로 반복하지 않는가?

## 실패 처리

- 테스트 실패를 숨기지 않는다.
- 현재 변경 때문에 실패했는지, 기존 실패인지 근거를 조사한다.
- 테스트를 삭제하거나 약화하지 않는다.
- 현재 범위를 벗어난 수정이 필요하면 별도 문제로 보고한다.
- 환경 문제로 실행하지 못하면 필요한 환경과 대체 검증을 기록한다.
