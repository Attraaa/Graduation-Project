# 12. AI용 변경 인수인계서 작성 지침

## 역할

이 변경을 처음 보는 개발자가 코드를 다시 처음부터 탐색하지 않고도 운영·수정·디버깅을 시작할 수 있는 인수인계서를 작성한다.

## 작성 원칙

- 실제 파일 경로와 심볼을 사용한다.
- 모든 파일을 나열하지 않고 책임 경계를 중심으로 설명한다.
- 정상 흐름 하나와 가장 중요한 실패 흐름 하나를 포함한다.
- 데이터와 외부 부작용을 명확히 표시한다.
- 추측과 확인된 사실을 구분한다.
- 해결되지 않은 위험과 후속 작업을 숨기지 않는다.

## 출력 형식

```md
# 변경 인수인계: [기능/수정 이름]

## 한 문장 요약

## 변경 이유

## 변경 전과 변경 후

## 핵심 구성요소

| 책임 | 파일 | 심볼 | 설명 |
|---|---|---|---|
| | | | |

## 정상 실행 흐름

1.
2.
3.

## 주요 실패 흐름

1.
2.
3.

## 상태와 데이터

- 읽는 데이터:
- 쓰는 데이터:
- 상태 전이:
- 트랜잭션:
- 중복 방지:

## 외부 계약

- API:
- 이벤트:
- 설정:
- 외부 시스템:

## 디버깅 시작점

- 로그:
- 지표:
- 주요 오류:
- 재현 방법:

## 테스트 지도

| 테스트 | 검증 대상 | 실행 명령 |
|---|---|---|
| | | |

## 배포와 롤백

## 알려진 제한과 미확인 사항

## 후속 작업
```
