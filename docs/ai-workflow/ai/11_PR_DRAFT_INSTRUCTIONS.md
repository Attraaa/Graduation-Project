# 11. AI용 PR 본문 작성 지침

## 역할

완료된 실제 diff와 검증 결과를 근거로 PR 본문 초안을 작성한다. PR 템플릿 원본은 수정하지 않는다.

## 입력

- `templates/PR_TEMPLATE.md`
- 원래 작업 입력
- 최종 계획과 ADR
- 단계 완료 보고서
- 최종 diff
- 테스트 및 독립 리뷰 결과

## 작성 규칙

- 계획이 아니라 실제 구현을 설명한다.
- 사용자 또는 시스템 문제를 먼저 설명한다.
- 변경 전과 변경 후를 관찰 가능한 동작으로 비교한다.
- 실행 흐름에는 실제 파일 경로와 심볼을 포함한다.
- API, DB, 이벤트, 설정 변경이 없으면 각각 `없음`으로 표시한다.
- 실행하지 않은 검사를 통과했다고 쓰지 않는다.
- 테스트가 증명하지 않는 범위를 작성한다.
- 미해결 리뷰 지적을 숨기지 않는다.
- AI가 지원한 영역과 사람이 확인해야 하는 영역을 구분한다.
- 롤백이 불가능하거나 제한적이면 명시한다.
- PR 템플릿 항목을 삭제하지 않는다. 적용되지 않으면 `해당 없음`과 이유를 쓴다.

## AI 사용 항목 작성 기준

`AI가 지원한 영역`에는 실제로 AI가 수행한 것을 표시한다.

`사람이 직접 확인한 영역`은 사용자가 확인했다고 명시한 항목만 표시한다. AI가 스스로 작성하고 검토한 것을 사람의 직접 확인으로 표시하지 않는다.

## 출력

1. `templates/PR_TEMPLATE.md` 형식을 채운 PR 본문 초안
2. 사용자에게 추가 확인이 필요한 항목 목록
3. PR을 생성하기 전에 반드시 교체해야 하는 placeholder 목록

git push 또는 PR 생성은 별도 요청이 없으면 수행하지 않는다.
