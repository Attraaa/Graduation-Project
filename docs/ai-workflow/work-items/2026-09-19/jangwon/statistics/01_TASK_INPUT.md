# 01. 작업 사전 입력

> 사용자가 작업 시작 전에 작성한다. 모르면 비워 두지 말고 `모름`, `AI 조사 필요`, `담당자 확인 필요`라고 쓴다. `<!-- 예: ... -->` 주석은 참고용이므로 지우지 않아도 된다.
>
> 이 문서는 저장소에 커밋될 수 있다. 비밀번호, API 키, 접근 토큰, 실제 카드 정보와 고객 개인정보는 넣지 않는다.

## 한 문장 목표

<!-- 예: 결제 응답이 늦어도 같은 주문이 두 번 결제되지 않게 한다. 구현 방법보다 사용자가 얻을 결과를 쓴다. -->
Moti의 통계 부분을 실제 데이터와 연결되도록 한다. 일단 sqlite를 사용하여 구현하되 나중에 서버가 열린다면 원하는 정보를 바로 넘겨서 작동할 수 있게 한다.  


## 현재 문제 또는 요청

<!-- 예: 결제 버튼을 누른 뒤 화면이 멈추면 사용자가 다시 눌러 결제가 두 번 생성될 수 있다. 가능하면 재현 순서도 쓴다. -->
- sqlite를 사용하여 현재 통계 탭에서 나타나는 데이터들을 실제 자세 데이터로 보여 줄 수 있게한다.
- 현재 평균 자세 점수, 개선도, 거북목 주의보, 시간대별 자세 점수 변화, AI분석 등이 있는데 이 뿐만아니라 자세 분석으로 얻은 데이터를 바탕으로 넣어줄 수 있는 다양한 통계 데이터를 추가해 줄 것.
- 학습이력의 데이터를 실제 데이터로 넣어서 작동 할 수 있게 한다.
- AI 맞춤형 피드백과 의학 정보의 경우에 일단 제외하고 구현한다. 현 상태 유지 하여 확인만 가능하도록 한다.
- 기존에 사용하고 있던 하드코딩된 값이나 db가 있다면 제대로 작동 할 수 있도록 삭제를 하거나 대체 하여 새롭게 수정된 db를 사용하도록 한다.

## 원하는 결과

<!-- 예: 첫 결제 결과가 확인될 때까지 새 결제를 막고, 화면에는 '결제 확인 중'을 표시한다. -->

- sqlite로 다양한 자세 측정 데이터를 받고, 통계 탭과 학습이력 탭에 전달하여 다양한 통계 데이터를 사용자가 확인 할 수 있게 한다.


## 이번 작업에 포함할 것

<!-- 예: 응답 지연 처리, 같은 주문의 중복 요청 방지, 관련 테스트 -->

- 현재 평균 자세 점수, 개선도, 거북목 주의보, 시간대별 자세 점수 변화, AI분석 등이 있는데 이 뿐만아니라 자세 분석으로 얻은 데이터를 바탕으로 넣어줄 수 있는 다양한 통계 데이터를 추가해 줄 것.
- 학습이력의 데이터를 실제 데이터로 넣어서 작동 할 수 있게 한다.
- 학습 모드 별 데이터를 쪼개서 동작하도록 한다. (협업 위해)
- 기존에 사용하고 있던 하드코딩된 값이나 db가 있다면 제대로 작동 할 수 있도록 삭제를 하거나 대체 하여 새롭게 수정된 db를 사용하도록 한다.

## 이번 작업에 포함하지 않을 것

<!-- 예: 새 결제사 추가, 환불 기능 변경, 결제 화면 전체 개편 -->

- AI 맞춤형 피드백과 의학 정보의 경우에 일단 제외하고 구현한다. 현 상태 유지 하여 확인만 가능하도록 한다.
- 키보드 모드와 안구 데이터들은 일단 제외하고 구현 할 것.


## 알고 있는 관련 위치

<!-- 모르면 `AI 조사 필요`라고 쓴다. 예: 주문 화면의 결제 버튼, 내부 이슈 #142 -->

- 관련 디렉터리: AI 조사 필요
- 관련 파일: AI 조사 필요
- 관련 화면/API/작업: AI 조사 필요
- 관련 이슈/PR/문서: AI 조사 필요

## 유지해야 하는 기존 동작

<!-- 예: 정상 결제와 카드 거절은 지금처럼 동작해야 하며 기존 주문 기록이 사라지면 안 된다. -->

- 학습이력의 경우 현재와 같이 동작해야하며 db를 연결해서 변경되는 경우에만 수정하도록 한다.
- 학습 탭의 해당 모드들은 수정하지 않도록 한다. 현재와 같이 동작해야 한다.

## 특별히 걱정되는 부분

<!-- 예: 실제 결제는 성공했는데 실패로 처리되는 것, 기존 결제 흐름이 깨지는 것 -->

- 읽기 쓰기 권한의 충돌이 나지 않게 끔 한다.
- db의 안정성 검사를 하도록 한다. 
- db관련 디렉토리를 따로 하나 만들어서 관리하기 쉽도록 한다.

## 완료되었다고 판단할 조건

<!-- 화면이나 결과로 확인 가능한 문장으로 쓴다. 예: 응답이 늦어도 결제 요청이 한 건만 생성된다. -->

- 모름 (AI 조사 필요)

## 내가 알고 있는 테스트 또는 확인 방법

<!-- 예: 결제 버튼을 빠르게 두 번 눌러도 요청이 한 건인지 확인한다. 모르면 `AI 제안 필요`라고 쓴다. -->

- AI 테스트 필요

## 변경 권한과 제한

<!-- 잘 모르겠다면 모두 `사전 승인 필요`로 선택하는 것이 안전하다. -->

- DB 스키마 변경: 허용
- 공개 API 변경: 허용
- 기존 파일 대규모 리팩터링: 별도 작업으로 분리
- 배포·외부 시스템 변경: 허용
