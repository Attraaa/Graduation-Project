# 10. 독립 리뷰 패스

## 범위와 방법
2026-09-19, 구현 이후 읽기 전용 리뷰 패스로 입력·전체 승인 계획·Accepted ADR·시작 0820714 대비 tracked diff와 신규 untracked 소스/테스트를 검토했다. 별도 agent를 사용하지 않았으며 같은 Codex가 구현 설명과 분리하여 정확성/회귀/트랜잭션/신뢰 경계/테스트를 점검했다. 리뷰 중 프로덕션 코드 수정 없음.

## 결과
미해결 P0/P1 발견 없음. 검토한 핵심 경계:
- 평가/카메라 코어를 보존하고 모든 캡처의 평가 누적값을 기록하는 최소 연결.
- SQL 매개변수, 입력 값/필드/시간/순번 검증, 요약과 버킷 원자 저장, 중복 재시도, 계정별 조회와 삭제 세대 무효화.
- 스키마/앱 ID/무결성 확인과 비파괴 거부, 시작 시 미종료 상태 복구.
- 원래 main 창/프레임/문서 IPC 신뢰 검사와 정상 종료 flush, 실패 반환 시 닫기 보류.
- 모드/정책/날짜 분리와 시간 가중 평균, null/0, 전체 달력 건수/100개 페이지, 예시 영역 표시.
- 기존 사용자 입력·승인 파일, 점수 정책·순수 평가·hooks·서버·Python·잠금 의존성 유지.

## 검증 보완
최초 service 테스트의 정상 close 검사는 이미 저장이 끝난 상태였다. 활성 측정이 남은 상황에서 close flush 실패→false, 같은 배치 재시도→true, finished 상태까지 assertion을 보강하고 해당 테스트를 다시 통과했다. 기존 assertion 삭제/약화 없음. 캡처 프레임 지연은 테스트 도구만 수정해 재검증했다.

## 남은 운영 제한 (P2)
- 위치: database/sqlite/repository.ts의 detail/write/batches.
- 조건: 하나의 매우 긴 기록 또는 많은 날짜에 걸친 누적 사용.
- 영향: 상세는 한 기록의 전체 분 버킷을 반환하고 각 배치 digest가 누적된다. 실제 사용량에서 디스크 용량/쿼리 지연 상한을 아직 측정하지 않았다.
- 근거: SQL detail 전체 반환, 초당 저장 및 batches 보존. 현재 181분 backlog·102개 페이지 기능 검사만 존재한다.
- 후속: 장시간 fixture/실사용으로 용량·지연을 측정한 뒤 필요 시 호환 가능한 상세 페이지와 retention을 별도 설계. 요청하지 않은 자동 삭제는 추가하지 않았다.

## 미검증 경계
실제 카메라·설치 패키지·전원 장애/디스크 가득 참·native 종료 실패 대화상자 실조작. 데모 인증은 기존 승인 범위이며 같은 OS 사용자의 악의적 접근을 막는 서비스 인증으로 간주하지 않는다.
