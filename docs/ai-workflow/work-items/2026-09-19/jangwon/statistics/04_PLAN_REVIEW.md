# 04. 계획 검토 및 승인

> AI가 작성한 계획을 받은 뒤 사용자가 작성한다. 모든 기술 내용을 이해할 필요는 없지만 목표·범위·위험·완료 조건은 확인한다. 주석 속 예시는 참고용이다.

## 범위 확인

<!-- 예: 결제 서비스와 관련 테스트만 바꾸며 전체 결제 모듈 리팩터링은 별도 작업으로 둔다. -->

- [x] 변경 예상 파일과 모듈이 과도하지 않다.

- [ ] 각 단계가 끝날 때 실행·검증 가능한 상태다.

## 검증 확인

<!-- 예: 정상·거절·timeout·중복 요청 테스트와 실행하지 못할 검사가 표시되어 있다. -->

- [x] 각 단계에 테스트 또는 확인 방법이 있다.

## 이번 작업의 검토 안내 (AI 작성, 결정은 사용자 작성)

`03_PLAN.md`의 5절(범위), 8절(단계), 13절(Q1~Q5)을 확인해 주세요.

- `사용자 결정`: 승인/조건부 승인/수정 요청/보류 중 하나만 체크합니다.
- `수정 요청 또는 승인 조건`: Q1~Q5의 선택을 적습니다. 모두 동의하면 `Q1~Q5 권장안에 동의`라고 적을 수 있습니다.
- `구현을 승인하는 첫 단계`: 동의하면 단계 번호 `1`, 단계 이름 `저장 계약과 모드별 기록 모델`을 적습니다. 계획 승인 뒤에도 별도 ADR 승인 전 구현은 시작하지 않습니다.

권장안은 학습 동작을 유지한 최소 저장 연결, 현재 데모 계정별 기록, 미래 서버용 데이터 계약만 준비, 유사도/관측률/기준 이탈 통계, 배치 저장과 현재 계정 기록만 확인 후 삭제입니다. 서버 전송은 후속이며 강제 종료 직전의 미커밋 구간은 복원하지 못할 수 있습니다.

승인란을 AI가 대신 선택하지 않았습니다. 저장 후 대화에 `작성했어`라고 보내면 이 작업을 이어갑니다.
