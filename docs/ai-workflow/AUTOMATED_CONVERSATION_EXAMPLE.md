# 자동 진행 대화 예시

이 예시는 Codex 또는 Claude Code에서 사용자가 작업 폴더 경로와 `작성했어`라는 응답만으로 흐름을 이어가는 모습을 보여준다. 아래의 `Codex` 표기는 현재 사용 중인 AI 도구로 바꿔 읽어도 된다.

## 1. 사용자의 최초 시작

```text
현재 작업 폴더는 다음입니다.
`docs/ai-workflow/work-items/2026-09-16/minsu/payment-timeout/`

이 작업을 자동 워크플로로 진행하세요.
```

## 2. Codex의 자동 작업

Codex는 별도 질문 없이 다음을 수행한다.

```text
01_TASK_INPUT 확인
→ STATUS가 없으면 생성
→ Git 브랜치와 작업 트리 확인
→ 관련 코드와 테스트 조사
→ 03_PLAN.md 작성
→ STATUS를 PLAN_REVIEW로 갱신
```

그 후 사람 판단이 필요한 계획 검토에서 멈춘다.

```text
현재 위치: 계획 검토

완료된 내용:
- 작업 폴더와 STATUS 초기화
- 현재 결제 흐름 조사
- 3단계 구현 계획 작성
- API와 DB에 미치는 영향 정리

멈춘 이유:
구현 전에 작업 범위와 첫 구현 단계를 사람이 승인해야 합니다.

사용자가 할 일:
`docs/ai-workflow/work-items/2026-09-16/minsu/payment-timeout/04_PLAN_REVIEW.md`
에서 다음을 작성하세요.

- 사용자 결정
- 수정 요청 또는 승인 조건
- 첫 구현 허용 단계

권장안:
단계 1만 먼저 승인하고 DB와 API 변경은 아직 보류하는 것이 안전합니다.

저장 후 보낼 답변:
작성했어
```

## 3. 사용자의 응답

사용자는 파일을 작성하고 다음만 보낸다.

```text
작성했어
```

## 4. Codex의 자동 재개

Codex는 사용자가 작업 폴더를 다시 말하지 않아도 다음을 수행한다.

```text
04_PLAN_REVIEW.md 재확인
→ 승인 조건을 03_PLAN.md에 반영
→ ADR 필요 여부 판단
→ ADR이 불필요하면 구현 시작
→ 승인된 단계 1 구현
→ 테스트 실행
→ 단계 보고 작성
→ STATUS 갱신
→ 검증된 체크포인트 로컬 커밋
→ 다음 승인된 단계 구현
```

ADR이 필요하면 구현 전에 다음과 같이 멈춘다.

```text
현재 위치: 아키텍처 결정 검토

완료된 내용:
- 계획 검토 반영
- 결제 중복 방지 방식 3개 비교
- Proposed ADR 작성

멈춘 이유:
이 결정은 결제 데이터와 재시도 규칙에 장기적인 영향을 줍니다.

작성할 파일:
`.../adr/0001-payment-idempotency.md`

작성할 항목:
- 승인: 승인 / 수정 요청 / 보류 / 거절
- 승인자
- 승인 조건

권장안:
pending 상태와 같은 결제 시도 키를 사용하는 대안을 권장합니다.
다만 모바일 호환성 확인을 승인 조건으로 남기세요.

저장 후 보낼 답변:
작성했어
```

## 5. 구현 완료 후 이해 확인

Codex는 구현, 테스트, 리뷰, PR 초안까지 자동으로 마친 뒤 다음 지점에서 멈춘다.

```text
현재 위치: 변경사항 이해 확인

완료된 내용:
- 승인된 구현 단계 완료
- 관련 테스트와 타입 검사 통과
- 독립 리뷰 P1 수정 및 재검증
- PR 본문 초안과 기술 인수인계 작성

멈춘 이유:
최종 승인 전에 사용자가 변경 목적과 가장 위험한 실패를 이해했는지 확인해야 합니다.

작성할 파일:
`.../13_UNDERSTANDING.md`

최소 작성 항목:
- 무엇을 바꿨나
- 어디서 시작하나
- 중요한 데이터가 어디서 바뀌나
- 가장 위험한 실패
- 무엇으로 검증했나
- 아직 모르는 것

모르는 용어가 있으면 그 단어만 질문하세요.

저장 후 보낼 답변:
작성했어
```

## 6. 최종 승인

이해 문서를 AI가 코드와 대조하여 교정한 뒤 마지막으로 다음 파일을 요청한다.

```text
작성할 파일:
`.../16_FINAL_APPROVAL.md`

작성할 항목:
- 최종 결정
- 남은 조건 또는 보류 이유

저장 후 보낼 답변:
작성했어
```

승인되면 상태는 `READY_TO_MERGE`가 된다. 기본 정책에서는 원격 push, 실제 PR 생성, 병합, 배포 전에 별도 허가를 한 번 요청한다.

## 새 대화에서 이어갈 때

같은 대화에서는 `작성했어`만 보내면 된다. 새 대화에서는 작업 폴더를 다시 지정한다.

```text
현재 작업 폴더는 다음입니다.
`docs/ai-workflow/work-items/2026-09-16/minsu/payment-timeout/`

STATUS와 실제 Git 상태를 대조하고 자동 워크플로를 재개하세요.
```
