# AI Work-Item Automation Policy

> 이 파일은 프로젝트에서 한 번 정하는 자동 진행 정책이다. 작업마다 복사하지 않는다. 개발을 모르는 사용자는 기본값을 그대로 사용할 수 있다.

## 지원 실행 도구

- OpenAI Codex: `AGENTS.md`와 `.agents/skills/ai-workflow-orchestrator/`
- Anthropic Claude Code: `CLAUDE.md`와 `.claude/skills/ai-workflow-orchestrator/`
- 공유 상태: `docs/ai-workflow/work-items/.../STATUS.md`

두 도구는 순차적으로 같은 작업을 이어갈 수 있지만 동시에 같은 브랜치와 work item을 수정해서는 안 된다. 전환할 때 `CROSS_AGENT_HANDOFF.md`를 적용한다.

## 기본 진행 방식

- 진행 모드: `continuous-with-human-gates`
- 질문 방식: `필요한 경우 한 번에 한 가지 쉬운 질문`
- 현재 작업 기억: `같은 대화에서 사용자가 다른 작업 폴더를 지정할 때까지 유지`
- 기술 문서 작성: `AI 자동`
- 코드 조사·구현·테스트·리뷰: `AI 자동`
- STATUS 갱신: `AI 자동`
- 계획의 승인된 구현 단계 사이 자동 진행: `사용`
- 동시 실행 도구 수: `work item당 1개`

## 사용자가 직접 작성하거나 승인하는 지점

다음 단계에서만 기본적으로 멈춘다.

1. `01_TASK_INPUT.md`가 없거나 목표가 비어 있음
2. `04_PLAN_REVIEW.md`의 승인 또는 수정 요청
3. 필요한 ADR의 승인·보류·거절
4. `13_UNDERSTANDING.md`의 사용자 이해 확인
5. `16_FINAL_APPROVAL.md`의 최종 결정
6. 요구사항·비용·권한·데이터 결과가 달라지는 중요한 미확인 사항
7. 저장소 상태가 문서 기록과 충돌함

## AI가 자동으로 수행하는 작업

- STATUS가 없으면 작업 구조 초기화
- 현재 코드와 테스트 조사
- 계획 초안 작성과 사용자 피드백 반영
- ADR 필요 여부 판단과 Proposed 초안 작성
- 승인된 계획 단계를 순서대로 구현
- 단계별 테스트와 정적 검사
- 단계 보고와 검증 문서 작성
- 범위 내 테스트 실패 수정과 재검증
- 독립 리뷰 패스와 범위 내 P0/P1 수정
- PR 본문 초안과 기술 인수인계서 작성
- 상태 파일, 다음 행동, 미확인 항목 갱신

## Git 자동화

- 기능 브랜치 확인: `자동`
- base branch에서 시작했고 작업 트리가 깨끗하며 브랜치 이름을 안전하게 만들 수 있음: `작업용 브랜치 자동 생성 허용`
- 검증된 계획·ADR·구현 단계의 로컬 체크포인트 커밋: `허용`
- 커밋에 포함할 내용: `현재 작업 범위의 코드, 테스트, 단계 보고, STATUS`
- 관련 없는 staged/unstaged/untracked 변경 포함: `금지`
- rebase, force push, reset --hard, 다른 사람 변경 폐기: `금지`

브랜치 이름은 작업 입력의 제목과 작업 폴더를 사용하여 짧고 안전하게 제안한다. 기존 팀의 브랜치 규칙이 있으면 해당 규칙을 우선한다.

## 명시적인 추가 허가가 필요한 작업

다음은 자동 진행하지 않는다.

- 원격 저장소 push
- GitHub/GitLab PR 실제 생성
- PR 병합
- 배포
- 프로덕션 또는 공유 데이터 변경
- 외부 사용자에게 메시지 전송
- 비용이 발생하는 외부 서비스 실행
- secret, token, 권한 설정 변경
- 삭제 또는 복구가 어려운 작업

AI는 필요한 시점에 한 번만 구체적인 허가를 요청한다.

## 자동 중단 조건

- 계획에 없는 공개 API, DB, 이벤트 계약 변경이 필요함
- 새 production dependency 승인이 필요함
- 인증·권한·결제·개인정보에 계획되지 않은 위험이 발견됨
- 테스트가 반복 실패하고 안전한 범위 내 원인을 확정할 수 없음
- 다른 작업자의 변경과 충돌함
- 작업 폴더와 Git 상태가 일치하지 않음
- 인간 소유 파일의 필수 결정이 비어 있음
- P0/P1 리뷰 문제가 범위 내에서 안전하게 해결되지 않음

## 사람이 받는 메시지 형식

AI는 긴 진행 상황을 매 단계마다 보고하지 않는다. 자동 단계가 계속되는 동안 필요한 작업을 수행하고, 멈출 때 다음만 보여준다.

```text
현재 위치:
완료된 내용:
멈춘 이유:
사용자가 할 일:
작성할 정확한 파일:
작성할 정확한 항목:
저장 후 보낼 답변: 작성했어
```

## 정책 변경

팀은 필요하면 로컬 자동 커밋, 사람 게이트 또는 외부 동작 정책을 변경할 수 있다. 변경된 정책은 저장소에 커밋하여 모든 팀원과 Codex가 동일하게 사용하게 한다.
