# Codex와 Claude Code 간 작업 인계

Codex와 Claude Code는 동일한 `docs/ai-workflow/work-items/...` 문서와 Git 브랜치를 공유할 수 있다. 그러나 같은 work item을 동시에 수정하면 코드, STATUS, 테스트 결과와 커밋이 충돌할 수 있으므로 한 번에 하나만 실행한다.

## 공통 원칙

- `STATUS.md`의 `현재 실행 도구`는 `codex`, `claude`, `없음` 중 하나다.
- 한 도구가 `작업 중`이면 다른 도구는 자동으로 구현을 시작하지 않는다.
- 전환 전에는 가능한 한 검증 가능한 체크포인트를 만든다.
- 미커밋 변경이 있으면 파일과 현재 실패 상태를 정확히 기록한다.
- 새 도구는 STATUS만 믿지 않고 실제 Git 상태를 다시 확인한다.
- 같은 worktree를 동시에 두 도구에서 실행하지 않는다.

## Codex에서 Claude로 넘기기

Codex 대화에서 다음처럼 요청한다.

```text
현재 work item을 Claude Code로 인계할 수 있게 준비해 줘.
코드, 테스트, 단계 보고와 STATUS를 확인하고 가능한 경우 체크포인트 커밋을 만들어.
미커밋 변경과 실행하지 못한 테스트를 숨기지 말고 기록한 뒤 실행 도구 잠금을 해제해 줘.
```

Codex는 다음을 수행한다.

1. 현재 단계 중 안전하게 완료할 수 있는 부분을 검증한다.
2. 코드·테스트·단계 보고·STATUS를 체크포인트로 정리한다.
3. 미완성 파일과 테스트 결과를 기록한다.
4. `현재 실행 도구`를 `없음`, 상태를 `대기` 또는 `인계 준비`로 변경한다.
5. `다른 도구로 인계 가능`을 `예`로 변경한다.

Claude Code를 열고 다음처럼 시작한다.

```text
현재 작업 폴더는 다음입니다.
`docs/ai-workflow/work-items/2026-09-16/minsu/payment-timeout/`

Codex에서 인계받았습니다. STATUS와 실제 Git 상태를 대조한 뒤 자동 워크플로를 재개하세요.
```

## Claude에서 Codex로 넘기기

Claude Code에서 다음처럼 요청한다.

```text
현재 work item을 Codex로 인계할 수 있게 준비해 줘.
코드, 테스트, 단계 보고와 STATUS를 확인하고 가능한 경우 체크포인트 커밋을 만들어.
미커밋 변경과 실행하지 못한 테스트를 숨기지 말고 기록한 뒤 실행 도구 잠금을 해제해 줘.
```

그다음 Codex에서 작업 폴더 경로와 함께 재개를 요청한다.

## 비정상 종료 후 잠금이 남은 경우

도구가 종료되어 `작업 중` 기록만 남았다고 잠금을 임의로 덮어쓰지 않는다. 새 도구에게 다음을 요청한다.

```text
이 work item의 이전 실행 도구가 비정상 종료되었습니다.
STATUS와 실제 Git 상태, 마지막 커밋, 미커밋 변경, 테스트 유효성을 대조해 주세요.
아직 코드를 수정하지 말고 안전한 인계 가능 여부와 불일치만 보고해 주세요.
```

사용자가 요약을 확인한 뒤 인계를 승인하면 새 도구가 현재 실행 도구를 자기 이름으로 바꾸고 작업을 재개한다.

## 별도 worktree를 사용하는 경우

서로 다른 작업이라면 Codex와 Claude가 각각 별도 브랜치와 worktree에서 동시에 작업할 수 있다. 같은 work item, 같은 브랜치 또는 같은 파일 영역을 동시에 수정하지 않는다.
