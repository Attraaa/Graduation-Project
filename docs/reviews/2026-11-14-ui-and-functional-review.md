# Moti UI 변경과 전체 기능 재검토

기준: 2026-11-14, 병합 완료 커밋 `ceafd32`에서 시작한 `codex/overlay-session-review`. 사용자 요청의 1번인 오버레이·상체/키보드 학습 상세 UI만 제품 코드를 수정했다. 2번 기능 검토에서 발견한 문제는 수정하지 않고 이 문서에 기록한다. 서버·DB 계약·카메라 생명주기·점수/보정/알림 판정 정책은 변경 대상이 아니다.

UI 구현과 아래 검토를 완료했다. 기능 검토는 확인한 정상 동작·결함·환경 제약을 구분하며, 프로젝트의 모든 문제가 해결됐다는 뜻이 아니다.

## 1. UI 구현

- 오버레이: Moti 아이콘과 기존 테마 토큰을 사용한다. 모드 이름·상태, 수치·활성 시간을 두 행으로 정리하고 제어 버튼을 각 행 오른쪽으로 옮겼다. 시작/일시정지·재개/중지는 별도 고정 슬롯이며 이름과 툴팁을 제공한다. 기본 강조는 시작에만 쓰고 중지는 중립 버튼으로 표시한다. **돌아가기**는 창 하단에 고정하고 오류 안내 공간을 유지했다.
- 학습 상세: 상체와 키보드 모두 카메라/조작 영역과 실시간 지표/안내 영역을 나란히 배치한다. 좁은 창에서는 세로로 쌓는다. 지표를 반복된 작은 카드 대신 구분선 목록으로 표현하고 현재 값과 세션 평균을 구분한다. 카메라 설정·기준/위치 재수집은 상단, 시작·일시정지/재개·중지는 카메라 하단에 배치했다.
- 작은 창: 미리보기의 외곽 16:9와 분석 해상도를 보존하면서 짧은 창에서는 미리보기 표시 폭을 줄여 첫 화면에서 제어가 보이도록 했다. 상태 문구 길이와 무관하게 제어 슬롯의 크기를 유지한다.
- 대시보드는 기존 카드 표현을 유지한다. 점수 0·자료 없음·세션 평균·깜빡임 단위와 보정/보호/오류 안내 의미를 바꾸지 않았다.

변경 전후와 라이트/다크·크기별 화면은 `reports/ui-review-2026-11-14/`에 보관한다. 해당 디렉터리는 원래 저장소 정책에 따라 Git 제외 대상이다.

P1은 외부 배포·사용자 테스트 전에 우선 판단할 항목, P2는 정상 사용 또는 복구 신뢰성에 영향을 주는 항목, P3는 제한된 환경의 불편·추가 검토 항목이다.

| Q-11 | P2 | 부하가 있는 개발 환경에서 분석기 준비가 45초를 넘은 사례 | 네이티브 IPC 검사 1회 시간 초과. 같은 서비스의 단독 실행 7,316ms·유휴 IPC 재검사 4,743ms로 성공. 항상 재현되는 고장이나 원인 확정으로 표현하지 않음 | 시작 단계별 시간과 부하 영향을 측정하고 지원 환경·실패 안내/재시도 기준을 검토 |
| Q-12 | P2 | 새 Setup에 Authenticode 서명이 없음 | 새 산출물 검사 결과 NotSigned. 빌드의 ‘signing with signtool’ 로그와 구분. 실제 SmartScreen 표시를 확인한 것은 아님 | 외부 배포 방식과 코드 서명 필요 여부를 결정하고 깨끗한 PC에서 확인 |

핵심 관리 표는 **12건(P1 3·P2 8·P3 1)**이다. Q-01/02/03/08/09는 기존 R-01/02/03/04/05와 중복되므로 기존 보고서의 건수와 단순 합산하지 않는다. 이번에 추가 기록한 나머지 항목도 이번 UI 변경이 새로 만든 회귀라는 뜻은 아니다.

기존 검토의 나머지 미해결 항목은 폐기하거나 해결로 간주하지 않는다. [기존 전체 보고서](../../reports/release-review-2026-11-14/report.md)의 R-07·08·10·11·12·13·18·19·20·21은 이번 변경으로 전체 해결된 것이 아니다. 학습 상세의 제어 명암 대비 개선은 앱 전체의 R-07 해결과 다르다. R-09의 오류 후 제어/시간 중지는 재검사에서 유지됐고 원인별 상세 설명은 일반 안내로 남는다.

## 5. 최종 검증

새 파일은 `front/release/Moti Setup 0.0.0.exe`, 484,840,704바이트, SHA-256 `e9ca6a806d80ed8cf5fe04989832b1fe8181ec9d53f8f3404fb202d3ac6c54f0`이다. blockmap은 505,181바이트, SHA-256 `3d6f18db25611050253de2f33c35abc41834352a6b23f7809ccd3434b69165f2`다. app.asar의 실행 파일 37개를 현재 빌드와 대조했다. 개발 전용 `index.d.ts`는 패키징 기본 제외 대상이며 실행 검증에 포함하지 않는다.

브라우저 UI와 API 쓰기는 격리된 계정·임시 MySQL에서만 수행했다. 설정된 외부 API는 인증 정보 없는 health 요청만 했다. 원래 설치된 Moti를 설치/제거로 변경하지 않았다. 유료 Claude 호출·외부 SMTP 배달·두 실물 카메라의 동시 정확도·깨끗한 PC·물리 다중 모니터는 위 제약과 결정 항목으로 남긴다.

결과 원본, 스크립트, 화면, 빌드/검사/패키지 로그와 소스 지문은 `reports/ui-review-2026-11-14/`에 보존한다. 테스트용 MySQL 호스트 설정, Express 계측 레이어, hash URL 대기, SMTP STARTTLS 수신기, 부하 중 화면 로드 제한, ASAR 경로 구분자와 개발 타입 필터의 하네스 보완은 제품 결함으로 세지 않았다. 구형 7-Zip 16.04의 ARM64 필터 미지원 2건은 builder의 최신 7-Zip으로 재검사해 내부 파일 3,646개가 정상임을 확인했다. 최초 실패 로그도 보존했다. 기존 큰 청크·동적 import·일시적 차트 치수 경고는 로그에 구분했다.
