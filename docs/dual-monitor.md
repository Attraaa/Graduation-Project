# 듀얼 모니터 — 보는 화면 구분과 화면별 시간

2026-11-02, 브랜치 `claude/dual-monitor`. 상체 측정 중 **얼굴 방향으로 지금 어느 모니터를 보는지** 구분합니다. 옆 모니터를 볼 때는 "정면을 향해 주세요" 경고 대신 보고 있는 화면을 알려 주고, 측정 세션 동안 화면별 사용 시간을 보여 줍니다. 눈동자 시선 추적이나 의료 판정이 아니며, 목·어깨 점수 산식과 회전 보류 정책은 바꾸지 않았습니다.

## 왜 필요한가

- 상체 점수는 고개가 돌아가면 판정을 멈춥니다(`observation.ts`의 `head-turned`, 귀가 가려지면 `low-confidence`). 안구도 고개를 많이 돌리면 보류합니다.
- 그래서 듀얼 모니터 사용자는 옆 화면으로 일하는 동안 "정면을 향해 주세요" 안내를 계속 봅니다. 실제로는 정상적으로 일하는 중인데 경고처럼 보입니다.
- 이 기능은 그 시간을 **"오른쪽 모니터를 보는 중"** 으로 설명하고, 어느 화면을 얼마나 오래 봤는지를 기록합니다.

## 사용 흐름

1. 홈이나 상체 상세에서 상체 측정을 시작합니다.
2. 상체 상세 화면의 **듀얼 모니터** 카드에서 **모니터 방향 등록**을 누릅니다.
   - **데스크톱 앱 + 모니터 2대 이상:** Moti 창이 있는 모니터부터 화면 가운데에 초록 점이 차례로 나타납니다. 점을 바라보면 고개 방향을 1.5초 모아 등록하고 다음 모니터로 넘어갑니다(최대 4대).
   - **브라우저 실행이거나 모니터가 1대로 보일 때:** "카메라가 있는 정면 모니터 → 보조 모니터" 순서로 직접 바라봅니다. 다른 컴퓨터의 화면처럼 연결되지 않은 보조 화면도 이 방식으로 등록할 수 있습니다.
3. 등록이 끝나면 카드가 **지금 보는 화면**, 화면별 시간 비율, 화면 전환 횟수, 정면이 아닌 화면을 가장 길게 이어서 본 시간을 보여 줍니다.
4. 5분 이상 관찰하면 배치 안내를 한 줄 보여 줍니다.
   - 정면이 아닌 화면 비율이 50% 이상이면 가장 많이 보는 화면을 몸 정면에 두고 카메라도 그 화면 위로 옮기라고 안내합니다.
   - 정면이 아닌 한 화면을 10분 이상 이어서 봤으면 오래 보는 작업 창을 정면 화면으로 옮기라고 안내합니다.
   - 둘 다 아니면 정면 위주로 쓰고 있다고 알려 줍니다.
5. 등록한 방향은 이 기기에 저장되어 다음 측정에서도 씁니다. **다시 등록**과 **등록 해제** 버튼이 있습니다.

## 동작 원리

| 단계 | 내용 | 파일 |
| --- | --- | --- |
| 얼굴 방향 | 이미 깜빡임에 쓰는 Face Landmarker에 `outputFacialTransformationMatrixes`를 켜고, 변환 행렬의 회전에서 yaw(좌우)·pitch(상하)를 도 단위로 읽습니다. 새 모델이나 카메라는 없습니다. 얼굴이 정확히 하나일 때만 사용합니다. | `features/dual-monitor/headPose.ts`, `features/eye/EyeMonitor.tsx` |
| 방향 등록 | 점이 뜬 뒤 1.2초는 고개 돌리는 시간으로 버립니다. 흔들림 6° 이내로 1.5초(최소 10표본)를 모아 중앙값을 등록합니다. 이미 등록한 화면과 10° 안쪽이면 아직 고개를 돌리지 않은 것으로 보고 기다립니다. 0.5초 넘게 얼굴이 안 보이면 다시 모으고, 한 화면에 15초를 넘기면 실패로 끝냅니다. | `layout.ts` |
| 정면 모니터 | 등록한 방향 중 카메라를 가장 정면으로 보는 방향(yaw·pitch 크기가 가장 작은 방향)을 **정면 모니터**로 정합니다. 상체 기준 자세의 "정면"과 같은 뜻입니다. 나머지는 Windows 디스플레이 배치에서의 위치로 "왼쪽/오른쪽/위쪽/아래쪽 모니터"라고 부르고, 위치를 모르면 "보조 모니터"라고 부릅니다. | `layout.ts` |
| 화면 판정 | 가장 가까운 등록 방향을 고릅니다. 모든 화면에서 25° 넘게 벗어나면 "화면 밖"입니다. 다른 화면이 3° 이상 더 가깝고 그 상태가 0.3초 이어져야 전환으로 인정하며, 그 0.3초도 새 화면 시간에 넣습니다. 짧은 눈짓은 원래 화면 시간으로 남깁니다. | `tracker.ts` |
| 시간 집계 | 표본 간격이 1초를 넘거나 얼굴이 1초 넘게 사라진 구간, 일시정지·중지 구간은 어느 화면에도 넣지 않습니다. "화면 밖"은 화면 전환 횟수에 세지 않습니다(정면 → 화면 밖 → 오른쪽은 전환 1회). | `tracker.ts` |
| 상태 소유 | `MonitoringProvider`가 `useDualMonitor`로 등록 상태와 세션별 집계를 소유합니다. 프레임마다 받는 값은 ref로만 갱신하고 화면은 0.25초마다 갱신합니다. 새 상체 실행이 시작되면 집계를 초기화하고 등록 방향은 유지합니다. | `useDualMonitor.ts`, `features/session/MonitoringProvider.tsx` |
| 화면 | 상체 상세의 듀얼 모니터 카드와, 판정 보류 중 보조 모니터를 볼 때 바뀌는 안내 문구입니다. 표시만 하며 계산을 소유하지 않습니다. | `DualMonitorPanel.tsx`, `features/posture/PostureSession.tsx` |
| 데스크톱 연동 | Electron main이 연결된 모니터의 id·위치·이름만 넘깁니다(`displays:list`). 등록 중에는 해당 모니터 작업 영역 가운데에 클릭이 통과하는 작은 점 창을 띄웁니다(`displays:show-target`/`hide-target`). 모니터를 연결·해제하거나 배치를 바꾸면 `displays:changed`를 보냅니다. 점 창은 preload 없이 sandbox로 열고 30초 뒤 자동으로 닫습니다. | `electron/displays.ts`, `electron/main.ts`, `electron/preload.ts`, `public/display-target.html` |

숫자 설정은 모두 `features/dual-monitor/screenSettings.ts` 한 곳에 있습니다. 실제 책상 배치에서 검증하기 전의 임시 제품 값입니다.

## 저장과 무효화

- 등록한 방향은 이 기기의 `localStorage` `moti.dual-monitor.layout`(version 1)에 저장합니다. 서버로 보내지 않으며 DB 스키마·API·기록 계약은 바뀌지 않습니다.
- 화면별 시간은 세션 메모리에만 있고 통계·학습이력에 저장하지 않습니다.
- 등록 방향은 같은 카메라 장치와 같은 영상 변환(좌우 반전·회전·자르기 등, `imageSignature`)일 때만 씁니다. 좌우 반전이 바뀌면 yaw의 부호가 뒤집히기 때문입니다.
- 모니터 구성(id·위치·크기)이 바뀌어도 쓰지 않습니다. 이때 카드는 다시 등록하라고 안내하고 집계를 멈춥니다.
- 저장 값이 손상되었거나 형식이 다르면 무시하고 등록 전 상태로 보여 줍니다.

## 검증한 것과 한계

자동 검사(`front/tests/dual-monitor.test.mjs`, 16개)로 확인한 것은 다음과 같습니다.

- 회전 행렬에서 yaw·pitch 복원(roll·배율·행/열 우선 순서 무관), 잘못된 입력 거부
- 등록의 대기·흔들림·얼굴 유실·짧은 끊김 허용·10° 근접 거부·제한 시간
- 모니터 배치 기반 이름과 번호 매기기, 저장 값 검증과 무효화
- 판정의 전환 대기와 시간 귀속, 경계 흔들림 억제, 화면 밖, 공백·일시정지 제외, 요약·안내 조건
- Electron 헬퍼의 입력 검증, 카드의 각 상태 표시

**확인하지 않은 것:**

- 실제 카메라와 사람 얼굴로 측정한 방향 정확도
- 실물 모니터 2대에서 점 창이 뜨는 모습과 등록 흐름
- 큰 회전(대략 45° 이상)에서 Face Landmarker가 얼굴을 계속 찾는지

**알려진 한계:**

- 얼굴 방향이지 눈동자 시선이 아닙니다. 고개는 그대로 두고 눈만 옆 화면으로 돌리면 정면으로 판정합니다.
- 옆 모니터가 매우 멀리 있어 얼굴이 옆모습에 가까워지면 얼굴을 놓칠 수 있고, 그 시간은 집계하지 않습니다.
- 정면 모니터는 몸이 향한 방향이 아니라 카메라를 정면으로 보는 방향입니다. 카메라를 보조 화면에 달았다면 그 화면이 "정면 모니터"가 됩니다. 이 경우는 배치 안내가 카메라 이동을 권합니다.
- Windows 디스플레이 설정의 배치가 실제 책상 배치와 다르면 "왼쪽/오른쪽" 이름이 틀릴 수 있습니다. 판정 자체는 등록한 방향을 쓰므로 영향을 받지 않습니다.
- 옆 화면을 보는 동안 목·어깨 점수는 지금처럼 보류합니다. 그 시간에도 점수를 매기려면 아래 다음 단계 1번의 별도 검증이 필요합니다.

## 다음 단계 (제안, 미구현)

1. **화면별 기준 자세:** 모니터마다 기준 자세를 따로 모아, 옆 화면을 보는 동안에도 그 화면 기준으로 목·어깨를 평가합니다. [회전·카메라 높이 검토](posture-viewpoint-proposal.md)대로 0/10/20° 이상 회전에서 실측 비교한 뒤 점수 정책 버전을 올려야 합니다.
2. **보는 화면에 알림 띄우기:** 아직 없는 자세 알림을 만들 때, 지금 보는 모니터에 작은 알림 창을 띄웁니다. 등록에 쓴 점 창의 위치 계산과 click-through 창을 재사용할 수 있습니다.
3. **화면별 시간 저장:** 통계·학습이력에 "오늘 오른쪽 모니터 42%"처럼 보여 주려면 기록 계약(`database/`)과 서버 마이그레이션을 추가해야 합니다.
4. **한쪽으로 오래 돌린 목 알림:** 정면이 아닌 화면을 오래 이어서 보면 잠깐 정면으로 풀어 주라고 실시간으로 안내합니다. 기준 시간은 사용자 피드백으로 정해야 합니다.
