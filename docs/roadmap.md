# 합의된 방향과 남은 작업

사용자 답변(D1~D8, 추가 D4/D7 답변)을 반영했습니다. 이전의 “전체 팀 확인 대기” 상태는 끝났습니다. 다음 작업은 [제품 결정](product-decisions.md)과 현재 [구조](architecture.md)를 기준으로 이어갑니다.

## 확정된 방향

- 개발/배포 모두 Windows. 정확한 버전과 간편 설치 방법은 구현자가 선정합니다.
- 한 번에 한 모드, 카메라 한 개로 시작합니다. 상체는 화상회의 구도, 키보드는 손/손목 구도입니다.
- 서버와 첫 자세 캘리브레이션은 새로 구성할 수 있습니다. 더 효과적인 구간은 기존 구현을 교체해도 됩니다.
- 매 세션 기준 자세를 수집합니다. 자세 점수와 작업/휴식 지표는 분리합니다.
- 기록은 서버에 저장하는 방향입니다. DB 제품은 아직 미정이며 SQLite 오프라인 사용은 이후 검토합니다.
- 키보드의 “틀림”은 권장 손가락과 다른 손가락을 사용한 경우입니다. 글자 오타 판정이 아닙니다.
- 키별 결과와 통계를 저장하고, AI는 사용자 API 키 사용을 기본 구상으로 검토합니다. 로컬 AI 대안도 비교합니다.
- UI는 공통 규칙과 컴포넌트로 먼저 정리합니다. 졸업 일정과 개인 담당자 배정은 이번 범위에서 다루지 않습니다.

## 다음 구현 순서

1. **DB와 데이터 계약:** 개발/배포 DB를 정하고 기준 자세, 관측, 세션, 손가락 통계, 점수 정책 버전의 저장 형태를 확정합니다. 기존 DB나 기존 두 SQL을 초기화하지 않습니다.
2. **한 모드의 실제 저장 경로:** 인증 → 기준 수집 → 관측 → 세션 종료 → 서버 저장 → 다시 열어 같은 기록 확인을 완성합니다. 사용자의 API 키나 영상 데이터를 먼저 서버로 보내지 않습니다.
3. **점수와 습관 평가:** 동일 입력에 동일 출력, 누락과 오사용의 구분, 임계값 경계와 자정 집계를 검증합니다. 기준 자세 유사도와 해부학적 진단을 구분합니다.
4. **키보드 검증·저장:** 현재 실시간 개발 연결에서 실물 영상으로 키 이름/손/손가락과 판정 보류 기준을 검증하고, 판별 가능한 입력을 분모로 통계를 만듭니다. Shift/Ctrl 등 미지원 키와 배열별 예외 정책을 정합니다.
5. **UI 전체 이관:** 실제 로딩·저장 실패·재시도·측정 불가 상태에 맞춰 페이지를 정리합니다. 필요한 복합 입력만 외부 UI primitive로 바꿉니다.
6. **요약과 배포:** 기본 집계 요약부터 완성하고 선택적 BYOK/로컬 AI를 연결합니다. 개발 도구가 없는 Windows에서 설치·실행을 확인합니다.

## 구현 전 남은 결정

필요한 질문만 해당 단계에서 확인합니다. Windows 여부나 모드별 실행처럼 이미 답한 내용은 다시 묻지 않습니다.

- 서버 DB 제품/호스팅, 기존 데이터 보존 여부와 초기 스키마 적용 대상
- 자세 점수 산식/평가 기준, 자세 변화 이벤트와 휴식 인정 조건
- 키보드 배열과 권장 손가락 예외(엄지/Space, Shift, Ctrl 등), 관측 신뢰도 기준
- AI 제공자/모델과 사용자 키 입력 UX, 집계/결과의 보관 기간

새 구조를 문서와 다르게 바꾸면 entry point, 명령, 입출력 계약, 실제 검증 결과를 같은 변경에서 갱신합니다. 미구현 항목을 문서의 계획만 보고 완료로 간주하지 않습니다.
