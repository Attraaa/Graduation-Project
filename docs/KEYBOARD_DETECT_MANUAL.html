Keyboard Detect Runtime Manual

VDT 증후군 개선 프로젝트에 붙이기 위한 비웹 런타임 문서입니다. 이 패키지는 Electron 같은 데스크톱 환경에서도 Python 모듈로 직접 사용할 수 있으며, 웹 테스트 서버는 선택형 디버그 도구일 뿐입니다.

목차 빠른 시작 동작 구조 파일 역할 키로거 동작 키보드 매핑과 고정 딜레이와 타이밍 테스트 실행법 통합 코드 예시 주요 API 문제 해결 보안 메모

빠른 시작

패키지 위치는 D:\keyboard detect입니다. 먼저 의존성을 설치합니다.

cd "D:\keyboard detect"
python -m pip install -r requirements.txt

웹 없이 OpenCV 창으로 전체 흐름을 테스트합니다.

cd "D:\keyboard detect"
python keylog\examples\live_console_test.py

성공적으로 잡히면 터미널에 다음처럼 출력됩니다.

[map debug] keyboard ok keys=61
[key event] Q source=global
[Q] Right index on Q | delta=12.4ms analysis=87.3ms
고정 매핑: 미리보기 창에서 키보드 오버레이가 잘 맞으면 왼쪽 클릭하세요. 이후 손이 네 코너 키를 가려도 저장된 키 polygon을 계속 사용합니다.

동작 구조

1. 카메라 프레임
OpenCV, Electron, 기존 VDT 카메라 모듈에서 BGR/RGB 프레임 확보
2. 손끝 좌표
MediaPipe가 엄지, 검지, 중지, 약지, 소지 끝점을 픽셀 좌표로 변환
3. 키 입력
명시적으로 켠 키로거 또는 앱의 키 이벤트가 KeyEvent 생성
4. 시간 매칭
FrameBuffer가 키 입력 시각에 가장 가까운 프레임 선택
5. 판정
KeyboardPressAnalyzer가 손끝이 어떤 key polygon 위인지 계산

기존 AI 모듈인 KeyboardCoordinateMapper는 키보드의 ~, Backspace, L-Ctrl, R-Ctrl 네 코너를 YOLO로 찾고, perfect_map.json의 기준 좌표를 현재 프레임에 homography로 투영합니다.

키로거 동작

RealTimeKeyLogger는 자동으로 켜지지 않습니다. 외부 코드가 start()를 호출한 뒤부터만 입력을 받고, stop()을 호출하면 즉시 멈춥니다. 

from keylog import RealTimeKeyLogger

def on_event(event):
    print(event.key, event.perf_counter_ns)

logger = RealTimeKeyLogger(on_event=on_event)
logger.start()

# 필요한 시간 동안만 실행

logger.stop()
항목동작
입력 소스pynput.keyboard.Listener 기반 전역 key press
ON/OFFstart(), stop()로 명시 제어
반복 입력기본값은 키를 누르고 있는 동안 반복 이벤트 제거. capture_repeats=True면 반복 허용
키 이름 변환normalize_key_name()으로 Space를 Spacebar, ControlLeft를 L-Ctrl처럼 map 파일 이름에 맞춤
저장파일 저장 없음. 콜백으로 이벤트 객체만 전달
Electron 앱이 이미 키 이벤트를 갖고 있다면 전역 키로거를 쓰지 않는 편이 더 좋습니다. Electron의 keydown 이벤트를 Python 쪽으로 IPC 전달하고 KeyEvent.now("Q")처럼 만들면 됩니다.

키보드 매핑과 고정

라이브 매핑은 현재 프레임에서 네 코너 키를 다시 찾습니다. 손이 코너를 가리면 실패할 수 있으므로, 좋은 매핑을 한 번 잡은 뒤 고정해서 쓰는 기능이 들어 있습니다. 

from keylog import KeyboardPressAnalyzer

analyzer = KeyboardPressAnalyzer()

# 좋은 프레임에서 키보드 매핑 계산
mapping = analyzer.map_keyboard(frame_bgr)
if mapping.ok:
    analyzer.freeze_mapping(mapping)

# 이후 analyze()는 frozen mapping을 우선 사용
result = analyzer.analyze(event, snapshot, frame_delta_ms=delta_ms)

# 카메라나 키보드 위치가 바뀌면 고정 해제
analyzer.unfreeze_mapping()
메서드역할
map_keyboard(frame)라이브 프레임에서 키보드 polygon 계산. 성공하면 latest mapping으로 저장
freeze_mapping(mapping)현재 좋은 mapping을 고정
unfreeze_mapping()고정 해제 후 다시 라이브 매핑 사용
current_mapping()고정 mapping이 있으면 그것을, 없으면 마지막 성공 mapping 반환
frozen현재 고정 모드인지 확인

고정 매핑은 카메라와 키보드 위치가 유지될 때만 정확합니다. 키보드가 움직였거나 카메라 각도가 바뀌면 반드시 고정을 풀고 다시 잡아야 합니다.

딜레이와 타이밍

키 입력 순간의 손 위치를 맞추려면 같은 시간 기준으로 이벤트와 프레임을 비교해야 합니다. 이 패키지는 time.perf_counter_ns()를 기준으로 키 이벤트와 프레임 수신 시각을 남깁니다.

파라미터기본값의미
camera_receive_delay_ms80실제 촬영 시각과 Python이 프레임을 받은 시각 사이의 추정 지연
analysis_wait_ms120키 이벤트 직후 해당 시각의 프레임이 버퍼에 들어올 시간을 기다림
frame_delta_ms결과값선택된 프레임이 보정된 키 입력 시각보다 얼마나 앞/뒤인지
latency.analysis_ms결과값YOLO/손끝/판정 계산에 걸린 시간. 입력 순간 선택에는 직접 쓰지 않음

통합 코드 예시

VDT 프로젝트가 이미 카메라와 MediaPipe를 갖고 있는 경우

import time
from keylog import FrameBuffer, FrameSnapshot, KeyEvent, KeyboardPressAnalyzer
from keylog.events import FingerPoint

frames = FrameBuffer(max_frames=180)
analyzer = KeyboardPressAnalyzer()

# 카메라 루프 안에서 실행
finger_points = [
    FingerPoint(hand="Right", finger="index", x=index_x, y=index_y),
    FingerPoint(hand="Right", finger="middle", x=middle_x, y=middle_y),
]

frames.add(FrameSnapshot(
    frame=frame_bgr,
    perf_counter_ns=time.perf_counter_ns(),
    wall_time_ns=time.time_ns(),
    sequence=frame_no,
    fingers=finger_points,
))

# 앱의 키 입력 콜백 안에서 실행
event = KeyEvent.now("Q", source="electron")
snapshot, delta_ms = frames.nearest_for_event(event, camera_receive_delay_ms=80)
result = analyzer.analyze(event, snapshot, frame_delta_ms=delta_ms)

print(result.pressed_key)
print(result.pressed_finger)

Python이 키 입력까지 직접 받는 경우

from keylog import RealTimeKeyLogger

def on_key(event):
    snapshot, delta_ms = frames.nearest_for_event(event, camera_receive_delay_ms=80)
    result = analyzer.analyze(event, snapshot, frame_delta_ms=delta_ms)
    print(result.to_jsonable())

logger = RealTimeKeyLogger(on_event=on_key)
logger.start()

# 앱 종료 시
logger.stop()

Electron 연동 방식

권장 형태는 Electron이 UI, 카메라, 앱 키 이벤트를 담당하고 Python 프로세스는 판정만 담당하는 구조입니다. IPC, stdin/stdout JSON, 로컬 소켓 중 프로젝트 구조에 맞는 통로를 선택하면 됩니다. 

// Electron 쪽 예시 개념
window.addEventListener("keydown", (event) => {
  sendToPython({
    type: "key",
    key: event.key,
    code: event.code,
    timestamp: performance.now()
  });
});

주요 API

이름설명
KeyEvent.now(key)현재 clock으로 키 이벤트 생성
FrameSnapshot(...)프레임, 시간, 손끝 좌표를 묶은 객체
FingerPoint(...)한 손가락 끝의 픽셀 좌표
FrameBuffer.add(snapshot)프레임을 버퍼에 추가
FrameBuffer.nearest_for_event(event)키 이벤트에 가장 가까운 프레임 선택
KeyboardPressAnalyzer.analyze(...)무슨 손가락이 무슨 키 위에 있었는지 판정
PressAnalysis.to_jsonable()결과를 JSON 직렬화 가능한 dict로 변환

문제 해결

증상의미조치
[key event]가 안 나옴전역 키 입력 캡처 실패 또는 창 포커스 문제OpenCV 창을 클릭 후 다시 누르기. 필요하면 관리자 권한 터미널에서 실행. 또는 Electron 키 이벤트를 직접 넘기기
keyboard fail reason=missing_cornersYOLO가 네 코너 키 중 일부를 못 찾음~, Backspace, L-Ctrl, R-Ctrl이 모두 보이게 카메라 조정
keyboard fail reason=low_confidence코너는 찾았지만 신뢰도가 낮음초점, 조명, 반사, 흔들림 개선
손이 코너를 가리면 매핑이 풀림라이브 매핑이 현재 프레임에서 네 코너를 다시 찾기 때문keyboard ok keys=61 상태에서 왼쪽 클릭으로 고정 매핑 사용
키는 맞는데 손가락이 다름프레임 타이밍 또는 MediaPipe 손끝 좌표 문제--camera-delay-ms, --analysis-wait-ms 조정. 손끝이 카메라에 보이게 배치
카메라가 열리지 않음카메라 인덱스 불일치 또는 다른 앱이 사용 중--camera-index 1, --camera-index 2 순서로 확인

보안 메모

이 패키지는 숨김 실행, 입력 파일 저장, 외부 전송을 하지 않습니다. 전역 키 입력은 RealTimeKeyLogger.start()를 호출한 동안만 콜백으로 전달됩니다.

Python 코드만으로 운영체제 수준의 다른 프로세스가 키 입력을 관찰하는 것을 완전히 막을 수는 없습니다. 최종 앱에서는 가능한 한 Electron/앱 내부 키 이벤트를 직접 넘기고, 전역 키로거는 테스트 또는 필요한 범위에서만 켜는 편이 좋습니다.
