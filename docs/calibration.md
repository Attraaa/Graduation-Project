# 세션별 기준 자세 캘리브레이션

대상 구현: [calibration.ts](../front/src/features/posture/calibration.ts). 검증: [calibration.test.mjs](../front/tests/calibration.test.mjs). 이 문서는 기준값 수집 계약을 설명합니다. 화면·API 연결 여부는 [architecture.md](architecture.md)를 함께 확인합니다.

## 무엇을 수집하는가

사용자가 매번 측정을 시작할 때 기준으로 삼을 자세를 정하고, 카메라에서 안정적으로 관측한 값의 중앙값을 저장합니다. 카메라 위치와 사용자의 착석 위치가 세션마다 달라질 수 있어 새 세션은 새 기준값으로 시작합니다. 자동으로 기준값을 계속 갱신하면 서서히 바뀐 자세가 새 기준으로 흡수되므로, 완료된 기준값은 고정합니다.

MediaPipe는 신체 랜드마크의 이미지 좌표와 모델이 추론한 3차원 좌표를 제공합니다. 이미지 `x`는 너비, `y`는 높이로 각각 정규화하며 `visibility`는 랜드마크 가시성의 추정값입니다. 따라서 가로·세로 비율이 다른 화면에서 정규화된 두 좌표를 그대로 같은 길이 단위로 계산하면 안 됩니다. [Google MediaPipe Web 공식 문서](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

현재 모듈은 정면 상체 화면의 코와 양 어깨 좌표를 픽셀로 환산하고 다음 값을 구합니다. 분모인 어깨 너비는 **화면에 투영된 양 어깨 사이 픽셀 거리**이며 실제 신체 길이가 아닙니다.

| 필드 | 의미와 단위 |
| --- | --- |
| `noseOffsetShoulderWidths` | 어깨 중점 대비 코의 화면 오른쪽 이동량 / 어깨 너비. 무차원 비율 |
| `noseHeightShoulderWidths` | 어깨 중점보다 코가 화면 위에 있는 높이 / 어깨 너비. 무차원 비율 |
| `shoulderHeightDifferenceShoulderWidths` | 해부학적 왼쪽 어깨 y − 오른쪽 어깨 y / 어깨 너비. 화면 아래쪽이 양수 |

**설계상 해석 한계:** 이 비율은 기준 자세 대비 화면상 변화량입니다. 정면 2차원 관측으로 실제 목의 전방 이동량이나 해부학적 거북목 각도를 확정할 수 없다는 판단에 따라, 이 모듈은 거북목 여부·정상 여부·100점 환산을 반환하지 않습니다. 고개 회전, 카메라 기울기, 사용자와 카메라 사이 거리도 관측값에 영향을 줄 수 있습니다. 이 해석은 좌표 계약에 근거한 설계상의 추론이며, 제품의 정확도를 검증한 결과가 아닙니다.

기존 Pose 문서의 품질 평가 조건은 2–4m 거리의 한 사람과 Yoga/Dance/HIIT 데이터입니다. 이를 가까운 노트북 웹캠 구도의 성능 보장으로 취급하지 않습니다. 실제 사용할 구도의 검증 영상을 별도로 확보해야 합니다. [MediaPipe 저장소의 Pose 평가 설명](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/pose.md#pose-estimation-quality)

## 수집 흐름과 임시 설정

1. 얼굴과 양 어깨가 보이는 미리보기와 기준 자세 안내를 표시합니다. 사용자에게 기준으로 삼을 자세를 정하고 잠시 유지하도록 안내한 후 수집을 시작합니다.
2. 유효한 관측이 연속으로 쌓이는 동안 진행률을 표시합니다. 랜드마크 누락·낮은 가시성·화면 이탈은 이전 수집분을 지웁니다. 관측 실패를 정상 또는 0으로 기록하지 않습니다.
3. 전체 수집 구간의 변화 폭을 확인합니다. 한 프레임씩 조금 움직이는 느린 이동도 누적 변화가 커지면 다시 수집합니다. 저장 간격 사이에 들어온 프레임도 움직임 검사를 합니다.
4. 시간과 표본 수 조건을 모두 충족하면 지표별 중앙값을 기준으로 확정합니다. 작은 허용 범위 내 일시적인 좌표 튐이 평균값을 끌어당기는 영향을 줄이기 위한 선택입니다.
5. 새 세션, 모드 전환, 카메라 재배치 후에는 새로 수집합니다. 카메라 스트림 ID 또는 영상 크기가 바뀐 경우는 코드가 자동으로 무효화합니다. 같은 스트림으로 카메라를 물리적으로 옮긴 사실은 확정할 수 없으므로 사용자의 재설정 경로가 필요합니다.

아래 값은 `DEFAULT_CALIBRATION_OPTIONS`에 모여 있는 **수집용 임시 설정**입니다. 정확도·건강·자세 점수의 기준이 아니며, 실제 웹캠 검증 결과로 조정합니다. 한 수집 과정 중에는 설정을 바꾸지 않습니다.

| 설정 | 기본값 |
| --- | --- |
| 연속 수집 시간 | 3,000ms 이상 |
| 표본 수 | 20개 이상. 100ms 간격이면 일반적으로 31개 |
| 저장 표본 사이 최소 간격 | 100ms |
| 표본 공백 허용 | 500ms까지. 초과 시 재시작 |
| 각 필수 랜드마크 가시성 | 0.7 이상 |
| 양 어깨의 수평 간격 | 영상 너비의 0.1 이상 |
| 지표별 전체 수집 구간 변화 폭 | 어깨 너비 대비 0.08 이하 |
| 어깨 중점 x/y 변화 폭 | 각각 영상 너비/높이 대비 0.025 이하 |
| 어깨 너비 변화 폭 | 영상 너비 대비 0.025 이하 |

안정적인 관측이라는 사실만으로 사용자의 자세가 올바르다고 판정하지 않습니다. UI 완료 문구도 “기준 자세 저장 완료”로 표현합니다. 자세 점수와 작업 습관 지표는 분리하기로 했지만, 기준값을 점수로 환산하는 공식과 지속시간 조건은 이 모듈에 포함하지 않습니다.

## 연결 계약

```ts
// 매 세션과 명시적인 재설정 시에 생성합니다.
let calibration = createCalibration();

// 새 영상 프레임에 대한 MediaPipe 결과마다 호출합니다.
const frame = {
  landmarks: results.poseLandmarks,
  widthPx: video.videoWidth,
  heightPx: video.videoHeight,
  sourceId: activeVideoTrack.id,
  timestampMs: capturedAtMs,
};
calibration = advanceCalibration(calibration, frame);
const current = extractFrontalMeasurement(frame);
```

- `capturedAtMs`는 해당 영상 프레임을 추론에 전달할 때의 단조 증가 시간입니다. 같은 프레임을 여러 번 새 표본으로 세지 않습니다. `performance.now()`를 사용할 수 있으며 서버의 날짜·시각을 의미하는 값은 아닙니다. 서버 저장 시 세션의 UTC 시작 시각은 별도로 관리합니다.
- `phase`는 `collecting` 또는 `ready`, `progress`는 0–1입니다. `reason`은 다시 수집하는 이유입니다. `reference`에는 스키마 버전, 카메라 스트림 ID, 영상 크기, 수집 시각·표본 수, 중앙값 지표가 있습니다.
- 가시성이 낮아진 **측정 중** 상태와 이미 저장된 기준값은 구분합니다. `ready` 상태에서는 기준값이 유지되므로, 실시간 관측의 유효성은 반드시 `extractFrontalMeasurement()`로 별도 확인해야 합니다.
- 콜백이 더 이상 오지 않는 스트림 종료·권한 철회·화면 이탈은 UI/카메라 계층에서 처리해야 합니다. 모듈 자체는 타이머나 카메라를 소유하지 않습니다.
- React 리렌더 때문에 수집기를 다시 만들지 않습니다. 세션 단위 `useRef` 또는 reducer에 보관하고, 화면 이탈 시 카메라·추론 작업을 정리합니다.
- CSS 미러링은 미리보기 표현에만 적용합니다. 코의 화면 오른쪽 이동과 사용자가 보는 오른쪽을 설명할 때는 미러링 여부를 고려합니다.
- 키보드 손캠은 별도 입력입니다. 키보드 평면 매핑과 손가락 판정에 이 상체 기준값을 재사용하지 않습니다.

## 검증 범위와 다음 작업

Node 24에서 `node --test front/tests/calibration.test.mjs`로 순수 계산·상태 전이를 검증합니다. 영상 비율 보정, 시간과 표본 수, 중앙값, 누락·불확실 좌표, 갑작스러운 이동과 느린 이동, 표본 사이의 이동, 카메라 변경·시간 역행, 기준값 고정, 입력 불변성을 포함합니다.

이 테스트는 실제 웹캠 인식률을 검증하지 않습니다. 다음 단계는 팀의 Windows 노트북/웹캠에서 착석 거리·해상도·조명·고개 회전·카메라 이동·일시 가림을 재현하고, 기준 자세 수집 완료율과 재시작 이유를 확인하는 것입니다. 이후 자세 변화 지표와 별도의 작업 습관 지표를 정의하고, 그 검증 자료를 바탕으로 점수·알림 규칙을 추가합니다.
