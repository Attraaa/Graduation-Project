# 세션별 기준 자세 캘리브레이션

대상 구현: [calibration.ts](../front/src/features/posture/calibration.ts). 검증: [calibration.test.mjs](../front/tests/calibration.test.mjs). 기준 확보 후 비교와 시간 계산은 [observation.ts](../front/src/features/posture/observation.ts), 검증 결과는 [evaluation.md](evaluation.md)를 따릅니다. 이 문서는 기준값 수집 계약을 설명합니다. 화면·API 연결 여부는 [architecture.md](architecture.md)를 함께 확인합니다.

## 무엇을 수집하는가

사용자가 매번 측정을 시작할 때 기준으로 삼을 자세를 정하고, 카메라에서 안정적으로 관측한 값의 중앙값을 저장합니다. 카메라 위치와 사용자의 착석 위치가 세션마다 달라질 수 있어 새 세션은 새 기준값으로 시작합니다. 자동으로 기준값을 계속 갱신하면 서서히 바뀐 자세가 새 기준으로 흡수되므로, 완료된 기준값은 고정합니다.

MediaPipe는 신체 랜드마크의 이미지 좌표와 모델이 추론한 3차원 좌표를 제공합니다. 이미지 `x`는 너비, `y`는 높이로 각각 정규화하며 `visibility`는 랜드마크 가시성의 추정값입니다. 따라서 가로·세로 비율이 다른 화면에서 정규화된 두 좌표를 그대로 같은 길이 단위로 계산하면 안 됩니다. [Google MediaPipe Web 공식 문서](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

현재 모듈은 정면 상체 화면의 양 귀와 양 어깨 좌표를 픽셀로 환산하고 다음 값을 구합니다. 분모인 어깨 너비는 **화면에 투영된 양 어깨 사이 픽셀 거리**이며 실제 신체 길이가 아닙니다.

| 필드 | 의미와 단위 |
| --- | --- |
| `earOffsetShoulderWidths` | 어깨 중점 대비 귀 중점의 화면 오른쪽 이동량 / 어깨 너비. 무차원 비율 |
| `earHeightShoulderWidths` | 어깨 중점보다 귀 중점이 화면 위에 있는 높이 / 어깨 너비. 무차원 비율 |
| `shoulderHeightDifferenceShoulderWidths` | 해부학적 왼쪽 어깨 y − 오른쪽 어깨 y / 어깨 너비. 화면 아래쪽이 양수 |

**설계상 해석 한계:** 이 비율은 기준 자세 대비 화면상 변화량입니다. 정면 2차원 관측으로 실제 목의 전방 이동량이나 해부학적 거북목 각도를 확정할 수 없다는 판단에 따라, 이 모듈은 거북목 여부·정상 여부·100점 환산을 반환하지 않습니다. 고개 회전, 카메라 기울기, 사용자와 카메라 사이 거리도 관측값에 영향을 줄 수 있습니다. 이 해석은 좌표 계약에 근거한 설계상의 추론이며, 제품의 정확도를 검증한 결과가 아닙니다.

기존 Pose 문서의 품질 평가 조건은 2–4m 거리의 한 사람과 Yoga/Dance/HIIT 데이터입니다. 이를 가까운 노트북 웹캠 구도의 성능 보장으로 취급하지 않습니다. 실제 사용할 구도의 검증 영상을 별도로 확보해야 합니다. [MediaPipe 저장소의 Pose 평가 설명](https://github.com/google-ai-edge/mediapipe/blob/master/docs/solutions/pose.md#pose-estimation-quality)

## 수집 흐름과 임시 설정

1. 얼굴과 양 어깨가 보이는 미리보기와 기준 자세 안내를 표시합니다. 사용자에게 기준으로 삼을 자세를 정하고 잠시 유지하도록 안내한 후 수집을 시작합니다.
2. 유효한 관측이 연속으로 쌓이는 동안 진행률을 표시합니다. 랜드마크 누락·낮은 가시성·화면 이탈은 이전 수집분을 지웁니다. 관측 실패를 정상 또는 0으로 기록하지 않습니다.
3. 전체 수집 구간의 변화 폭을 확인합니다. 한 프레임씩 조금 움직이는 느린 이동도 누적 변화가 커지면 다시 수집합니다. 저장 간격 사이에 들어온 프레임도 움직임 검사를 합니다.
4. 시간과 표본 수 조건을 모두 충족하면 지표별 중앙값을 기준으로 확정합니다. 작은 허용 범위 내 일시적인 좌표 튐이 평균값을 끌어당기는 영향을 줄이기 위한 선택입니다.
5. 새 세션, 명시적인 재수집, 카메라 재배치 후에는 새로 수집합니다. 화면 이동이나 다른 모드의 실행은 현재 기준을 유지합니다. 카메라 스트림 ID 또는 영상 크기가 바뀐 경우는 코드가 자동으로 무효화합니다. 같은 스트림으로 카메라를 물리적으로 옮긴 사실은 확정할 수 없으므로 카메라 설정 창의 **기준 다시 잡기**로 다시 수집합니다.

아래 값은 `DEFAULT_CALIBRATION_OPTIONS`에 모여 있는 **수집용 임시 설정**입니다. 정확도·건강·자세 점수의 기준이 아니며, 실제 웹캠 검증 결과로 조정합니다. 한 수집 과정 중에는 설정을 바꾸지 않습니다.

| 설정 | 기본값 |
| --- | --- |
| 연속 수집 시간 | 3,000ms 이상 |
| 표본 수 | 20개 이상. 100ms 간격이면 일반적으로 31개 |
| 저장 표본 사이 최소 간격 | 100ms |
| 표본 공백 허용 | 500ms까지. 초과 시 재시작 |
| 각 필수 랜드마크 가시성 | 0.7 이상 |
| 양 어깨의 수평 간격 | 영상 너비의 0.1 이상 |
| 지표별 전체 수집 구간 변화 폭 | 어깨 너비 대비 0.08 이하 |
| 어깨 중점 x/y 변화 폭 | 각각 영상 너비/높이 대비 0.025 이하 |
| 어깨 너비 변화 폭 | 영상 너비 대비 0.025 이하 |

안정적인 관측이라는 사실만으로 사용자의 자세가 올바르다고 판정하지 않습니다. UI 완료 문구도 “기준 자세 저장 완료”로 표현합니다. 자세 점수와 작업 습관 지표는 분리하기로 했지만, 기준값을 점수로 환산하는 공식과 지속시간 조건은 이 모듈에 포함하지 않습니다.

2026-10-02 기준 스키마 v2로 변경했습니다. 귀 수평 폭 `baseEarSpanPx`, 어깨 거리 `baseShoulderSpanPx`, 귀 중점과 어깨 중점의 수직 간격 `baseEarHeightPx`를 각각 중앙값으로 저장합니다. 양 귀·코·양어깨 모두 가시성 조건을 통과해야 하며 귀 수평 폭은 영상 너비의 2% 이상이어야 합니다. 코는 고개 회전 방어에만 사용합니다. 기준 수집 중 yawRatio가 0.15를 초과하면 정면 안내와 함께 수집을 다시 시작합니다. 귀 폭 변화도 영상 너비 대비 2.5% 이내여야 합니다. 준비 완료 후에도 yaw가 0.15를 초과하면 목·어깨 관측을 보류하고 관찰 연속성을 끊습니다. 수집한 기준은 유지하며 정면 복귀 첫 프레임은 시간을 더하지 않습니다. 목은 귀-어깨 간격 감소, 어깨는 간격 변화의 절댓값을 사용합니다. 기준 스키마와 수집 규칙은 유지하며 v3 점수·보호 정책은 [evaluation.md](evaluation.md)를 따릅니다.

## 연결 계약

```ts
// 매 세션과 명시적인 재설정 시에 생성합니다.
let calibration = createCalibration();

// 새 영상 프레임에 대한 MediaPipe 결과마다 호출합니다.
const frame = {
  landmarks: results.poseLandmarks,
  widthPx: video.videoWidth,
  heightPx: video.videoHeight,
  sourceId: `${activeVideoTrack.id}:${cameraTransformGeneration}`,
  timestampMs: capturedAtMs,
};
calibration = advanceCalibration(calibration, frame);
const current = extractFrontalMeasurement(frame);
```

- `capturedAtMs`는 해당 영상 프레임을 추론에 전달할 때의 단조 증가 시간입니다. 같은 프레임을 여러 번 새 표본으로 세지 않습니다. `performance.now()`를 사용할 수 있으며 서버의 날짜·시각을 의미하는 값은 아닙니다. 서버 저장 시 세션의 UTC 시작 시각은 별도로 관리합니다.
- `phase`는 `collecting` 또는 `ready`, `progress`는 0–1입니다. `reason`은 다시 수집하는 이유입니다. `reference`에는 스키마 버전, 카메라 스트림 ID, 영상 크기, 수집 시각·표본 수, 중앙값 지표가 있습니다.
- 가시성이 낮아진 **측정 중** 상태와 이미 저장된 기준값은 구분합니다. `ready` 상태에서는 기준값이 유지되므로, 실시간 관측의 유효성은 반드시 `extractFrontalMeasurement()`로 별도 확인해야 합니다.
- 콜백이 더 이상 오지 않는 스트림 종료·권한 철회·화면 이탈은 UI/카메라 계층에서 처리해야 합니다. 모듈 자체는 타이머나 카메라를 소유하지 않습니다.
- React 리렌더 때문에 수집기를 다시 만들지 않습니다. 공통 모니터링 런타임에 보관하고 페이지 이동 중에는 유지합니다. 일시정지는 관측 연속성을 끊고 기준/평균을 보존하며, 아직 수집 중인 기준은 재개 후 다시 수집합니다. 해당 모드 중지나 앱 영역 이탈 시 카메라·추론 작업을 정리합니다.
- 공통 카메라 설정의 영상 반전·회전·필터·확대·이동을 적용한 같은 캔버스를 미리보기와 추론에 사용합니다. 상체의 기본 좌우 반전은 이전 셀프 미리보기 방향을 유지합니다. `sourceId`는 트랙 ID와 설정 세대를 포함하며 영상 구도가 바뀌면 기준을 다시 수집합니다. 픽셀/정규화 단위, 기준 스키마 v2, 점수/습관 v3 산식은 유지합니다. [카메라 설정 계약](camera-settings.md)을 따릅니다.
- 키보드 손캠은 별도 입력입니다. 키보드 평면 매핑과 손가락 판정에 이 상체 기준값을 재사용하지 않습니다.

## 거북목 모델 E19 보정 (2026-11-23)

2026-11-23부터 목 점수는 연구에서 고른 거북목 모델 E19(패키지 `20261117_ensemble_v1`, `front/public/models/fhp-e19`)가 계산합니다. 구현은 `features/posture/e19/`(`model.ts` 보정·추론, `flow.ts` 순서·필터, `frame.ts` 입력 만들기), 연결은 `PostureMonitor.tsx`, 검증은 `e19-runtime.test.mjs`·`fhp-e19-parity.test.mjs`입니다. 보정·품질 숫자는 패키지 `config.json`을 그대로 읽으며 바꾸지 않습니다.

- **순서:** 측정 시작, 카메라 설정 창의 **기준 다시 잡기**, 카메라 구도·해상도 변경 때 3초 준비("편하게 바르게 앉아 화면 가운데를 보세요") → 5초 기록(포즈 결과가 있는 프레임을 약 100ms 간격, 약 50장) → 보정 계산. 연구의 실시간 비교 도구와 같은 순서입니다.
- **자세:** 편하게 바르게 앉은 자세(머리를 일부러 뒤로 당기지 않음). 이 자세가 목 점수 100점이고 화면 추정 CVA는 기준 CVA(기본 50°, 설정에서 40–60°)입니다.
- **E19 보정:** 얼굴·어깨가 보이는 프레임의 크기 단서 중앙값과 원소별 중앙값 랜드마크(포즈 0–12번, 얼굴 478점, 머리 행렬)를 기준으로 삼고, 같은 프레임의 목 Δ·부하·고개 각도 중앙값을 오프셋으로 뺍니다. 곱하는 보정은 없습니다. 보정 전에는 목 점수를 만들지 않으므로 대체 모델(`fallback.onnx`)은 넣지 않았습니다.
- **어깨 기준:** 위의 `calibration.ts` 규칙(3초 이상 연속 안정 구간의 중앙값)을 같은 5초 프레임에만 적용합니다. 두 기준이 모두 성공해야 관찰을 시작합니다.

| 실패 이유 | 조건(config.json) | 카메라 화면 아래 띠의 안내 |
| --- | --- | --- |
| `too_few_frames` | 포즈 검사(코·눈·귀·어깨 가시성 0.5)와 얼굴이 맞는 프레임이 80 % 미만 | 얼굴과 양쪽 어깨가 화면 안에 보이게 앉아 주세요. |
| `unstable` | 목 Δ 표준편차 3° 초과 | 5초 동안 움직임이 있었어요. 움직이지 말고 그대로 계세요. |
| `not_upright` | 고개 각도(숙임·들기) 중앙값 12° 초과 | 고개를 들어 화면 가운데를 봐 주세요. |

실패하면 이유를 3초 보여 준 뒤 3초 준비부터 자동으로 다시 하며, 그동안 목·어깨 점수는 `—`입니다. 어깨 기준이 5초 안에 잡히지 않으면 `calibration.ts`의 마지막 재수집 이유를 위 세 안내 중 하나로 보여 줍니다(움직임 → `unstable`, 고개 회전 → `not_upright`, 그 밖 → `too_few_frames`).

- **입력:** 앱이 분석하는 변환 캔버스(반전·회전·확대 반영) 기준의 레거시 Pose 0–12번 `[x, y, z, visibility]`와 FaceLandmarker 결과입니다. `EyeMonitor`가 같은 캔버스의 얼굴 결과를 캡처 시각·영상 시각과 함께 넘기고, 같은 영상 프레임이 없으면 70ms 이내에서 가장 가까운 결과를 씁니다. 얼굴이 여럿이면 얼굴 1번 점(코끝)이 포즈 코와 가장 가까운 얼굴을 씁니다. MediaPipe 버전·옵션은 학습 때와 같고, FaceLandmarker에 `outputFacialTransformationMatrixes: true`만 더했습니다(랜드마크·깜빡임 계산은 그대로).
- **측정 중:** 기존 관측 조건(가시성 0.7, 고개 회전 비율 0.15)을 통과한 프레임에서만 초당 약 10회 E19를 돌리고, E19 자체 검사(고개 좌우 35° 초과)도 적용합니다. 영상·랜드마크는 저장하지 않습니다.
- **일치 시험 자료:** `fixtures/parity`에는 학습 참가자 얼굴 랜드마크가 있어 `front/tests/fixtures/fhp-e19-parity/`(Git 제외) 또는 `FHP_PARITY_DIR`에 두고, 없는 PC에서는 그 시험만 건너뜁니다. 모델 파일의 SHA-256 확인은 항상 실행합니다.
- **한계:** 추정 CVA는 목 기준(몸통 기울기를 빼도록 학습한 값)이라 임상 CVA보다 덜 내려가고, 목 점수(부하)는 몸통 숙임도 포함하므로 두 값이 다르게 움직일 수 있습니다. 연구에서 평소 자세로 보정했을 때 부하 오차가 컸습니다(학습에 안 쓴 사람 사진 L′ 29.3 %). 카메라 위치·거리·화면 각도가 바뀌면 다시 보정해야 하며, 진단이나 임상 측정이 아닙니다.
