## 7. 데이터 흐름과 계산 규칙

### 7.1 불러오기

네 곳을 동시에 부른다. `owner`는 로그인 사용자이고, 서버는 토큰으로 권한을 판단한다.

| 데이터 | 호출 | 범위 |
| --- | --- | --- |
| 상체 통계 | `statistics({ owner, from, to })` (mode 없이 불러서 목·어깨 모두) | 6일 전 ~ 오늘 |
| 안구 통계 | `eyeStatistics({ owner, from, to })` | 6일 전 ~ 오늘 |
| 키보드 기록 | `keyboardStatistics({ owner, from, to })` | 6일 전 ~ 오늘 |
| 오늘 이력 | `history({ owner, from: 오늘, to: 오늘, offset })`. `hasMore`가 참이면 `offset`을 늘려 이어서 부른다. | 오늘 |

날짜 키는 기존 통계와 같이 `todayDateKey()`와 `localDateKey`를 쓴다(기록에 저장된 그 지역의 날짜).

### 7.2 정책 묶음 선택 (서로 다른 정책은 섞지 않는다)

- **상체:** 목·어깨 각각 `statisticsKey`(모드, 점수 정책, 관찰 정책)로 묶는다. 범위 안에서 날짜와 시간이 가장 늦은 행이 속한 묶음만 쓴다.
- **안구:** `policyVersion`으로 묶고, 같은 방식으로 고른다.
- **키보드:** `[policyVersion, recognitionVersion, nearbyCredit]`으로 묶는다(키보드 통계 화면과 같은 기준). `updatedAt`이 가장 늦은 기록의 묶음만 쓴다.
- 대시보드의 모든 숫자(카드, 그래프, 상자, 타임라인, 이탈 시간대)는 고른 묶음만 쓴다. 다른 정책 기록은 통계·학습이력 화면에서 볼 수 있다.

### 7.3 날짜별 값 (d = 7일 중 하루)

- **목/어깨 점수(d):** 그날 행 합계의 `averageScore`. 유효 관찰이 0이면 `null`이다.
- **상체 세션 수(d):** 그날 행의 `recordIds`에서 `:turtle`과 `:shoulder` 꼬리를 뗀 서로 다른 세션 id의 수. 상체 세션은 `${sessionId}:turtle`, `${sessionId}:shoulder` 두 기록으로 저장된다.
- **상체 시간(d):** `max(목 runMs 합, 어깨 runMs 합)`. 같은 세션을 두 번 세지 않는다.
- **키보드(d):**
  - 점수와 판정 가능 비율: 그날 `date`인 counts로 `keyboardSummary(counts, nearbyCredit)`를 구해 `.score`와 `.coverage`를 쓴다.
  - 세션 수: 시작일(`localDateKey(startedAt, offsetMinutes)`)이 d인 기록의 수
  - 시간: 그 기록들의 `updatedAt − startedAt` 합
- **안구(d):**
  - 깜빡임 빈도: 그날 행 합계의 `eyeRate`. 유효 관찰이 30초 미만이면 `null`이고 "자료 부족"으로 표시한다.
  - 시간은 `runMs` 합, 휴식은 `breaks` 합이다.
  - 세션 수는 표시하지 않는다. 시간대별 행으로는 정확히 셀 수 없기 때문이다.
- **총 관찰(d):** 상체 시간 + 키보드 시간 + 안구 시간
- **상자와 점:** d에 세 모드 중 하나라도 값이 있으면 상자가 뜬다. 점은 점수가 있는 모드에만 찍힌다. 안구만 있는 날은 점 없이 상자만 뜬다.

### 7.4 모드 카드 (오늘 값)

- **상체:** 오늘 목·어깨 점수, 오늘 시간, 기준 이탈 횟수(오늘 목과 어깨의 `deviationEpisodeCount` 합), 7일 목·어깨 점수 추이선
- **키보드:** 오늘 점수, 오늘 시간, 판정 가능 %, 7일 점수 추이선
- **안구:** 오늘 깜빡임 빈도, 오늘 시간, 휴식 횟수, 7일 깜빡임 빈도 추이선
- 오늘 값이 없으면 고리를 비우고 "오늘 기록 없음"을 보여준다. 범위 안에 기록이 하나도 없으면 "아직 기록 없음"을 보여준다.

### 7.5 7일 그래프

- 목, 어깨, 키보드 세 계열을 그린다. 값이 없는 날은 건너뛰고 앞뒤 점을 잇는다(recharts `connectNulls`).
- 점은 값이 있는 날에만 그린다.
- y축 위쪽은 100이고, 아래쪽은 가장 낮은 점수에 맞춰 10 단위로 내린다.
- 통계 화면의 시간대 그래프는 빈 시간을 잇지 않는다(`connectNulls={false}`). 대시보드 7일 그래프가 빈 날을 잇는 것은 사용자 결정에 따른 의도된 차이다. 빈 날에는 점이 없어서 0점과는 구분된다.

### 7.6 오늘 타임라인

- 오늘 이력의 상체 기록(같은 세션 id끼리 한 줄로 묶음)과 안구 기록, 그리고 오늘 시작한 키보드 기록을 시작 시각 순으로 보여준다.
- 각 줄에는 모드, 시작–끝, 길이, 값을 보여준다.
  - 시작–끝: `startedAt`부터 `startedAt + runMs`까지. 키보드는 `updatedAt`까지다.
  - 값: 상체는 목·어깨 `averageScore`, 키보드는 점수, 안구는 깜빡임 빈도
- `status`가 `interrupted`인 기록에는 "중단됨"을 붙인다.

### 7.7 기준 이탈이 잦은 시간

- 7일치 상체 행(고른 묶음)의 시간대별 `deviationEpisodeCount` 합(목+어깨)을 막대로 그린다.
- 상체 기록이 있는 가장 이른 시간대부터 가장 늦은 시간대까지만 그린다.
- 최댓값의 75% 이상인 막대는 진한 색으로 표시한다.

## 8. 상태 처리

- 출처 4개(상체 통계, 안구 통계, 키보드 기록, 오늘 이력)마다 불러오는 중/실패/완료 상태를 따로 둔다.
- **불러오는 중:** 해당 영역에 회색 틀을 보여준다.
- **실패:** 해당 영역에만 "기록을 불러오지 못했어요"와 "다시 시도" 버튼을 보여준다. 다시 시도하면 네 곳을 모두 다시 부른다. 나머지 영역은 정상으로 보인다.
  - 상체 통계 실패: 상체 카드, 목·어깨 선, 이탈 시간대
  - 키보드 실패: 키보드 카드, 키보드 선, 타임라인의 키보드 줄
  - 안구 실패: 안구 카드, 상자의 안구 줄
  - 오늘 이력 실패: 타임라인의 상체·안구 줄
  - 그래프는 상체나 키보드 중 하나라도 있으면 그리고, 실패한 쪽은 안내 한 줄을 붙인다.
- **재생 버튼:** 데이터 상태와 상관없이 항상 동작한다. 측정 시작에는 서버가 필요 없고, 저장 실패 안내는 측정 화면이 이미 한다.
- **빈 상태 문구:**
  - 그래프: "측정을 시작하면 최근 7일 점수가 여기에 보여요"
  - 타임라인: "오늘 측정한 기록이 없어요"
  - 이탈 시간대: "상체 기록이 쌓이면 보여요"
- **로그인 문제:** 토큰이 없거나 만료되면 기존 API 오류 처리대로 실패 상태로 보인다. 로그인 확인 추가(TC-AUT-07)는 이번 범위 밖이다.

## 9. 테스트와 확인

### 9.1 자동 테스트 (`front/tests/dashboard-summary.test.mjs`, `node --test`, 가짜 데이터)

- 목/어깨 점수는 유효 시간 가중 평균이고, 유효 관찰이 0이면 `null`이다.
- 서로 다른 정책 묶음이 섞이지 않고 최신 묶음만 쓰인다(상체, 안구, 키보드 각각).
- 기록이 없는 날은 `null`이고(0이 아님), 그날은 상자가 없다.
- 안구 유효 관찰이 30초 미만이면 `null`이다.
- 같은 세션의 목·어깨 기록은 세션 1개로 세고, 시간도 한 번만 더한다.
- 키보드 점수와 판정 가능 비율이 `keyboardSummary`와 같고, 세션과 시간은 시작일 기준이다.
- 이탈 시간대 합계와 표시 범위가 맞다.
- 7일 날짜 키가 맞다(월·연 경계 포함).
- 타임라인 정렬, 상체 세션 묶기, "중단됨" 표시가 맞다.

### 9.2 기존 검사

- `moti.cmd check`(타입, 린트)와 `npm test` 전체가 통과해야 한다.

### 9.3 실제 앱 확인

- 사용자 계정으로 로그인해서 밝은/다크 테마와 창 폭 1280+, 1100, 800에서 화면을 캡처한다.
- 오늘 목·어깨 점수가 통계 화면의 오늘 값과 같은지, 타임라인이 학습이력과 같은지 대조한다.

### 9.4 DB 안전

- 배포 DB(`moti_demo`)에는 테스트 기록을 쓰지 않는다. 화면 확인은 이미 있는 기록으로만 한다.

## 10. 남는 점과 후속 작업

- 다른 화면은 이번에 예전 모양(입체 버튼 등)을 유지해서 잠시 모양이 섞여 보인다. 다음 차례 후보는 통계 → 학습이력 → 설정·로그인 → 측정 화면(팀원 조율 필요) 순이다.
