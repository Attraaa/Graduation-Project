## 1. 목적

- **통계:** 같은 크기 카드 9개, 개발 용어, 점수 정책 버전 문자열 때문에 흐름이 한눈에 안 들어온다. 대시보드와 같은 데이터 위젯 스타일로 바꿔서 기간 흐름을 바로 보이게 한다.
- **학습이력:** 새 통계와 자연스럽게 이어지게 한다. 날짜로 바로 이동할 수 있고, 기록 단위와 모양이 같아야 한다.

| 안구 용어 | **바꾸지 않는다.** 깜빡임 빈도, 유효 관찰 시간, 실행 시간, 눈 휴식 완료, 가까워짐 안내, 깜빡임 안내를 그대로 쓴다. |

| 기록 없는 날 | 지난 날짜는 흐리게 보이지만 고를 수 있다. 고르면 "이 날은 측정 기록이 없어요"와 앞뒤 기록 날짜로 가는 버튼을 보여준다. 오늘 기록이 없으면 "오늘은 아직 측정하지 않았어요", 상체·키보드·안구 측정 시작 버튼, 가장 최근 기록 링크를 보여준다. 미래 날짜는 점선으로 보이고 고를 수 없으며, 미래 주로 넘기는 ▶도 비활성이다. |

## 3. 팀 논의 항목과 추가 결정 (사용자, 2026-10-07)

초안에서 팀 논의로 미뤘던 다섯 항목:

| 항목 | 결정 |
| --- | --- |
| 1. 구현 방식 | **섞어서.** 상체·안구 통계와 학습이력은 대시보드 계산 함수를 넓혀 같이 쓴다. 키보드 통계는 계산 코드를 그대로 두고 모양만 바꾼다. |
| 2. 팀원 파일 수정 범위 | 꼭 필요한 세 파일만 고친다. `pages/Statistics.tsx`와 `pages/LearningHistory.tsx`는 새 화면으로 다시 짜고, `features/keyboard/KeyboardStatistics.tsx`는 모양을 바꾸고 데이터를 페이지에서 받으며 세션 목록을 뺀다. 상체 `StatisticsData.tsx`, 안구 `EyeStatistics.tsx`와 `EyeStatisticsData`는 고치지 않고 쓰지 않는 채로 남긴다(되돌리기용). |
| 3. 키보드 세션 목록 | 학습이력으로 옮긴다. 통계 키보드 탭에는 "측정 기록은 학습이력에서 보기 →" 링크만 남긴다. |
| 4. 상체 용어 변경 | 새 화면에만 쉬운 말을 쓴다. 옛 컴포넌트와 그 테스트(`record-ui.test.mjs`), `docs/evaluation.md`는 그대로 두고 9절 대응표로 잇는다. |
| 5. 학습이력 일간 보기 | 뺀다. 주간·월간만 둔다. |

함께 정한 것:

| 항목 | 결정 |
| --- | --- |
| 안구 측정 횟수 | 보여주지 않는다. 서버 안구 통계는 시간대별로만 묶여 있어 횟수를 정확히 셀 수 없다(대시보드와 같은 이유). 대신 실행 시간을 보여준다. |
| 가장 긴 측정 | "가장 길게 이어진 측정"으로 바꾼다. 기존 화면의 "최장 연속 관찰"(`longestContinuousMs`) 값이다. 측정 한 번의 전체 길이는 서버 통계로 정확히 구할 수 없다. |
| 기간 버튼 | "7일 / 30일"로 쓴다. 학습이력에서 지난 날짜로 넘어오면 "최근"이 맞지 않기 때문이다. 끝 날짜가 오늘이 아니면 "오늘까지 보기" 버튼을 보여준다. |
| 학습이력 불러오는 범위 | 보이는 주(또는 달)의 앞뒤 1주까지 불러온다. 달력·목록·앞뒤 기록 버튼을 모두 같은 데이터에서 "측정을 시작한 날" 기준으로 계산해서 서로 어긋나지 않게 한다. 앞뒤 기록이 이 범위 밖이면 버튼을 숨긴다. |
| 이전 기준 | 지금 앱이 쓰는 점수 기준과 다른 기준으로 측정한 기록이다. 안내 문구는 "지금과 다른 점수 기준으로 측정한 기록이에요. 지금 기준 기록과 합쳐서 계산하지 않아요."로 한다. |
| 측정 품질 고리 | 대시보드 `ScoreRing`에 단위(%) 선택을 더해서 다시 쓴다. 대시보드 표시는 그대로다. |
| 대시보드 부품 위치 | `DayDetail`, `ScoreRing`, `format.ts`는 옮기지 않고 지금 자리에서 가져다 쓴다. 대시보드 설계 6절의 "공용 폴더로 옮긴다"를 바꾼 것이다. main에 반영된 대시보드 파일을 덜 흔들기 위해서다. |
| 저장 실패 안내 | 기존 `RecordingStatus`는 저장에 실패했을 때만 통계 제목 아래에 보여준다. 평소 문구("측정한 기록은 서버에 저장됩니다.")는 부제와 겹쳐서 숨긴다. |

## 4. 화면 상세

### 4.1 통계 공통

- 제목은 "통계", 부제는 "서버에 저장된 내 측정 기록이에요 · 9월 30일 ~ 10월 6일"처럼 보여주는 기간을 적는다.
- 오른쪽 위에 기간 버튼 "7일 / 30일"을 둔다. 끝 날짜가 오늘이 아니면 옆에 "오늘까지 보기" 버튼을 둔다.
- 모드 탭은 상체 · 키보드 · 안구 순서다(대시보드와 같은 순서). 탭에는 모드 색 점을 붙이고, 고른 탭은 어두운 칸으로 표시한다.
- 직전 기간 비교 칩
  - 상체: "직전 7일보다 +3"처럼 보여준다. 올랐으면 초록, 같거나 내렸으면 회색이다.
  - 키보드: 같은 모양이고, 숫자는 기존 계산(소수 첫째 자리 차이)을 그대로 쓴다.
  - 안구: 점수가 아니라서 회색 칩에 "직전 7일 13회/분"처럼 값만 보여준다.
  - 어느 한쪽 기간에 값이 없으면 칩을 숨긴다.
- 날짜별 그래프
  - 기록 있는 날만 점을 찍고, 빈 날은 선이 이어서 지나간다(대시보드 규칙).
  - 그 탭 모드의 기록이 없는 날은 x축 날짜 글자를 흐리게 한다.
  - 마우스를 올리면 대시보드와 같은 날짜 상자(그날 기록한 모드만)에 "눌러서 학습이력 보기 →"를 붙여 보여준다. 누르면 학습이력의 그 날짜로 간다.
  - 30일 보기에서는 날짜 글자를 건너뛰어 겹치지 않게 한다.
- 화면 폭은 대시보드처럼 넓게(`max-w-7xl`) 쓴다.

### 4.2 상체 탭

- **숫자 4개:**
  - 목 평균 점수(직전 대비 칩)
  - 어깨 평균 점수(직전 대비 칩)
  - 측정 시간("7회 측정 · 가장 길게 이어진 측정 25분")
  - 기준에서 벗어남("벗어나 있던 시간 6%")
- **그래프:** 날짜별 목·어깨 점수
- **보조 카드:**
  - 시간대별 점수(기간 평균, 목·어깨 두 선)
  - 측정 품질(고리: 제대로 측정된 시간 %, "자리 비움 등으로 측정 못 한 시간 11분")
  - 측정 기록("7회 · 평균 19분", "가장 길게 이어진 측정 25분", "학습이력에서 보기 →")
- **문구:** "점수는 기준 자세와의 화면상 유사도예요. 의학적 진단이 아니에요."
- **맨 아래 오른쪽:** "AI 기능 예정 (예시)"를 접어 두고, 펼치면 `StatisticsExamples`를 보여준다.

### 4.3 키보드 탭 (용어와 문장은 기존 그대로)

- **숫자 4개:** 훈련 점수(직전 대비 칩), 기본표 일치율, 판정 가능 비율, 사용 일관성. 설명 줄은 지금 화면의 문장을 그대로 쓴다.
- **그래프 "연습 변화":** 훈련 점수(키보드 색 선)와 판정 가능 비율(회색 점선). 지금의 비교 문장과 주의 문장은 그래프 아래에 둔다.
- **보조 카드:**
  - 키별 히트맵(누르면 고른 키의 상황·손가락·판정 표를 아래에 보여준다. 지금 동작 그대로)
  - 기본표와 자주 다른 키, 그 아래 "측정 기록은 학습이력에서 보기 →"
  - 보류·제외 원인(접힘)
- 정책이 여러 개면 지금의 정책 선택을 그대로 둔다. 정책·인식 버전 줄은 탭 맨 아래 작은 글씨로 둔다.
- 세션 목록과 세션 상세는 학습이력으로 옮긴다.

### 4.4 안구 탭 (용어는 기존 그대로)

- **숫자 4개:**
  - 깜빡임 빈도(직전 기간 값은 회색 칩)
  - 유효 관찰 시간("실행 시간 2시간 40분")
  - 눈 휴식 완료("20초 후 복귀 버튼으로 본인이 확인한 횟수")
  - 가까워짐 안내("깜빡임 안내 5회")
- **그래프:** 날짜별 깜빡임 빈도. 지금의 날짜별 표를 대신한다.
- **보조 카드:** 시간대별 깜빡임(기간 평균), 유효 관찰 비율("얼굴 유실은 휴식으로 계산하지 않아요"), 측정 기록(실행 시간, "학습이력에서 보기 →")
- **문구:** "깜빡임 빈도는 생활 습관 안내용이에요. 건강 점수나 진단이 아니에요."

### 4.5 학습이력

- **위쪽:** 제목 "학습이력", 부제 "날짜를 고르면 그날 측정한 기록이 보여요". 오른쪽에 "이 날까지 7일 통계 →" 링크와 주간·월간 전환을 둔다.
- **달력 카드:**
  - "◀ 9월 27일 ~ 10월 3일 ▶"(월간은 "2026년 10월")와 모드 색 범례를 둔다.
  - 주는 일요일부터 시작한다.
  - 날짜 칸에는 "수 30", 모드 색 점, 그날 측정 시간을 보여준다.
  - 고른 날은 진한 테두리, 오늘은 "오늘" 표시를 붙인다.
- **기록 목록(왼쪽):**
  - 머리: "10월 2일 (금) 기록"과 "2회 · 38분"
  - 줄: 모드 색 막대와 값("상체 · 목 70 · 어깨 86", "키보드 · 66점", "안구 · 분당 14회"), 둘째 줄에 "10:05 – 10:23 (18분)". 키보드는 둘째 줄 끝에 "· 판정 가능 91%"를 붙인다.
  - 꼬리표: "중단됨", "기록 중", "이전 기준"
  - 이전 기준 기록이 있으면 맨 아래에 안내 문구(3절)를 둔다.
- **상세(오른쪽):**
  - 상체: "상체 · 10:05 – 10:23"과 상태(정상 종료, 중단됨, 기록 중), 숫자 4칸(목, 어깨, 기준에서 벗어남, 제대로 측정), 분별 점수 그래프(목·어깨 두 선, 빈 분은 잇지 않음)
  - 안구: 기존 `EyeDetailData`(분별 안구 관찰 표)를 그대로 쓴다.
  - 키보드: 지금 통계 화면의 세션 상세 문장(전체 횟수·점수·정책, 최근 집계 시각·상태, 보관 범위 안내)을 그대로 옮긴다.
- 날짜를 고르면 그날 첫 기록이 골라진 상태로 상세가 열린다.
- **기록 없는 날:** 2절 표대로 보여준다. 이때는 목록 카드가 가로 전체를 쓰고 상세는 없다.

### 4.6 지켜야 할 규칙

- 0점과 기록 없음을 구분한다. 기록이 없으면 "—"와 빈 안내를 보여준다.
- 서로 다른 점수 정책은 합치지 않는다. 통계는 모드별 최신 정책 묶음만 쓴다. 학습이력은 지금과 다른 정책의 기록에 "이전 기준" 표시를 붙인다.
- 의학적 진단이 아니라는 문구를 유지한다.
- 대시보드와 기록 단위를 맞춘다(상체 측정 한 번 = 목+어깨 한 줄).
- 기존 파일은 삭제하지 않는다.

## 6. 데이터 흐름과 계산 규칙

### 6.1 통계 불러오기

- 끝 날짜 E: 주소의 `end`가 올바른 날짜이고 오늘보다 늦지 않으면 그 값, 아니면 오늘(`todayDateKey()`)
- 기간 N: 주소의 `days`가 `30`이면 30, 아니면 7
- 처음 탭: 주소의 `mode`가 `upper`·`keyboard`·`eye` 중 하나면 그 탭, 아니면 상체
- 현재 기간 P = E에서 N−1일 전 ~ E. 직전 기간 Q = P 바로 앞의 N일
- 불러오는 범위는 Q의 첫날 ~ E(2N일)이다. 세 곳을 동시에 부르고, 탭을 바꿔도 다시 부르지 않는다.

| 데이터 | 호출 |
| --- | --- |
| 상체 통계 | `statistics({ owner, from, to })`(mode 없이 목·어깨 모두) |
| 안구 통계 | `eyeStatistics({ owner, from, to })` |
| 키보드 기록 | `keyboardStatistics({ owner, from, to })` |

### 6.2 통계 계산

- **정책 묶음:** 불러온 2N일 전체에서 대시보드 규칙(대시보드 설계 7.2절)대로 모드별 최신 묶음을 고른다. P와 Q 모두 같은 묶음만 쓴다.
- **날짜별 값과 날짜 상자:** P의 날짜마다 대시보드의 날짜별 값(목·어깨 점수, 키보드 점수·판정 가능 비율, 깜빡임 빈도, 모드별 시간)을 만든다.
- **상체 기간 요약:**
  - 목 평균 점수 = P의 목 행 합계의 `averageScore`(유효 시간 가중). 어깨도 같다. Q도 같은 방식이다.
  - 직전 대비 = 반올림한 P 값 − 반올림한 Q 값(화면에 보이는 정수끼리의 차이). 어느 한쪽이 없으면 비교하지 않는다.
  - 측정 시간 = P의 날짜마다 max(목 `runMs` 합, 어깨 `runMs` 합)을 더한 값(대시보드 규칙)
  - 측정 횟수 = P 행의 `recordIds`에서 `:turtle`·`:shoulder` 꼬리를 뗀 서로 다른 세션 수. 날짜를 넘긴 세션도 한 번만 센다.
  - 평균 길이 = 측정 시간 ÷ 측정 횟수
  - 가장 길게 이어진 측정 = P의 목·어깨 행 `longestContinuousMs` 중 최댓값
  - 기준에서 벗어남 = P의 목·어깨 `deviationEpisodeCount` 합
  - 벗어나 있던 시간 비율 = (목·어깨 `deviationMs` 합) ÷ (목·어깨 `validMs` 합)
  - 제대로 측정된 비율 r = (목·어깨 `validMs` 합) ÷ (목·어깨 `runMs` 합)
  - 측정 못 한 시간 = 측정 시간 × (1 − r)
  - 시간대별 점수 = 시간마다 P의 목(어깨) 행 합계의 `averageScore`. 상체 행이 있는 가장 이른 시간부터 가장 늦은 시간까지 그리고, 값이 없는 시간은 비운다.
  - 그래프 y축 아래쪽은 대시보드처럼 가장 낮은 점수에 맞춰 10 단위로 내린다. 시간대별 그래프도 시간대 값으로 같은 방식을 쓴다.
- **안구 기간 요약:**
  - 깜빡임 빈도 = P 행 합계의 `eyeRate`(유효 관찰 30초 미만이면 "자료 부족"). 직전 값은 Q 행 합계로 같은 방식으로 구한다.
  - 유효 관찰 시간, 실행 시간, 눈 휴식 완료, 가까워짐 안내, 깜빡임 안내 = P 행의 `validMs`, `runMs`, `breaks`, `nearReminders`, `openReminders` 합
  - 유효 관찰 비율 = `validMs` 합 ÷ `runMs` 합
  - 시간대별 깜빡임 = 시간마다 P 행 합계의 `eyeRate`. 안구 행이 있는 가장 이른 시간부터 가장 늦은 시간까지 그린다.
  - 그래프 y축은 0부터 max(20, 날짜별 최댓값을 5 단위로 올린 값)까지다.
- **키보드:** `KeyboardStatistics`가 지금처럼 계산한다(기간·정책 선택·히트맵·자주 다른 키·보류 원인). 페이지는 불러온 2N일 데이터와 E, N만 넘긴다.

### 6.3 학습이력 불러오기

- 고른 날짜 D: 주소의 `date`가 올바른 날짜이고 오늘보다 늦지 않으면 그 값, 아니면 오늘. 처음 보기는 주간이다.
- 보이는 날짜: 주간은 D가 속한 일요일~토요일, 월간은 D가 속한 달 전체
- 불러오는 범위: 보이는 첫날 7일 전 ~ min(보이는 마지막 날 7일 후, 오늘)
- 두 곳을 동시에 부른다. 범위가 바뀔 때(◀ ▶, 주간/월간 전환)만 다시 부르고, 범위 안에서 날짜만 고를 때는 다시 부르지 않는다.

| 데이터 | 호출 |
| --- | --- |
| 상체·안구 기록 | `history({ owner, from, to, offset })`. `hasMore`가 참이면 `offset`을 늘려 끝까지 이어서 부른다. |
| 키보드 기록 | `keyboardStatistics({ owner, from, to })` |

- 고른 기록의 상세는 따로 부른다. 상체는 `detail`(목·어깨 기록 id 각각), 안구는 `eyeDetail`, 키보드는 `keyboardDetail`이다.

### 6.4 학습이력 계산

- **날짜별 기록 줄:** 대시보드 타임라인을 넓힌 함수로 만든다. 시작일(`localDateKey(startedAt, offsetMinutes)`)이 그 날짜인 상체 기록(같은 세션 id끼리 한 줄), 안구 기록, 키보드 기록을 시작 순으로 놓는다. 학습이력에서는 정책으로 거르지 않는다.
  - 시작–끝: 상체는 세션 기록들의 가장 이른 시작부터 가장 늦은 끝(`startedAt + runMs`)까지, 안구는 `startedAt + runMs`까지, 키보드는 `updatedAt`까지다.
  - 값: 상체는 목·어깨 `averageScore`, 키보드는 `keyboardSummary(counts, nearbyCredit)`의 점수와 판정 가능 비율, 안구는 `eyeRate`다.
  - 꼬리표: `status`가 `interrupted`면 "중단됨", `running`이면 "기록 중", 6.5절에 해당하면 "이전 기준"
- **달력 칸:** 그 날짜 기록 줄의 모드(점)와 길이 합(측정 시간)이다. 목록과 같은 데이터라서 서로 어긋나지 않는다.
- **목록 머리:** 기록 줄 수와 길이 합("2회 · 38분")
- **앞뒤 기록:** 불러온 범위 안에서 D보다 앞인 가장 가까운 기록 날짜와 D보다 뒤이면서 오늘을 넘지 않는 가장 가까운 기록 날짜. 없으면 버튼을 숨긴다. 오늘에 기록이 없을 때 "가장 최근 기록"은 앞쪽 기록 날짜다.
- **◀ ▶ 이동:** 주간은 D를 7일, 월간은 한 달(그 달 1일) 옮긴다. 옮긴 날짜가 오늘보다 늦으면 오늘로 맞춘다. 다음 기간의 첫날이 오늘보다 늦으면 ▶를 비활성화한다.
- **상체 상세:**
  - 목·어깨 상세의 분 버킷을 분 단위로 합쳐 두 선을 그린다(각 분의 `averageScore`, 값이 없으면 비움).
  - 숫자 4칸은 목·어깨 점수, 두 기록 `deviationEpisodeCount` 합, (두 기록 `validMs` 합) ÷ (두 기록 `runMs` 합)이다.
  - 예전 기록처럼 목이나 어깨 하나만 있으면 없는 쪽은 "—"로 보여준다.
- **날짜 계산:** 대시보드처럼 `YYYY-MM-DD` 문자열을 UTC 기준으로 더하고 뺀다. 브라우저의 지역 시간으로 날짜를 만들지 않는다.

### 6.5 이전 기준

- 지금 앱이 새 기록에 쓰는 정책과 다르면 "이전 기준"이다.
  - 상체: 기록의 (`scorePolicyVersion`, `habitPolicyVersion`)이 지금의 (목 또는 어깨 점수 정책 버전, `HABIT_POLICY.version`)과 다르다. 세션의 목·어깨 중 하나라도 다르면 그 줄에 붙인다.
  - 안구: `policyVersion`이 `eyePolicy.version`과 다르다.
  - 키보드: `policyVersion`이 `ansi-qwerty-touch:2.0.0` 형식의 지금 값과 다르거나, `recognitionVersion`이 `RECOGNITION_VERSION`과 다르다.
- 통계는 최신 묶음만 쓰므로 서로 다른 기준을 합쳐서 계산하는 일이 없다. 안내 문구는 3절과 같다.

### 6.6 화면 사이 이동

- 통계 그래프에서 날짜를 누르면 `/history?date=그날짜`로 간다.
- 통계의 "학습이력에서 보기 →"는 `/history?date=E`로 간다.
- 학습이력의 "이 날까지 7일 통계 →"는 `/statistics?end=D&days=7&mode=고른 기록의 모드`로 간다. 고른 기록이 없으면 `mode`를 빼서 상체 탭으로 연다.
- 기록 없는 날의 측정 시작 버튼은 `/learn/upper_body`, `/learn/keyboard`, `/learn/eye`로 간다.

## 7. 상태 처리

- 불러오는 곳마다 불러오는 중/실패/완료 상태를 따로 둔다. 대시보드의 `SourceLoading`(회색 틀)과 `SourceError`("기록을 불러오지 못했어요"와 "다시 시도")를 다시 쓴다.
- **통계:**
  - 탭마다 그 모드의 출처 상태만 보여준다. 상체 탭은 상체 통계, 키보드 탭은 키보드 기록, 안구 탭은 안구 통계다.
  - 다시 시도하면 세 곳을 모두 다시 부른다.
  - 날짜 상자는 불러온 출처만으로 만든다. 실패한 출처는 빈 것으로 본다(대시보드와 같음).
  - 그 탭 모드의 기록이 P에 없으면 숫자 칸은 "—", 그래프 자리는 "이 기간에 측정한 기록이 없어요", 보조 카드는 "기록이 쌓이면 보여요"를 보여준다.
- **학습이력:**
  - 상체·안구 기록을 못 불러오면 달력과 목록 자리에 실패 안내를 보여준다. 키보드만 남은 화면은 "기록 없음"으로 잘못 보일 수 있어서다.
  - 키보드 기록만 못 불러오면 나머지는 그대로 보여주고, 달력 아래에 "키보드 기록을 불러오지 못했어요"와 "다시 시도"를 붙인다.
  - 상세를 못 불러오면 오른쪽 상세 자리에만 실패 안내를 보여준다.
- **로그인 문제:** 로그인 정보가 없으면 "로그인하면 이 계정의 기록을 볼 수 있어요."로 실패 상태가 된다(대시보드와 같음).

## 8. 테스트와 확인

### 8.1 계산 테스트 (`node --test`, 가짜 데이터)

- `statistics-period.test.mjs`
  - 7일·30일의 P·Q·불러오는 범위가 맞다(월·연 경계 포함).
  - 목·어깨 평균은 유효 시간 가중이고, 직전 대비는 보이는 정수끼리의 차이이며, 한쪽이 없으면 비교하지 않는다.
  - 다른 정책 묶음은 P와 Q 모두에서 섞이지 않는다.
  - 같은 세션의 목·어깨와 날짜를 넘긴 세션은 한 번만 센다. 측정 시간은 날짜별 max(목, 어깨)의 합이다.
  - 가장 길게 이어진 측정, 기준에서 벗어남 합계와 비율, 제대로 측정된 비율과 측정 못 한 시간이 맞다.
  - 시간대별 값은 기록 없는 시간이 `null`이고, 표시 범위가 첫 시간~마지막 시간이다.
  - 안구 깜빡임 빈도는 유효 관찰 30초 미만이면 `null`이고, 직전 값과 합계·비율이 맞다.
  - 0점인 날은 0이고, 기록 없는 날은 `null`이다.
- `history-calendar.test.mjs`
  - 주는 일요일부터 7일이고, 월은 그 달 전체와 앞 빈칸 수가 맞다.
  - 불러오는 범위는 앞뒤 7일이고 오늘을 넘지 않는다.
  - ◀ ▶ 이동이 오늘을 넘지 않고, 다음 기간이 미래면 ▶가 비활성이다.
  - 상체 세션은 한 줄이고, 키보드·안구 기록과 함께 시작 순으로 놓인다. "중단됨"과 "기록 중"이 맞다.
  - 달력 칸의 모드 점과 시간이 같은 날짜 기록 줄과 일치한다.
  - "이전 기준" 판단이 상체·안구·키보드 각각 맞다.
  - 앞뒤 기록 날짜를 범위 안에서 찾고, 없으면 `null`이다.
- `dashboard-summary.test.mjs`(기존): `summary.ts`를 넓힌 뒤에도 그대로 통과해야 한다.

### 8.2 화면 부품 테스트 (`stats-history-ui.test.mjs`, `renderToStaticMarkup`)

- 숫자 칸이 값 없음은 "—", 0은 0으로 보여주고, 비교 칩 문구("직전 7일보다 +3", 안구 "직전 7일 13회/분")가 맞다.

## 9. 용어 대응표 (새 화면 문구 ↔ 기존 화면·`docs/evaluation.md`)

| 새 화면 문구 | 기존 용어 | 값 |
| --- | --- | --- |
| 목·어깨 평균 점수 | 평균 기준 자세 유사도 | `averageScore` |
| 측정 시간 | 실행 시간 | `runMs` |
| 제대로 측정된 시간(비율) | 유효 관측 시간, 관측률 | `validMs`, `validMs ÷ runMs` |
| 측정 못 한 시간 | 미관측 시간 | `runMs − validMs` |
| 기준에서 벗어남 | 지속된 기준 이탈 | `deviationEpisodeCount` |
| 벗어나 있던 시간 비율 | 확정 후 기준 이탈 시간 ÷ 유효 관측 시간 | `deviationMs ÷ validMs` |
| 가장 길게 이어진 측정 | 최장 연속 관찰 | `longestContinuousMs` |
| 이전 기준 | 다른 점수·관찰 정책 버전 | `scorePolicyVersion`, `habitPolicyVersion`, `policyVersion` |

키보드와 안구 탭은 기존 용어를 그대로 쓰므로 대응표가 필요 없다.

## 10. 남는 점과 후속 작업

- 안구 측정 횟수와 측정 한 번의 전체 길이를 보여주려면 서버가 기록 단위 기간 요약을 돌려줘야 한다. 서버 변경과 배포가 필요해서 이번 범위에서 뺐다.
- 앞뒤 기록 버튼은 보이는 기간의 앞뒤 1주 안에서만 찾는다.
- AI 박스는 계속 예시이고 실제 데이터와 연결하지 않는다.
- 이 브랜치는 팀 합의 전 시도다. 팀이 원하지 않으면 브랜치째 되돌린다.
- 다음 차례 후보는 설정·로그인 → 측정 화면(팀원 조율 필요)이다.
