# 점수와 습관 평가 검증

단일 상체 모드의 **목·좌우 균형 독립 점수와 관찰 습관 집계**를 구현했습니다(2026-11-25에 어깨 점수를 좌우 균형으로 바꿈). 아래 수치는 개발용 제품 설정이며 실험으로 검증한 건강 기준이 아닙니다. 키보드 분석은 기존 독립 화면을 유지합니다.

## 점수 알고리즘

| 목 | 2026-11-23부터 거북목 모델 E19(아래 [목 점수 E19](#목-점수-e19-2026-11-23)). 이전 v3 가중합 `0.35 × headForward + 0.25 × torsoForward + 0.4 × neckSlump`은 제거 | `upper-body-neck-e19-v1-<해시>`(이전 `upper-body-neck-v3-<설정 해시>`) |

### 목 점수 E19 (2026-11-23)

사용자 결정(2026-11-21~23)으로 목 점수를 연구에서 고른 거북목 모델 E19로 바꿨습니다. 보정 계약은 [calibration.md](calibration.md#거북목-모델-e19-보정-2026-11-23)를 따릅니다.

- **목 점수** = 100 − 목 부하 점수. 목 부하 점수 = 100 × clip(부하 / 150 %, 0, 1)이고, 부하는 머리 무게중심이 C7보다 앞으로 나간 거리가 5초 보정 자세보다 늘어난 비율(몸통 숙임 포함)입니다. 100점 = 보정 자세와 같음.
- **시간 처리:** 연구 도구와 같은 One Euro 필터(minCutoff 0.5, beta 0.01, dCutoff 1.0, 초 단위)만 쓰고 보정할 때 초기화합니다. 움직임 동결·유예·복귀 확인 같은 보호 규칙은 없습니다. 시간 가중 평균·연속 관찰·저장은 좌우 균형과 같은 규칙(잰 결과 사이 500ms 이하만 이어 셈)입니다.
- **측정 조건:** 연구 도구처럼 E19 자체 검사(코·눈·귀·어깨 가시성 0.5, 고개 좌우 25°)만 따르고 안내 띠용 관측 조건(가시성 0.7·회전 비율 0.15)은 적용하지 않습니다. 고개 좌우 한도는 연구 패키지의 35°에서 앱만 25°로 낮췄습니다(사용자 결정, 재학습 없음). 좌우 균형도 같은 25° 한도를 쓰며, 목·좌우 균형 둘 다 못 잴 때만 관찰 일시 불가입니다.
- **화면 추정 CVA(부하 기준, 2026-11-24 변경)** = 기준 CVA − 환산(L′). L′ = One Euro를 거친 목 부하 점수 × 1.5 = (100 − 목 점수) × 1.5(0–150 %, 0보다 작으면 0)이고, 환산은 인계 패키지 `runtime/cva_map.json`(앱 `features/posture/e19/cva_map.json`, 숫자 변경 금지)의 목 부하 → CVA 감소 표를 선형 보간한 값입니다. 잰 각도가 아니라 **지금 목 부하가 보통 CVA 몇 도인 자세의 부하와 비슷한지**를 각도로 바꿔 보여 주는 참고값입니다. 목 점수와 같은 값에서 나오므로 둘은 늘 함께 움직이고, 목을 내밀지 않고 몸통만 숙여도 부하가 늘면 내려갑니다. 중력 기준인 실제 CVA도 몸통을 숙이면 내려갑니다(인계 문서 S01 몸통 숙이기 B2: 실제 36°, 부하 기준 38°). 기준 CVA는 설정에서 고르는 표시값(기본 50°, 40–60°)이라 저장하지 않으며 통계·학습이력에는 나오지 않습니다.
- **기준 이탈(습관):** 목 편차 = (100 − 화면의 정수 목 점수) / 200. 2026-11-25부터 기준은 설정 알림 카드의 상체 "N점 이하 N초 유지"와 같고(기본 70점 이하 3초면 1회, N + 10점 이상이면 끝), 좌우 균형도 같은 기준을 씁니다. 자세한 규칙은 [점수와 분리된 습관 정보](#점수와-분리된-습관-정보)를 따릅니다.
- **기록:** 서버·DB 변경 없이 기존 목(`turtle`) 기록에 새 정책 ID로 저장합니다. ID에는 모델 해시·부하 기준·필터·편차 환산·보정 순서·측정 조건(고개 25°)이 들어가 다른 정책 기록과 평균하지 않습니다. 습관 정책 ID는 2026-11-25부터 알림 설정을 담은 `alert-hold-v1:<점수>:<초>`입니다(그 전 `weighted-reference-deviation-v3`와 민감도 변형).
- **검증:** `fhp-e19-parity.test.mjs`가 앱 안의 `model.onnx`를 학습 때 기대값과 비교합니다(목 Δ < 0.05°, 부하 < 0.25 %; 2026-11-23 결과 300프레임 최대 차이 7.6e-6°·3.1e-5 %). `e19-runtime.test.mjs`가 보정 성공·실패 세 가지·얼굴 없음·고개 돌림(앱 25°)·보정 전, 보정 순서와 필터·목 관찰 시간, 포즈·얼굴 짝짓기, 점수·편차·CVA 환산(인계 문서 5절 값 L′ 0/30/60/100/150 % → 50/39.6/32.8/21.7/9.9°)을 확인합니다. 녹화 랜드마크를 연구 실시간 도구와 앱에 같이 넣은 비교는 [development.md](development.md#2026-11-23-목-점수를-연구-도구와-같은-조건으로)에 있습니다. 실제 웹캠 정확도는 사용자 확인으로 따로 봅니다.
- 연구 결과(인계 문서 6절): 학습에 안 쓴 사람(S01) 사진, 평소 자세 보정, 기준 CVA 50°. 목 부하 점수는 평소 0, 목 내밀기 F1/F2/F3 20/45/65(앱 목 점수 80/55/35), 몸통 숙이기 B1/B2 0/24, 고개 숙이기 P1 29이고, 추정 CVA는 50°, 40/31/23°, 50/38°, 36°입니다(옆 사진의 실제 CVA는 50°, 42/30/23°, 50/36°, 42°).

### 좌우 균형 점수 (2026-11-25)

사용자 결정(2026-11-25)으로 어깨 점수를 없애고 좌우 균형 점수로 바꿨습니다. 어깨 점수는 실제 사용에서 정확도가 낮고 자주 끊기며 값이 튀었고, 목을 내민 것과 별개로 고개를 한쪽으로 갸웃한 채 있는 습관을 잡자는 요청입니다. 구현은 [modes/balance.ts](../front/src/features/posture/modes/balance.ts)입니다.

- **각도:** 고개 = 같은 프레임 얼굴 분석의 머리 회전 행렬(열 우선 `R(r,c) = f[4c+r]`)의 좌우 기울기 roll = `atan2(f[1], f[0])`. 고개를 좌우로 25°(E19와 같은 yaw 식·한도) 넘게 돌리면 재지 않습니다. 어깨선 = 포즈 11·12번 점을 영상 가로·세로 픽셀로 환산해 이은 선이 수평과 이루는 각(−90°…90°, 어느 어깨가 영상 왼쪽에 있든 같은 식이라 거울 영상에서도 ±180° 근처로 튀지 않음)이고, 두 점 가시성이 모두 0.7 이상일 때만 잽니다.
- **기준:** 5초 보정 프레임에서 각 각도의 중앙값. 그 각도를 보정 프레임의 절반 이상(최소 3장)에서 잰 경우에만 기준으로 씁니다.
- **기운 정도:** `max(|고개 − 기준|, |어깨선 − 기준|)`. 어깨선은 지금과 기준 모두 잰 경우에만 넣고, 고개를 못 재면 점수를 내지 않습니다(어깨만으로 매기지 않음).
- **점수:** 좌우 균형 민감도 50%(기본)에서 3° 이내 100점, 18° 이상 0점, 사이는 직선(1°에 약 6.7점, 7.5°에서 70점). 목과 같은 One Euro 필터로 다듬고 보정할 때 초기화합니다. 보호 규칙은 없습니다.
- **좌우 균형 민감도(설정):** 사용자 결정(2026-11-25)으로 설정의 자세 무너짐 민감도 자리를 이 슬라이더(10–100%, 10% 간격, 기본 50%)로 바꿨습니다. 10%p 올릴 때마다 두 각도가 기본값의 10%씩 작아져 덜 기울어도 점수가 내려갑니다(100% → 1.5°/9°, 70% → 2.4°/14.4°, 10% → 4.2°/25.2°; 70점이 되는 기울기는 3.75°–10.5°). 상체를 시작할 때 읽어 그 실행 동안 고정합니다. 50%가 아니면 정책 ID에 `:s<값>`을 붙여 통계는 같은 민감도로 잰 기록끼리만 묶고, 학습이력은 이 변형들을 이전 기준으로 표시하지 않습니다. 구현은 `modes/balance.ts`의 `balancePolicy`, 저장은 `features/settings/preferences.ts`(`moti.settings.balanceSensitivity`, 예전 자세 무너짐 민감도 값은 읽지 않음), 시작 시 적용은 `features/session/MonitoringProvider.tsx`입니다.
- **기준 이탈(습관):** 편차 = (100 − 화면의 정수 점수) / 200으로 목과 같고, 기준도 목과 같은 알림 설정의 "N점 이하 N초"입니다(기본 70점 이하 3초면 1회, 80점 이상이면 끝). 민감도는 점수만 바꾸므로 같은 기울기라도 민감할수록 이탈로 더 쉽게 셉니다.
- **기록:** 새 모드 `balance`, 정책 ID `upper-body-balance-v1-<해시>`(3°·18°·0.7·필터·25°·편차 환산이 해시에 들어감). 이전 `shoulder` 기록은 쓰지 않고 배포 때 DB에서 지웁니다(사용자 결정). 앱이 `balance`를 보내므로 서버를 먼저 새 `database/contracts.ts`로 배포해야 합니다.
- **한계:** 정면 웹캠의 2D 어깨선과 머리 roll입니다. 카메라가 기울어 있어도 보정 기준이 같이 기울어 상쇄되지만, 측정 중 카메라를 움직이면 다시 보정해야 합니다. 3°·18°·0.7은 실제 사용으로 다듬을 잠정 설정이며 진단 기준이 아닙니다.
- **검증:** `posture-balance.test.mjs`가 각도 계산(머리 행렬, 거울 영상의 어깨선), 25° 한도, 어깨 가시성, 기준 중앙값, 3°/18° 경계를 확인합니다. 실제 웹캠 정확도는 사용자 확인으로 따로 봅니다.

### 평균과 정수 점수

- 평균과 서버 기록에는 표시 점수를 유효 시간으로 사다리꼴 적분합니다: `Σ((이전 점수 + 현재 점수) / 2 × 유효 간격) / Σ유효 간격`. 500ms를 넘는 공백은 제외하고 분 경계는 프레임 간 선형 보간 근사입니다. 분모가 없으면 평균은 `null`, 실제 최저 점수는 `0`입니다. 가림·회전·저신뢰도·중복/역행 시각은 `null`로 표시하며 시간을 더하지 않고, 점수를 보류한 동안 평균이나 저장에 마지막 점수를 채워 넣지 않습니다.
- 2026-11-25부터 표시 점수(목·좌우 균형의 `currentScore`)는 반올림한 **정수**이고(사용자 결정: 화면만이 아니라 저장도 정수 점수로), 위 적분과 서버로 보내는 분 단위 점수×시간 합계도 이 정수로 계산합니다. 저장은 점수 자체가 아니라 점수×시간 합계와 유효 시간이므로 DB 열·서버는 그대로입니다.
- 2026-11-25에 어깨 점수와 함께 움직임 보호 규칙(250px/초 동결·2초 유예·초당 35점 감점·1초 복귀 확인)도 없앴습니다. 목과 좌우 균형은 One Euro 필터만 씁니다.

## 점수와 분리된 습관 정보

- 관측률: 유효 관찰 시간 / 실행 시간. 실행 시간에는 모델 준비와 기준 수집이 포함됩니다. 분모 0은 `—`이며 미확인 시간을 휴식으로 바꾸지 않습니다.
- 연속·최장 관찰: 유효한 연속 구간 길이. 누락이나 긴 공백에서 현재 연속 구간을 끊습니다. 실제 작업·착석 시간을 확정하지 않습니다.
- 지속된 기준 이탈(2026-11-25부터 `alert-hold-v1:<점수>:<초>`, 사용자 결정): 설정 알림 카드의 상체 "N점 이하 N초 유지"를 그대로 씁니다. 화면에 보이는 정수 점수가 N점 이하인 관측이 N초 이어지면 1회로 확정하고, 이후 N + 10점 이상(100점 넘으면 100점)이면 끝냅니다. 진입과 종료 기준을 달리해 경계 주변 흔들림에 반복 집계되는 것을 줄입니다. 목·좌우 균형을 따로 세고(통계는 둘을 더함), 재지 못한 구간은 이탈 연속성을 끊습니다. 상체를 시작할 때 읽어 그 실행 동안 고정하므로 실행 중에 알림 설정을 바꾸면 알림은 바로, 이 횟수는 다음 실행부터 바뀝니다. 기본값 ID는 `alert-hold-v1:70:3`입니다.
- 확정 후 이탈 시간: 확정된 이탈 상태가 양 끝에서 이어진 유효 간격만 더합니다. 대기 2초는 소급 가산하지 않습니다. 누락·새 기준·중지는 구간을 종료하며, 확인하지 못한 복귀나 휴식을 만들어내지 않습니다.

이전 규칙: 2026-10~11-25에는 알림과 따로 `weighted-reference-deviation-v3`(70점 이하 2초, 80점 이상 종료)였고, 2026-10-17부터는 설정의 **자세 무너짐 민감도**(10–100%)가 이 기준을 바꿨습니다(50%가 아니면 `…:s<값>`). 2026-11-25에 그 슬라이더 자리는 좌우 균형 민감도가 되었고 기준 이탈은 알림 설정을 따릅니다. 지난 기록은 영상이 없어 다시 셀 수 없으므로 그때 기준으로 센 횟수를 그대로 둡니다. 기록마다 규칙 ID가 남고, 통계는 상체를 점수 정책으로만 묶어 규칙이 다른 기록도 함께 더하며, 학습이력은 규칙이 달라도 이전 기준으로 표시하지 않습니다.

종료 기준(N + 10점)도 잠정 제품 설정입니다. 이 지표는 기준에서 달라진 구간의 기록이며 잘못된 자세·오사용·자세 전환 빈도·휴식 판정과 다릅니다. 이를 하나의 습관 점수로 합치거나 오래 같은 자세라는 이유로 자세 점수를 깎지 않습니다. 명시적 휴식 기록·휴식 알림은 후속 작업입니다.

## 관측값의 의미

- `delta`는 귀·어깨의 **화면상 변화 비율과 현재 기울기**이며 2026-11-25부터 안내 띠와 화면 관찰 시간에만 씁니다. 증가/감소의 한쪽만 사용하는 항은 반대 방향 변화도 0이므로, 0이 반드시 기준과 동일함을 뜻하지 않습니다. 100점은 보정 자세에서 허용 범위 안이라는 뜻이며 건강한 자세, 해부학적 정상, 거북목 진단을 뜻하지 않습니다. 기준 수집·관측 모듈 자체는 점수를 계산하지 않습니다.
- 관측 누락·낮은 가시성·허용 범위를 벗어난 고개 회전은 `delta: null`입니다. 정상 자세, 오사용 또는 휴식으로 분류하지 않습니다. 화면 갱신 간격 중 누락이 발생해도 이전 변화량은 즉시 지웁니다.
- `observedSeconds`는 기준 확보 후 연속된 유효 관측 사이의 시간 합입니다. 첫 관측과 재개 첫 관측은 시간을 더하지 않으며 기준 수집 시간도 제외합니다. PC 작업시간·실제 착석시간·휴식시간의 측정값이 아닙니다.
- 시간은 프레임 캡처 시점의 단조 증가 시각을 사용합니다. 500ms까지의 연속 간격만 가산하고, 초과 간격 전체를 제외합니다. 중복·역행·비유한 시각은 값을 지우고 연속성을 끊습니다. 역행 이전의 마지막 시각을 유지해 같은 구간을 다시 더하지 않습니다.

구현은 [observation.ts](../front/src/features/posture/observation.ts), 수집 설정은 [calibration.md](calibration.md)를 따릅니다. 500ms·가시성 0.7 등의 값은 기존 수집 설정이며 건강·점수·습관 판정 임계값이 아닙니다.

`PostureMonitor`는 모든 관측 결과를 점수·습관 계산에 전달한 뒤 화면만 약 200ms 간격으로 갱신합니다. 중지 시 마지막 계산을 화면에 반영하고, 새 세션이나 모드 변경에는 이전 결과를 전달하지 않습니다. 정책 버전이 바뀌면 평균·습관 누적을 초기화해 서로 다른 정책 결과가 섞이지 않게 합니다. 현재 결과의 버전은 `MonitorSnapshot.neck`/`balance`와 서버 부위별 기록에 저장합니다.

달력의 기존 단순 평균 오류를 수정했습니다. 예를 들어 90점 9세션과 0점 1세션은 45점이 아니라 81점입니다. 평균은 최종 결과에서 반올림합니다. `sessionCount`에는 점수 없는 행의 세션도 포함합니다. 기존 집계 행 내부에서 누락된 개별 점수 수는 현재 스키마로 복원할 수 없습니다.

## 자정 집계의 현재 계약과 한계

기존 서버는 DB의 `DATE(started_at)`에 세션 전체 시간을 귀속합니다. 예를 들어 9월 12일 23:59:50에 시작해 13일 00:00:10에 종료한 세션은 **12일에 20초와 세션 1회**로 집계하는 SQL입니다. 날짜별로 10초씩 분할하지 않습니다. 이는 유지한 기존 계약이며 새 습관 통계 정책이 아닙니다.

새 상체 점수·습관 계산은 단조 시각을 사용하므로 자정에 평균이나 이탈 대기 시간이 초기화되지 않습니다. 기존 서버에는 새 정책의 결과를 아직 전송하지 않습니다. 시간 가중 점수·관측률·정책 버전의 일별 저장은 기존 세션 수 평균과 구분해 데이터 계약을 정한 뒤 연결해야 합니다.

테스트는 SQL·트랜잭션 대역과 날짜가 지정된 응답 자료를 검사합니다. **실제 DB에서 자정 경계를 실행한 검증은 아닙니다.** MySQL 드라이버의 `timezone: '+09:00'`만으로 DB 세션 시간대가 설정되었다고 볼 수 없습니다. 실제 DB 선정 후 DB 시간대, SQL mode, FLOAT 누적 정밀도, 동시 종료 및 월말·연말 경계를 확인해야 합니다. 세션 시작 응답의 JS 시각과 DB 저장 시각의 차이도 확인 대상입니다.

세션 상세 그래프는 날짜까지 포함해 그룹화하지만 응답의 `time`은 기존 `HH:mm`입니다. 다일 세션에는 같은 라벨이 여러 번 나올 수 있습니다. 그래프의 `AVG(measured_value) AS score` 역시 단위가 미정인 기존 필드이며 새 자세 점수가 아닙니다.

## 로컬 SQLite 집계 계약 (2026-09-19)

키보드의 2026-10-01 정책은 [키보드 계약](../front/src/features/keyboard/README.md)을 따릅니다. 기본표·허용 100, 같은 손 인접 70, 그 외 0을 판정 가능한 입력 수로 평균하고 보류는 분모에서 제외합니다. 판정 가능 비율과 사용 일관성은 분리하며 정책/인식 버전/가중치가 다른 기록은 합산하지 않습니다. 일관성은 키·Shift 상황별 10회 이상 그룹의 최빈 손가락 수/그룹 관측 수이며 점수 보너스가 아닙니다. 타자 내용의 오타율·건강 개선율·판별 정확도로 읽으면 안 됩니다.

가림 자체를 감지하는 모델은 없으며 손끝 관측 부족, 키보드/손 구분 품질, 거리·후보 차이와 프레임 시간 차이를 잠정 보류 기준으로 사용합니다. MediaPipe의 손 구분 점수는 손끝 정확도 확률이 아닙니다. 70점과 기하 임계값은 CHI 2016이 검증한 수치가 아닙니다. 자동 검사는 산식·데이터 보존·상태·보안 경계만 검증하고 실제 카메라의 인식률은 검증하지 않습니다.

목·어깨의 기존 evaluation 누적 결과를 화면 갱신 전 모든 캡처에서 기록합니다. 500ms 이하 유효 구간의 사다리꼴 점수 적분을 분 경계에 나누고 같은 모드·정책의 유효 시간 합으로 평균합니다. 미관측 시간과 0점은 구별하며 원시 프레임은 저장하지 않습니다. 통계 날짜는 구간 발생일, 이력 날짜는 기록 시작일입니다. 시간대는 기록 시작 offset을 유지합니다. 전일 차이는 같은 정책의 점수 차이이며 의료적 개선율이 아닙니다. 최장 연속 관찰은 날짜에 포함된 기록 전체의 최댓값으로 명시합니다.

`record-replay.test.mjs`는 실제 observation/evaluation reducer에 누락·중복·역행 프레임을 넣어 저장된 시간·적분·기준 이탈·최장 관찰 합계가 동일함을 확인합니다. 파일 SQLite 재시작/잠금/롤백/세대 삭제, 자정·연말·정책 분리·가중 평균·페이지·실제 Electron IPC/UI 검증도 수행했습니다. 실제 카메라 정확도나 의학적 타당성을 증명하지 않습니다.
