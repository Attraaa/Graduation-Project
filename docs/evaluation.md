# 점수와 습관 평가 검증

2026-09-15 현재 **목·어깨의 기준 자세 유사도 점수와 관찰 습관 집계**를 구현했습니다. 사용자의 추가 구현 요청에 따라 초기 정책 v1을 적용했으며 아래 수치는 개발용 제품 설정입니다. 실험으로 검증한 건강 기준이 아닙니다. 키보드 분석은 이번 작업에서 제외하고 기존 화면을 독립 컴포넌트로 옮겼습니다.

## 점수 알고리즘 v1

| 모드 | 기준 대비 변화 `d` | 정책 버전 |
| --- | --- | --- |
| 목 (`turtle`) | 코 가로 위치 변화·높이 변화의 절댓값 중 최대 | `reference-similarity-turtle-v1` |
| 어깨 (`shoulder`) | 양어깨 높이 차이 변화의 절댓값 | `reference-similarity-shoulder-v1` |

`d`의 단위는 화면에 투영된 어깨 너비 대비 비율입니다. 예를 들어 `0.05`는 5%이며 각도나 cm가 아닙니다. 선택한 지표의 변화가 5% 이하면 100점, 30% 이상이면 0점, 사이는 `100 × (0.30 − d) / (0.30 − 0.05)`입니다. 17.5%는 50점입니다. 미선택 지표는 해당 모드의 점수에 사용하지 않습니다.

5%는 작은 관측 변화의 허용 구간, 30%는 환산 범위의 끝으로 정한 **초기 구현값**입니다. 두 값에 의료적 근거나 실기기 정확도를 부여하지 않습니다. 원점수는 반올림하지 않고 화면에서만 정수로 표시합니다. 임계값과 선택 지표는 `modes/turtle.ts`, `modes/shoulder.ts`가 소유하고 공통 환산은 `scoring.ts`가 담당합니다.

세션 평균은 유효한 양 끝 관측 점수의 평균에 간격을 곱하는 사다리꼴 적분을 사용합니다: `Σ((이전 점수 + 현재 점수) / 2 × 유효 간격) / Σ유효 간격`. 프레임 수로 평균하지 않습니다. 첫 프레임에는 현재 점수만 있으며, 유효 시간 분모가 생기기 전 평균은 `null`입니다. 측정 누락은 `null`, 관측된 최저 점수는 `0`으로 구분합니다.

## 점수와 분리된 습관 정보

- 관측률: 유효 관찰 시간 / 실행 시간. 실행 시간에는 모델 준비와 기준 수집이 포함됩니다. 분모 0은 `—`이며 미확인 시간을 휴식으로 바꾸지 않습니다.
- 연속·최장 관찰: 유효한 연속 구간 길이. 누락이나 긴 공백에서 현재 연속 구간을 끊습니다. 실제 작업·착석 시간을 확정하지 않습니다.
- 지속된 기준 이탈: `reference-deviation-v1` 정책입니다. `d ≥ 0.15`인 양 끝 관측 구간이 2,000ms 이상 연속되면 1회로 확정합니다. 이후 `d ≤ 0.10`이면 종료합니다. 진입과 복귀 기준을 달리해 경계 주변 흔들림에 반복 집계되는 것을 줄입니다.
- 확정 후 이탈 시간: 확정된 이탈 상태가 양 끝에서 이어진 유효 간격만 더합니다. 대기 2초는 소급 가산하지 않습니다. 누락·새 기준·중지는 구간을 종료하며, 확인하지 못한 복귀나 휴식을 만들어내지 않습니다.

15%·10%·2초도 잠정 제품 설정입니다. 이 지표는 기준에서 달라진 구간의 기록이며 잘못된 자세·오사용·자세 전환 빈도·휴식 판정과 다릅니다. 이를 하나의 습관 점수로 합치거나 오래 같은 자세라는 이유로 자세 점수를 깎지 않습니다. 명시적 휴식 기록·휴식 알림은 후속 작업입니다.

## 관측값의 의미

- `delta`는 기준 자세와 현재 얼굴·어깨의 **화면상 기하 차이**입니다. 0은 기준과 같다는 뜻이며 건강한 자세, 해부학적 정상, 거북목 진단을 뜻하지 않습니다. 100점 역시 위 허용 범위 안의 유사도를 의미합니다. 기준 수집·관측 모듈 자체는 점수를 계산하지 않습니다.
- 관측 누락·낮은 가시성은 `delta: null`입니다. 정상 자세, 오사용 또는 휴식으로 분류하지 않습니다. 화면 갱신 간격 중 누락이 발생해도 이전 변화량은 즉시 지웁니다.
- `observedSeconds`는 기준 확보 후 연속된 유효 관측 사이의 시간 합입니다. 첫 관측과 재개 첫 관측은 시간을 더하지 않으며 기준 수집 시간도 제외합니다. PC 작업시간·실제 착석시간·휴식시간의 측정값이 아닙니다.
- 시간은 프레임 캡처 시점의 단조 증가 시각을 사용합니다. 500ms까지의 연속 간격만 가산하고, 초과 간격 전체를 제외합니다. 중복·역행·비유한 시각은 값을 지우고 연속성을 끊습니다. 역행 이전의 마지막 시각을 유지해 같은 구간을 다시 더하지 않습니다.

구현은 [observation.ts](../front/src/features/posture/observation.ts), 수집 설정은 [calibration.md](calibration.md)를 따릅니다. 500ms·가시성 0.7 등의 값은 기존 수집 설정이며 건강·점수·습관 판정 임계값이 아닙니다.

`PostureMonitor`는 모든 관측 결과를 점수·습관 계산에 전달한 뒤 화면만 약 200ms 간격으로 갱신합니다. 중지 시 마지막 계산을 화면에 반영하고, 새 세션이나 모드 변경에는 이전 결과를 전달하지 않습니다. 정책 버전이 바뀌면 평균·습관 누적을 초기화해 서로 다른 정책 결과가 섞이지 않게 합니다. 현재 결과의 버전은 `MonitorSnapshot.evaluation`에 있으며 아직 DB에 저장하지 않습니다.

## 자동 검증과 수정 결과

| 대상 | 확인한 동작 |
| --- | --- |
| 상체 계산 | 같은 입력 재생 시 같은 상태·변화량·점수·관찰 시간, 입력 불변성, 기준 수집 시간 제외, 모드별 사용 지표 격리 |
| 누락·재개 | 누락·저신뢰도에서 `null`, 누락 구간 제외, 재개 첫 프레임 미가산, 카메라/기준 변경 시 구간 분리 |
| 경계 | 가시성 0.7/1, 최소 어깨 수평 폭 0.1, 표본 간격 100ms, 허용 공백 500ms의 경계와 인접값, 설정된 안정 범위 경계 |
| 시간 | 중복·역행 시각에 관찰 시간이 감소하거나 중복 가산되지 않음. 단조 시각은 자정을 넘어도 이어짐 |
| 새 점수·습관 | 5%/30% 점수 경계, 15% 진입·10% 복귀·2초 경계, 시간 가중 평균, 프레임 밀도, 누락·정책 변경 초기화 |
| 기존 점수 입력 | 0·100 포함, 누락·범위 밖·소수·문자열 거부. 로그의 누락 측정값과 실제 0 구분 |
| 서버 평균 | 오늘·달력 모두 세션 수 가중 평균. 평균값이 `null`인 행은 점수 분모에서 제외하고 실제 0점은 포함. 점수 자료가 없으면 `null` |
| 날짜별 조회 | 달력 날짜 구분, 다일 세션에서 다른 날짜의 같은 시각 로그를 별도 분으로 그룹화 |
| 종료 집계 | 동일 연결에서 잠금 → 종료 저장 → 시작일 집계 → 커밋, 실패 시 롤백, 종료 재시도 중복 방지 |

달력의 기존 단순 평균 오류를 수정했습니다. 예를 들어 90점 9세션과 0점 1세션은 45점이 아니라 81점입니다. 평균은 최종 결과에서 반올림합니다. `sessionCount`에는 점수 없는 행의 세션도 포함합니다. 기존 집계 행 내부에서 누락된 개별 점수 수는 현재 스키마로 복원할 수 없습니다.

실행: `moti.cmd check`와 프론트 `npm run build`. 최신 검사 수와 화면 검증 결과는 [development.md](development.md)에 기록합니다. 이 테스트들은 실제 카메라의 판별 정확도를 검증하지 않습니다.

## 자정 집계의 현재 계약과 한계

기존 서버는 DB의 `DATE(started_at)`에 세션 전체 시간을 귀속합니다. 예를 들어 9월 12일 23:59:50에 시작해 13일 00:00:10에 종료한 세션은 **12일에 20초와 세션 1회**로 집계하는 SQL입니다. 날짜별로 10초씩 분할하지 않습니다. 이는 유지한 기존 계약이며 새 습관 통계 정책이 아닙니다.

새 상체 점수·습관 계산은 단조 시각을 사용하므로 자정에 평균이나 이탈 대기 시간이 초기화되지 않습니다. 기존 서버에는 새 정책의 결과를 아직 전송하지 않습니다. 시간 가중 점수·관측률·정책 버전의 일별 저장은 기존 세션 수 평균과 구분해 데이터 계약을 정한 뒤 연결해야 합니다.

테스트는 SQL·트랜잭션 대역과 날짜가 지정된 응답 자료를 검사합니다. **실제 DB에서 자정 경계를 실행한 검증은 아닙니다.** MySQL 드라이버의 `timezone: '+09:00'`만으로 DB 세션 시간대가 설정되었다고 볼 수 없습니다. 실제 DB 선정 후 DB 시간대, SQL mode, FLOAT 누적 정밀도, 동시 종료 및 월말·연말 경계를 확인해야 합니다. 세션 시작 응답의 JS 시각과 DB 저장 시각의 차이도 확인 대상입니다.

세션 상세 그래프는 날짜까지 포함해 그룹화하지만 응답의 `time`은 기존 `HH:mm`입니다. 다일 세션에는 같은 라벨이 여러 번 나올 수 있습니다. 그래프의 `AVG(measured_value) AS score` 역시 단위가 미정인 기존 필드이며 새 자세 점수가 아닙니다.

## 로컬 SQLite 집계 계약 (2026-09-19)

목·어깨의 기존 evaluation 누적 결과를 화면 갱신 전 모든 캡처에서 기록합니다. 500ms 이하 유효 구간의 사다리꼴 점수 적분을 분 경계에 나누고 같은 모드·정책의 유효 시간 합으로 평균합니다. 미관측 시간과 0점은 구별하며 원시 프레임은 저장하지 않습니다. 통계 날짜는 구간 발생일, 이력 날짜는 기록 시작일입니다. 시간대는 기록 시작 offset을 유지합니다. 전일 차이는 같은 정책의 점수 차이이며 의료적 개선율이 아닙니다. 최장 연속 관찰은 날짜에 포함된 기록 전체의 최댓값으로 명시합니다.

`record-replay.test.mjs`는 실제 observation/evaluation reducer에 누락·중복·역행 프레임을 넣어 저장된 시간·적분·기준 이탈·최장 관찰 합계가 동일함을 확인합니다. 파일 SQLite 재시작/잠금/롤백/세대 삭제, 자정·연말·정책 분리·가중 평균·페이지·실제 Electron IPC/UI 검증도 수행했습니다. 실제 카메라 정확도나 의학적 타당성을 증명하지 않습니다. 자세한 증거는 [검증 기록](ai-workflow/work-items/2026-09-19/jangwon/statistics/09_VERIFICATION.md)에 있습니다.
