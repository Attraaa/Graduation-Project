# Moti 상체 모델 기여와 다음 선택

작성: 2026-10-18. 비교 기준: GitHub main `7753e71`, 현재 로컬 v6. 모델 가중치와 결합 조건은 v5와 같습니다. 실제 사용자 촬영 정확도를 검증한 보고서는 아닙니다.

## 결론

**현재 학습 모델은 Moti의 주된 거북목 판정기로 쓰기 어렵습니다.** 몸통 방향을 학습했고 골반 입력이 필요하므로, 얼굴·어깨 중심 구도에서의 기여는 작거나 0입니다. 당장은 main의 설명 가능한 점수 구조에 상대 관측을 보완하고, 학습 모델의 영향은 제한하는 선택이 적합합니다. 큰 모델로 교체하는 것보다 **Moti가 구별해야 할 동작을 실제 사용 구도로 수집하는 것**이 우선입니다.

## 무엇을 학습했고 무엇을 못 배웠나

| 항목 | 확인한 사실과 의미 |
|---|---|
| 자료 | MultiPosture CSV 실제 4,794행/13명. MediaPipe Heavy의 관절 좌표와 몸통 방향 라벨입니다. 원본 영상·사진은 없습니다. |
| 모델 | 코·어깨·골반에서 7특징 → 16개 은닉값 → upright/forward/backward/lateral 분류. 작은 NumPy MLP를 직접 학습했습니다. |
| 검증 | 한 사람씩 학습에서 제외한 13회 LOSO: 전체 정확도 97.85%, 최저 사람 88.52%. 보류 후 채택률 88.42%, 채택된 표본의 정확도 99.58%. |
| 배우지 않은 것 | 머리만 앞으로 내밀기와 의자 전체의 접근 구분, 거북목 각도/CVA, 골반 없는 근접 웹캠, Moti 점수의 정량적 정답. 높은 몸통 분류 정확도가 이 능력을 뜻하지 않습니다. |
| 추정기 차이 | 자료는 Heavy, 앱은 Full입니다. 입력 구도와 추정기의 차이에 대한 Moti 검증은 없습니다. |

MediaPipe가 반환하는 3D 좌표도 영상에서 추론한 값으로, 별도 거리 센서로 측정한 값이 아닙니다. [공식 출력 설명](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)

## 이번 반영에서의 실제 영향

직전 v4에서는 학습 모델을 앱에서 제외했으므로 **기여 0**이었습니다. v5/v6는 모델의 사용 조건을 만족할 때만 목의 25% 보조 항에 연결합니다. 기준 수집 전체가 upright, 현재 보이는 골반·얼굴·어깨의 품질 통과, forward 1초 확인, 머리/높이 변화가 함께 있어야 합니다. 최대 추가 영향은 원점수 **12.5점**, 어깨 영향은 0입니다. 골반 없는 일반 구도는 여전히 모델 기여 0이며 기본 측정은 계속됩니다. 개발용 테스트 화면에서 실제 기여를 확인할 수 있습니다. 제품 화면은 main 구성을 따릅니다. 이 보조가 실제 정확도를 개선했다고 아직 주장할 수는 없습니다.

주된 변경은 **원근 변화의 허용**과 **어깨에 대한 머리 상대 변화**입니다. 귀 폭이 거의 변하지 않을 때 코·귀의 추정 깊이가 함께 전진한 경우도 참고합니다. 어깨 크기가 크게 변하면 깊이 보조를 줄여 전체 접근에 따른 추정 오차를 억제합니다. main의 가중합·선형 환산·시간 보호를 유지합니다. v6는 큰 머리 전진의 지속 감점과 어깨 각도의 비선형 평가를 추가했습니다([조절 기준](posture-score-tuning.md)). 모델을 다시 학습한 변경은 아닙니다. 산식과 시험 상수는 [구현 가이드](posture-augmentation.md)에 공개했습니다.

이전 v5에서 같은 사진의 크기를 바꾼 56쌍에서 점수 흔들림 평균은 main 목 27.02 → v5 7.35점, 어깨 24.53 → 2.63점입니다. 다만 목 4쌍·어깨 1쌍은 5점 넘게 악화했고 최대 변화는 목 100점입니다. 이것은 정지 사진의 일관성 검사이며 **실제 거북목 정확도나 모든 사람에 대한 개선율이 아닙니다**. v6로 같은 좌표를 재검사한 결과 목은 7.35점으로 같고 어깨는 추가 민감도 조정 후 4.26점입니다(직전 v6 3.23점). 더 민감한 어깨 정책은 v5의 2.63점보다 흔들림도 커졌습니다. 특히 몸 전체 이동과 머리 전진이 동시에 일어나는 경우를 더 확인해야 합니다.

## 다음 선택의 우선순위

1. **사용 구도의 작은 검증 세트를 먼저 만듭니다.** 동의한 참가자 10명 이상/2회 세션의 예비시험에서 기준 유지, 의자 접근·후퇴, 머리만 전진, 숙임, 어깨 올림, 회전, 가림을 따로 기록합니다. 골반은 화면 밖에 두고 원본 영상은 로컬에 보관합니다. 개발에 쓴 참가자와 최종 시험 참가자를 분리합니다.
2. **현재 기준과 동일 영상으로 비교합니다.** 오경고/분, 머리 전진 누락률, 보류율, 반응·복귀 지연을 함께 봅니다. '보류를 늘려 정확도만 좋아지는' 변경을 막습니다. main, v5, v5에서 깊이 제거, 모델 보조 제거를 비교하면 각 요소의 실효성을 알 수 있습니다. 합격 기준은 결과를 보기 전에 정합니다.
3. **그 다음 골반 없는 작은 모델을 학습합니다.** 기준 대비 얼굴 크기·머리/어깨 상대 깊이·어깨 기울기·시간 변화량으로 '공통 접근/머리 전진/상체 기울임/불확실'을 분류하는 방안이 Moti 목표에 더 가깝습니다. 기존 안구 FaceLandmarker의 얼굴 좌표 재사용은 귀 가림 보완 후보지만, Pose와 캡처 시각·회전·기준 수집을 맞추고 비교 실험부터 해야 합니다. 이번에는 추가하지 않았습니다.
4. **각도나 cm가 필요하면 별도 정답이 필요합니다.** 측면 영상 등 독립 측정 기준 없이 현재 점수를 정답 삼아 재학습하면 현재 규칙을 모방할 뿐입니다. 공개 몸통 자료만 늘려 이 문제를 해결하려 하지 않는 편이 낫습니다.

지금 재학습을 반복하는 것보다 위 1→2의 검증이 우선입니다. 기존 학습 결과와 데이터 탐색은 `reports/posture-augmentation/model-inspector.html`, 재현 명령은 [가이드](posture-augmentation.md)에 있습니다. 이번에는 기존 가중치를 재사용했고 새 학습이나 실제 사용자 영상 수집은 하지 않았습니다.

## 실행 시간이 길었던 이유

- setup은 이전에 실행마다 `npm ci`를 수행했습니다. 설치 입력의 해시와 의존성 상태가 같으면 재사용하도록 변경했습니다. 이 PC의 전체 설치 23.7초, 반복 2.3초이며 첫 다운로드 시간은 네트워크에 따라 다릅니다.
- 개발 화면은 CSS 처리 중 메모리 약 1.4GB까지 늘고 응답이 지연됐습니다. CSS 입력을 앱 소스로 제한하고 캐시·중첩 작업 폴더를 개발 파일 감시에서 제외했습니다. 수정 후 개발 서버 0.67초, 첫 로그인 화면 1.98초/재접속 0.94초, Node 메모리 약 200MB를 확인했습니다. 측정 환경마다 다를 수 있습니다.
- 별도 MLP는 약 5KB의 숫자 배열과 작은 계산으로 추가 WASM 모델 초기화가 없습니다. 상체 시작 후 대기는 기존 Pose/Face의 초기화 단계입니다. 30초 강제 실패를 없애고 단계/경과 시간/첫 실행 1분 이상 가능 안내를 추가했습니다. 실제 오류는 계속 표시합니다.
