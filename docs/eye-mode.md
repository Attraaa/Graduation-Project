## 1. 무엇을 만들었는가

단안 RGB 웹캠으로 **눈을 깜빡이는 행동과 작업 중 휴식 습관**을 도와주는 모드입니다. 새 신경망을 학습한 것이 아니라, Google의 사전 학습 얼굴 모델에 프로젝트의 시간 판정 규칙을 결합했습니다. 추가 카메라, 깊이 센서, Python 분석기, 계정/API/DB가 필요하지 않습니다.

| 기능 | 실제 동작 | 해석의 한계 |
| --- | --- | --- |
| 깜빡임 | 양쪽 눈이 열린 뒤 감겼다가 다시 열리는 이벤트 집계 | 모델 계수로 추정한 동작. 미세·짧은 깜빡임, 가림은 누락 가능 |
| 빈도 | 깜빡임 수 × 60,000 / 유효 관찰 ms | 관찰 30초 전에는 `—`. 정상·비정상 임계값 없음 |
| 깜빡임 안내 | 양쪽 눈 열림이 연속 15초 관찰되면 문구 표시 | 구현자가 정한 알림 정책. 건조증 진단 기준 아님 |
| 가까워짐 안내 | 시작 구도보다 얼굴 폭이 커진 상태가 지속되면 안내 | 실제 거리 cm·안전 거리 아님. 줌/카메라 이동에도 반응 |
| 눈 휴식 | 실행 중 20분 주기로 안내. 사용자가 20초 휴식을 시작·완료 | 실제 먼 곳 응시 여부는 측정하지 않는 본인 확인 기록 |

시력, 안압, 눈물막 상태, 안구건조증, 피로의 임상적 정도, 질환 위험을 측정하지 않습니다. 그럴듯한 “눈 건강 90점”도 만들지 않았습니다. 휴식 안내는 AOA의 20–20–20 안내에서 가져왔지만, 앱 자체의 건강 개선 효과를 검증했다는 뜻은 아닙니다.

## 2. 실행

이 브랜치를 내려받은 저장소 루트에서 실행합니다. `Eye-Prototype`이라는 별도 하위 폴더를 만들 필요는 없습니다.

1. 이 폴더의 `eye.cmd`를 더블클릭합니다. 브라우저의 `/#/learn/eye` 화면이 열립니다. 기본 포트는 Vite의 5173이며 이미 사용 중이면 터미널의 실제 주소를 확인합니다.
2. 사용할 웹캠을 고릅니다. 화면 상단/중앙에 고정하고 얼굴 전체가 보이게 앉습니다. 화면 확대/자동 줌을 사용한다면 고정합니다.
3. **안구 모드 시작**을 누르고 카메라 권한을 허용합니다. 모델 준비 후 편안한 거리에서 정면 구도를 3초 유지합니다. 자연스럽게 깜빡여도 됩니다.
4. 깜빡임 횟수를 확인합니다. **빈도는 기준 수집 후 유효 관찰 30초부터** 표시합니다.
5. **지금 20초 쉬기**를 누르면 카메라가 꺼집니다. 20초가 지나면 **휴식 완료하고 복귀**를 누릅니다. 중간에 복귀하면 휴식 완료로 집계하지 않습니다.
6. **측정 중지** 시 스트림과 모델을 해제하고 현재 화면에 마지막 집계를 유지합니다. 새 시작/다른 화면 이동은 이전 결과를 보존하지 않습니다. 거리 기준만 다시 잡기는 누적 횟수·유효 시간·휴식 기록을 유지합니다. 터미널 `Ctrl+C`로 개발 서버를 종료합니다.

`eye.cmd`는 프로젝트 전용 Node/npm과 uv 도구가 없으면 기존 `setup.ps1 -ToolsOnly`로 준비하고, 프론트 의존성만 설치합니다. uv 실행 파일은 기존 도구 검사 계약 때문에 설치되지만 Python 환경/모델은 설치하지 않습니다. 같은 폴더의 데스크톱 실행 환경을 깨뜨리지 않도록 Electron 설치 단계도 유지합니다. 따라서 첫 실행에는 Electron 다운로드 시간도 걸릴 수 있으나 실행 화면은 **브라우저 안구 시연용**입니다. Electron/키보드까지 실행하려면 기존 `setup.cmd`를 먼저 실행한 뒤 `moti.cmd app`을 사용합니다.

브라우저는 `localhost` 또는 `127.0.0.1`에서 실행하세요. 기존 AWS의 HTTP IP 주소로 올리는 것만으로는 브라우저 카메라를 사용할 수 없습니다. 원격 배포 시 HTTPS 설정은 별도입니다. 이번 작업은 AWS/기존 DB에 아무것도 배포하지 않았습니다.

## 3. 모델과 계산

```text
웹캠 → Face Landmarker (기기 내부, CPU/WASM)
     → 얼굴 수·구도 검사 → eyeBlinkLeft/Right + 얼굴 폭
     → 개인 구도 기준 수집 → 시간 상태 기계 → 표시·안내
명시적 휴식 버튼 → 별도 휴식 타이머 → 카메라 중지/복귀
```

- 런타임: `@mediapipe/tasks-vision@0.10.32`, npm 잠금에 고정.
- 모델: Google Face Landmarker float16 v1 task bundle. 얼굴 랜드마크와 표정 계수를 사용합니다. `eyeBlinkLeft/Right`는 건강 점수나 확률로 해석하지 않습니다.
- 얼굴 2개까지 검출하도록 설정하고, 결과가 정확히 1개일 때만 관찰합니다. 2개 설정에서는 MediaPipe 내장 단일 얼굴 smoothing이 적용되지 않습니다. 시간 지속 조건으로 순간 변동을 완화합니다.
- 검출/얼굴 존재/추적 설정은 각 0.6. 추가로 얼굴 밖 좌표, 너무 작은 얼굴, 큰 기울기/회전으로 보이는 구도를 보류합니다. 이 필터는 안경 반사·손 가림을 모두 검출하는 품질 보증 모델이 아닙니다.
- 렌더링은 약 10회/초, 추론은 새 비디오 프레임에서 최소 30ms 간격으로 수행합니다. `detectForVideo`는 UI 스레드에서 실행되는 동기 함수입니다. 저사양 PC의 지연·실효 FPS는 실제 장비에서 평가해야 합니다. 이번 범위에서 Worker 전환은 하지 않았습니다.

### 깜빡임 규칙

`eyePolicy.ts`의 `eye-habits-v2` 정책입니다. 양쪽 계수 모두 ≤0.25이면 열림, 모두 ≥0.55이면 감김입니다. **열림 → 감김 → 열림** 순서이며, 감김을 관찰한 뒤 다시 열릴 때까지 40–700ms일 때 1회 집계합니다. 이는 실제 눈꺼풀의 완전 폐쇄 시간과 같지 않습니다. 처음부터 감겨 있거나, 한쪽만 감거나, 700ms를 넘게 감으면 깜빡임으로 세지 않습니다. 일반적인 짧은 깜빡임도 프레임 속도가 낮으면 놓칠 수 있습니다.

프레임이 없거나 무효 구도면 진행 중 이벤트를 폐기합니다. 유효 프레임 사이가 250ms를 넘으면 그 공백을 관찰 시간으로 더하지 않습니다. 정면으로 돌아왔다는 사실만으로 깜빡임을 하나 만들지 않습니다. 깜빡임 횟수와 유효 시간은 기준 수집 이후 누적합니다. **세션 전체 빈도**와 **최근 유효 관찰 최대 60초의 빈도**를 따로 표시합니다. 두 빈도 모두 유효 관찰 30초 전에는 `—`입니다. 최근 구간은 벽시계의 최근 1분이 아니며 휴식·유실 구간을 제외한 유효 시간축입니다. 최근 구간 밖으로 나간 깜빡임은 최근 빈도에서만 빠지고 누적 횟수에는 남습니다. 낮은 수치를 질환/건강 점수로 바꾸지 않습니다.

양쪽 열림이 연속 15초 관찰되면 편안하게 깜빡여 보라는 문구를 유지합니다. 중간 계수·감김·유실에서 연속 열림 시간을 끊습니다. 화면에 뜨는 안내이며 OS 알림이나 다른 창 위 알림은 아닙니다.

### 기준 대비 크기

3초 이상/30표본 이상 안정된 구도의 얼굴 폭 중앙값을 기준으로 저장합니다. 수집 중 폭의 최대–최소 차이가 중앙값의 10%를 넘거나 추적이 끊기면 수집을 다시 시작합니다. 폭은 좌우 볼 랜드마크 234·454 사이 거리이며, 영상 가로/세로 비율을 반영합니다.

표시값 = `현재 얼굴 폭 / 기준 얼굴 폭 × 100%`. 예를 들어 130%이면 카메라에서 얼굴이 시작보다 크게 보인다는 뜻입니다. 같은 카메라/배율·정면 조건이라면 가까워진 변화의 대리 지표로 쓸 수 있습니다. 화면에서 눈까지의 물리적 거리를 복원한 값은 아닙니다.

처음 125% 이상이 관찰된 시점부터 3초간 지속되면 안내하며, 한 번 켜진 안내는 115% 이하로 돌아오거나 관찰이 끊기면 해제합니다. 125%/115%/3초는 임시 제품 정책입니다. 시작 구도의 건강상 적절함을 판정하지 않습니다. 카메라 이동·줌 변경 시 **거리 기준만 다시 잡기**를 누릅니다. 누적 깜빡임·유효 시간·휴식 기록은 보존하고 거리 기준과 최근 빈도 구간을 새로 수집합니다. 장치 식별자나 실제 영상 해상도가 바뀌면 같은 재수집을 자동 수행합니다. 물리적 카메라 이동·줌·다른 사용자 여부를 자동으로 모두 알아내는 것은 아닙니다. 사용자 교체 시에는 중지 후 새 세션을 시작하세요. 장시간 자리를 비웠다고 얼굴의 신원을 확인하지 않습니다.

### 휴식 타이머

시작 버튼 이후 앱 세션 실행 시간을 기준으로 하며, 얼굴 유실도 휴식으로 간주하지 않아 타이머는 계속 갑니다. 휴식 중에는 작업 시간을 더하지 않고 카메라/모델을 닫습니다. 20초가 지나면 복귀 버튼을 눌러 완료하라는 안내로 바뀝니다. 자동 완료하지 않으며 사용자가 복귀를 눌러야 완료 1회 + 다음 20분으로 재설정합니다. 조기 취소는 이전 작업 시간을 유지합니다.

타이머 callback 간격이 2초를 넘는 PC 절전·심한 백그라운드 제한 구간은 확인되지 않은 시간으로 제외합니다. 따라서 벽시계 기준 정확히 20분이나 OS 전체 작업시간 추적은 아닙니다. 숨겨진 탭에서는 영상 관찰을 보류하고, 알림은 앱 화면에서만 볼 수 있습니다.

## 5. 확인 결과와 남은 촬영 검증

- 프론트 TypeScript·ESLint 통과.
- 기존 score 기반 작업본에서는 프론트 91개(기존 72개 + 안구 19개)가 통과했습니다. 최신 main 통합본 검증 결과는 아래 통합 절에 별도로 기록합니다.
- Vite 프론트 및 Electron main/preload 빌드 통과. 기존 큰 JS 청크 경고는 남아 있습니다.
- 실제 브라우저에서 로컬 WASM/모델 로딩과 빈 테스트 영상 추론 확인: 얼굴 없음 → 관찰 보류, 수치 임의 생성 없음. 휴식 중 테스트 스트림 0개, 20초 후 명시적 복귀에서 완료 기록 1회·새 스트림 1개, 측정 중지 후 스트림 0개를 확인했습니다.
- 실물 사람 영상의 깜빡임 정확도, 안경별 성능, 저사양 FPS, Windows 설치 파일 실행은 아직 검증하지 않았습니다. 자동 테스트 통과를 실제 정확도 증거로 보지 않습니다. 이번 안구 변경에서는 Python/DB를 준비하거나 전체 `moti.cmd check`를 실행하지 않았습니다.

Pop-Location
```

실촬영은 먼저 사람이 옆에서 센 깜빡임과 1분 관측 횟수를 비교하세요. 정면/안경/어두운 조명 각각 오검출·누락을 메모하고, 한쪽 윙크·1초 이상 감기·잠깐 얼굴 가리기가 횟수를 부풀리지 않는지 확인합니다. 앞으로 다가갔다 원래 위치로 복귀했을 때 안내가 유지/해제되는지, 중지·다른 모드 이동 시 카메라 사용 표시등이 꺼지는지도 확인하세요. 정책을 조정하면 버전과 테스트, 이 문서의 수치를 함께 바꿉니다.

개발용 가짜 영상 확인은 `eye.cmd` 실행 후 `/tests/eye-browser.html`로 접속합니다. 첫 프레임 정지는 `/tests/eye-browser.html?freeze=1`로 확인합니다. 이 페이지는 실제 카메라를 열지 않습니다. 일반 사용자 진입점·프로덕션 빌드에는 포함되지 않습니다.

## 7. main 통합과 팀 적용 (2026-09-21)

`codex/eye-mode`는 main `6883b8e6e38c0befde076d4cd0547a6e467ef622`에서 시작한 별도 브랜치입니다. 오래된 score 기반 프로젝트를 덮어쓰지 않고 안구 변경만 옮겼습니다. 목·어깨·키보드 모듈, 공통 세션/카메라 훅, Electron IPC, 루트 `database/`, `server/`, SQL·마이그레이션은 기준 main 그대로입니다. `LearningSession.tsx`의 준비 중 화면만 실제 EyeSession으로 연결했습니다. 기존 npm 잠금 항목은 유지하고 Face 런타임 하나를 추가했습니다.

검증 결과:

- 통합본 프론트 TypeScript/ESLint 및 전체 **113개 테스트** 통과(기존 94개 + 안구 19개).

- 이 통합에서 Python 환경을 새로 설치하거나 실물 키보드/사람 눈/Windows 설치 파일을 시험하지 않았습니다. 앞 절의 브라우저 가짜 영상 검사는 이전 안구 작업본에서 수행한 결과입니다.
- 제한 실행 환경에서 esbuild 폴더 접근과 tsx 사용자 정보 조회가 차단되어, 같은 검사를 일반 실행 환경에서 다시 수행해 위 결과를 확인했습니다.

팀원이 브랜치를 처음 받는 경우(현재 작업은 먼저 커밋하거나 별도로 보관):

```
