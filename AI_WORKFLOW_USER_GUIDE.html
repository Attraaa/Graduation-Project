사용자가 기억할 것은 네 가지입니다

계획 파일 선택, 코드 조사, 구현, 테스트, 리뷰, 상태 갱신은 AI가 담당합니다.

1문제를 작성01_TASK_INPUT.md에 현재 문제와 원하는 결과를 씁니다.
2작업 폴더 전달Codex 또는 Claude Code에 폴더 경로를 한 번 알려줍니다.
3요청받은 파일만 작성계획 검토·이해 확인·최종 승인 파일만 확인합니다.
4저장 후 한마디같은 대화에서 작성했어라고 보내면 자동 재개합니다.
① 사용자 입력문제와 원하는 결과 작성
② AI 계획코드 조사와 위험 분석
③ AI 실행승인 범위 구현·검증
④ 사람 판단이해 확인과 최종 승인

최초 1회: 프로젝트에 설치

프로젝트 관리자 한 명이 패키지 내용을 저장소 최상위에 넣습니다. 일반 사용자는 매번 설치하지 않습니다.

your-project/
├─ AGENTS.md                  # Codex 프로젝트 지침
├─ CLAUDE.md                  # Claude Code 프로젝트 지침
├─ .agents/skills/            # Codex 자동 워크플로
├─ .claude/skills/            # Claude Code 자동 워크플로
└─ docs/ai-workflow/          # 공통 양식과 작업 기록
Moti용 사전 병합본입니다. 이 패키지의 AGENTS.md와 CLAUDE.md에는 제공된 Moti 규칙이 이미 포함되어 있습니다. 대상 파일이 그 이후 수정되었다면 덮어쓰지 말고 diff를 확인해 새 규칙만 합치세요.

설치 후 Codex 또는 Claude Code를 새 작업/세션으로 다시 열면 지침과 스킬을 처음부터 인식할 수 있습니다.

새 작업 시작하기

1

작업 폴더를 만듭니다

docs/ai-workflow/work-items/YYYY-MM-DD/담당자/작업이름/

docs/ai-workflow/work-items/2026-09-16/minsu/payment-timeout/
└─ 01_TASK_INPUT.md
3

주석 예시를 보며 작성합니다

## 한 문장 목표

<!-- 예: 결제 응답이 늦어도 같은 주문이 두 번 결제되지 않게 한다. -->

회원 가입 인증번호가 늦게 도착해도 중복 발송되지 않게 한다.

4

기술 내용을 모르면 그대로 표시합니다

- 관련 디렉터리: AI 조사 필요
- 관련 파일: AI 조사 필요
- 관련 화면/API/작업: 회원 가입 화면의 인증번호 발송 버튼
- 관련 이슈/PR/문서: 고객 문의 #328

추측보다 AI 조사 필요, 모름, 담당자 확인 필요라고 쓰는 편이 안전합니다.

AI가 자동으로 하는 일

  1. STATUS.md 생성 또는 Git 상태와 대조
  2. 관련 코드·테스트·기존 계약 조사
  3. 계획과 위험·롤백 방법 작성
  4. 사람 승인이 필요하면 작성할 파일을 지정하고 정지
  5. 승인된 단계만 구현하고 테스트·리뷰·문서 갱신

파일을 작성한 뒤

작성했어

같은 대화에서는 이 한마디만으로 충분합니다. AI가 파일을 다시 읽고 다음 단계부터 이어갑니다.

사람이 확인하는 네 가지 관문

AI는 사람 판단이 필요한 시점에만 멈춥니다.

계획 검토04_PLAN_REVIEW.md
목표·범위·위험·첫 구현 단계를 승인하거나 수정 요청합니다.
중요 설계 결정adr/ADR-....md
API·DB·권한·재시도처럼 장기 영향이 있는 선택을 검토합니다.
변경 이해13_UNDERSTANDING.md
변경 전후, 실행 흐름, 상태 변경, 위험과 테스트를 확인합니다.
최종 판단16_FINAL_APPROVAL.md
승인, 조건부 승인, 재검토 또는 보류를 선택합니다.

AI의 요청 예시

현재 위치: 계획 검토
완료한 내용: 코드 조사와 계획 초안 작성
멈춘 이유: 구현 전에 사람의 범위 승인이 필요함
작성할 파일: docs/ai-workflow/work-items/.../04_PLAN_REVIEW.md
저장 후 보낼 답변: 작성했어
사용자는 AI가 지정한 파일만 작성하면 됩니다. 단계별 AI 지침이나 템플릿을 직접 고를 필요가 없습니다.

이해되지 않을 때는 승인하지 말고 질문합니다

코드를 전부 이해하는 것이 아니라 중요한 동작과 위험을 설명할 수 있으면 됩니다.

계획에 DB 스키마 변경이 필요하다고 적혀 있는데 이해하지 못했어.

1. 왜 필요한지
2. DB를 바꾸지 않는 방법이 있는지
3. 기존 데이터에 어떤 영향을 주는지
4. 문제가 생기면 되돌릴 수 있는지

개발을 모르는 사람 기준으로 설명해 줘.
아직 DB 변경은 승인하지 않을게.

변경사항 이해를 요청하는 문장

13_UNDERSTANDING.md를 작성했어.

`모름`이라고 작성한 항목만 실제 코드와 테스트를 근거로 설명해 줘.
전문 용어를 줄이고 실행 흐름은 최대 5단계로 설명해 줘.
내가 잘못 이해한 부분이 있다면 무조건 동의하지 말고 교정해 줘.
안전한 표현: 이해하지 못했습니다, AI 조사 필요, 담당자 확인 필요, 아직 승인하지 않습니다.

Codex와 Claude Code 사이에서 인계하기

두 도구는 같은 문서를 공유할 수 있지만 같은 작업·브랜치를 동시에 수정하면 안 됩니다.

1. 현재 도구에 인계 준비 요청

이 작업을 다른 AI 도구로 인계하려고 해.

현재 작업 폴더의 상태를 실제 Git 상태와 대조하고,
`CROSS_AGENT_HANDOFF.md` 규칙에 따라 인계를 준비해 줘.

마지막 완료 단계, 미완료 작업, 체크포인트 커밋,
미커밋 변경, 마지막 테스트, 다음에 읽을 파일을 정리하고
인계가 가능하면 현재 실행 도구 잠금을 해제해 줘.

2. 새 도구에서 재개

이 작업을 다른 AI 도구에서 이어받습니다.

현재 작업 폴더는 다음입니다.
`docs/ai-workflow/work-items/2026-09-16/minsu/payment-timeout/`

`STATUS.md`, 인계 문서, 현재 Git 브랜치, HEAD,
staged/unstaged/untracked 변경을 대조하세요.

불일치가 있으면 코드를 수정하지 말고 먼저 보고하세요.
일치하면 현재 실행 도구를 기록하고 자동 워크플로를 재개하세요.
금지: Codex와 Claude Code가 같은 작업 폴더와 같은 브랜치를 동시에 수정하게 하지 마세요. 서로 다른 작업은 별도 브랜치 또는 worktree에서 진행할 수 있습니다.

새 대화에서 작업 재개하기

새 대화는 이전 대화의 활성 경로를 모를 수 있으므로 작업 폴더를 다시 알려줍니다.

현재 작업 폴더는 다음입니다.

`docs/ai-workflow/work-items/2026-09-16/minsu/payment-timeout/`

이 폴더의 `STATUS.md`와 실제 Git 상태를 대조하세요.
완료된 문서와 테스트가 현재 코드에서도 유효한지 확인한 뒤
자동 워크플로를 재개하세요.

AI는 현재 브랜치, HEAD, staged·unstaged·untracked 변경과 테스트 유효성을 비교해야 합니다.

AI가 자동으로 하지 않는 일

외부 또는 복구하기 어려운 작업은 별도 허가가 필요합니다.

자동 진행 가능별도 명시적 요청 필요
코드와 테스트 조사원격 저장소로 push
계획·ADR·PR 본문 초안실제 PR 생성과 병합
승인 범위 내 코드 수정과 테스트배포와 프로덕션 데이터 변경
STATUS.md와 인계 문서 갱신외부 메시지, 권한·비밀 정보 변경
정책이 허용한 로컬 체크포인트삭제 또는 복구하기 어려운 작업

가장 짧은 사용법

☐ 작업 폴더를 만들었다.
☐ 01_TASK_INPUT.md를 복사하고 작성했다.
☐ AI에 작업 폴더 경로를 보냈다.
☐ AI가 지정한 사람용 파일만 작성했다.
☐ 저장 후 작성했어라고 보냈다.
☐ 모르는 내용은 모름으로 표시하고 질문했다.
☐ 다른 AI로 바꾸기 전 인계를 완료했다.
